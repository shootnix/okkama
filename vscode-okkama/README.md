# Okkama для VS Code

Локальное расширение `local.okkama-vscode`, версия 0.6.0: подсветка `.ok` и сервер
языка. Подсветка следует реализованному синтаксису Okkama; семантику проверяет
сервер.

## Сервер языка

Расширение запускает `okkama lsp` — Rust-сборку `okkama-rs`
(`cargo build --release -p okkama-cli` в `okkama-rs/`). Perl-обёртка `okkama`
команды `lsp` не знает. Что даёт сервер:

- ошибки и предупреждения анализа по мере набора (весь файл с импортами
  проверяется заново, ~0.1 с с полной std) и линтер: `unused-import`,
  `unused-let`, `unused-private`, `unreachable`, `snake-case` (как
  `okkama lint`; неиспользуемое показывается бледным);
- автодополнение: члены после `.`, локальные, поля, типы, natives, варианты
  enum, имена в `take`, ключевые слова — и в недописанной строке;
- подсказка сигнатуры при вводе аргументов;
- поиск ссылок, подсветка вхождений, переименование (`F2`) локальных и
  параметров;
- наведение: типы локальных, сигнатуры действий, конструкторов и natives, поля,
  варианты enum, у типов — конструкторы и действия; комментарий над
  объявлением — документация;
- переход к определению (`F12`, `Cmd+клик`), в том числе в std;
- структура файла (Outline, `Cmd+Shift+O`);
- форматирование (**Format Document**, `Shift+Alt+F`) — `okkama fmt`, стиль
  perlstyle. Форматировать при сохранении: в настройках пользователя
  `"[okkama]": { "editor.formatOnSave": true }`.

Файл с тестами проверяется в тестовом режиме: тела `test` и `fake` тоже.
Пока файл не разбирается, наведение и переход работают по последнему
разобранному варианту.

Настройки:

| настройка | по умолчанию |
| --- | --- |
| `okkama.serverPath` | `okkama-rs/target/release/okkama` в рабочей области, иначе `okkama` из PATH |
| `okkama.stdlibPath` | `std/` рабочей области, иначе `OKKAMA_STDLIB_DIR` или `/usr/local/lib/okkama/std` |
| `okkama.importDirs` | нет (как `OKKAMA_IMPORT_DIRS`) |

После пересборки сервера — **Okkama: Restart Language Server** из палитры команд.

Поддерживаются внутренние и внешние `cap Owner::Name`, вычисляемые поля,
`owner::Cap::field`, квалифицированные owner fields и generic cap types, включая
коллекции и callable signatures. Тела cap учитывают вложенные блоки, closures,
комментарии, обычные и fenced raw strings. Сохраняются роли, generic bounds,
constructor shorthand, successor, async/await/spawn, test/fake capabilities,
проекции, битовые операции и числовые литералы с разделителями.

`view` остаётся обычным идентификатором. `cap` распознаётся контекстно;
`cap()` не превращается в объявление. Выборка через `::` в выражении отличается
от имени масочного типа в аннотации `is`.

## Локальная установка

Установка — из корня репозитория `make vscode`: собирается
`okkama-vscode.vsix` (`npm install --omit=dev`, `vsce package`) и ставится
командой `code --install-extension`. Расширение находит сервер само:
`okkama.serverPath`, иначе сборка `okkama-rs/target/release/okkama` в рабочей
области, затем установленный `okkama` (`make install`: `~/.local/bin`) — первый,
кто отвечает на `okkama env`.

После обновления файлов выполните **Developer: Reload Window** из палитры команд
VS Code (`Cmd+Shift+P` на macOS). Повторно открывать рабочие файлы не требуется.

## Проверки

Из папки расширения:

```sh
npm test
npm run test:tokens
```

Первый набор проверяет JSON/регулярные выражения и синтаксические конструкции через
Perl. Второй использует настоящий движок `vscode-textmate` + `vscode-oniguruma`:
они должны быть доступны обычному Node.js через module resolution / `NODE_PATH`.
Зависимости не включаются в установленное runtime-расширение. Можно использовать
уже имеющиеся локальные пакеты редактора или другого расширения; путь передаётся
только для теста и не записывается в пользовательский shell profile.
