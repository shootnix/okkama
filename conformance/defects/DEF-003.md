# DEF-003 — Perl orders int map keys as text

- Implementation: okkama-perl at git f1ad6d43
- Case: `L05.map.int-key-order`
- Contract: `COLL.MAP` (boundary)
- Authority: spec 6.6 "`%K:V.keys() is @K` and `%K:V.values() is @V` (`keys()`/`values()` are sorted by key and
  share the same pairing order)"; spec 6.8 "maps use their established sorted-key order"; spec 6.3 "Key identity
  includes its exact type ... recorded before host normalization".
- Program: `[10: "ten", 9: "nine", 100: "hundred", -1: "minus"]` typed `%int:string`, then `keys()` / `values()`.
- Expected: `-1,9,10,100` and `minus,nine,ten,hundred` (keys of type int sorted by value).
- Observed: `-1,10,100,9` and `minus,ten,hundred,nine` (decimal text order of host-normalised keys).
- Note: D-037 records that the specification should name the order relation per key category explicitly;
  for an int key type, ordering by the text of the host key is not "sorted by key".
- Status: open. Expectation retained.
