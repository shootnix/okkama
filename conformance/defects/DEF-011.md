# DEF-011 — Perl promotes between numeric categories implicitly

- Implementation: okkama-perl at git f1ad6d43
- Cases: `L02.ordering.int-float-rejected`, `L02.ordering.byte-int-rejected`, `L02.float.plus-int-rejected`, `L02.byte.plus-int-rejected`, `L02.rat.plus-int-rejected`, `L02.range.byte-bound-rejected`, `L05.array.byte-index-rejected`
- Contracts: `VAL.ORDERING`, `VAL.BYTE`, `VAL.FLOAT`, `VAL.RAT`, `VAL.RANGES`, `COLL.ARRAY` (invalid)
- Authority: language owner decision of 21.10.2026 (D-046): different numeric categories
  interact only after an explicit cast.
- Programs: `1 < 1.5`, `byte(3) > 2`, `1.5 + 1`, `byte(200) + 100`, `rat(1, 2) + 1`,
  `[byte(1)..=3]`, `[10, 20, 30][byte(1)]`.
- Expected: rejection, statically or when the operation is evaluated.
- Observed: each operand is promoted (byte to int, int to float, int to rat) and the
  program completes with status 0.
- Status: open.
