## Authorities

Expectations are justified by, in order of precedence for a given subject:

1. The language specification `docs/okkama-spec-11072026.md` (last updated
   18.10.2026) and, for syntax, `docs/okkama-grammar-1.0.ebnf` / `.md`.
2. For library behaviour, the active `std/` module source and its documented
   header contract (the task names `std/` as the active library; historical
   `stdlib_DEPRECATED/`, research snapshots and obsolete examples never define
   behaviour).
3. Feature documents that record a later, explicit decision (e.g.
   `docs/allow-removal.md`, `docs/async-guide.md`, improvement results), cited
   per case.
4. Narrative documents (`docs/OkkamaBook*.md`, `docs/okkama-llm-context-1.0.md`)
   only where they agree with the above.

The interpreter is evidence, not an oracle. Where these sources disagree the
ledger records the decision; where no source decides, the contract is
`unresolved` and blocks the release gate.

## Contract statuses and aspects

`mandatory` contracts must be covered for every `required` aspect by
mandatory cases. `unresolved` contracts block the release. `deferred` contracts
describe features the specification marks as not yet runtime-supported.
`informative` contracts (std native substrate modules) are tracked but not
required: their behaviour is observed through public modules.

`ocs coverage` writes `coverage/matrix.json` and `coverage/COVERAGE.md`.
