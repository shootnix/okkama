# Общее ядро значений

`okkama-runtime-core` не зависит от компилятора, IR, байткода или VM.
Он предоставляет каноническое точное целое `IntValue`, арифметику `integer`,
значения `Value` и ошибки проверки их типа `ValueError`.

`scalar` реализует точное преобразование int → byte с проверкой 0..255 и
преобразование int/bool/byte → string. Значения byte и Unicode char сохраняют
свои типы. Кодирование строки в UTF-8 создаёт неизменяемый массив byte.
Тот же модуль проверяет диапазон счётчиков byte-сдвигов (0..7), сохраняя
восьмибитный результат. Полный перебор 256 значений × 8 счётчиков проверяет
оба направления сдвига.

`native` реализует общий UTF-8/16/32 provider по метаданным `okkama-runtime-abi`.
Кодирование сохраняет все Unicode scalars, включая BOM и noncharacters;
UTF-16/32 принимают точный порядок `big`/`little`. Декодирование строгое,
`valid_prefix` возвращает байтовое смещение начала первого повреждённого
символа. Ошибка декодирования — структурированный `NativeFailure` с domain
`core.utf` и code `invalid_data`. Ошибки типа/арности отделены от provider failure.

`native::Context` хранит состояние provider на время одного запуска.
`native::stdio` реализует stdout/stderr write и stdin read/read-line; потоки
передаются явно в provider для проверки коротких записей, прерываний и ошибок.
Обычный native-диспетчер подключает стандартные потоки процесса. Запись
возвращает принятый префикс и сбрасывает буфер; пустая запись не трогает поток.
Read-line и read разделяют оставшиеся сырые байты и EOF. Кодирование и политика
переводов строк остаются в `io/stdout`, `io/stdin` и `encoding/utf`.

IR-интерпретатор и Sparrow используют одно представление и одну реализацию
целочисленного сложения, умножения, остатка и сравнения. `okkama_compiler::ir::IntValue` сохраняется
как реэкспорт для совместимости существующих API.

`int` точный (R01, OIR-1 §23, заменяет D-016): операторы `+`, `-`, `*` и
унарный минус — `add`, `subtract`, `multiply`, `negate`, без переполнения
signed-64. Битовые операции и сдвиги работают со словом signed-64; операнд вне
его диапазона — ошибка `Bitwise operand is outside signed-64 range`, как в
JVM-рантайме. `%` имеет знак
делимого (D-031), `chomp` удаляет один LF/CRLF, оставляя одиночный CR (D-033).

Значения неизменяемы; строка разделяет `Rc<str>`, Object/Array содержат
идентификаторы в куче конкретного запуска. `heap::ArrayHeap` хранит неизменяемые массивы, split/join и lookup;
`heap::ObjectHeap` хранит обычные
объекты и создаёт successor без изменения старого значения. `strings` содержит
общие проверки Unicode-срезов, trim/chomp и буквальную замену. GC пока нет;
объекты удерживаются до конца запуска. Source spans добавляются адаптером IR-интерпретатора;
Sparrow сообщает индекс инструкции.

Внутренние array builders хранятся как цепочки неизменяемых узлов в арене.
Добавление элемента создаёт новую версию; завершение обходит цепочку
итеративно. Это поддерживает распаковку массивов, `@byte(...)`, `@string(...)`,
`map` и `filter`, не вводя мутабельных значений языка. Узлы также удерживаются
до завершения запуска.

```sh
cargo test --offline -p okkama-runtime-core
```
