# Совместимость с okkama-pl и документацией

Rust-фронтенд обязан принимать и отвергать те же программы и строить те же
деревья, что и эталонная Perl-реализация (`okkama-pl`), кроме случаев, где
решение по языку принято иначе. Такие случаи перечислены ниже с основаниями.
Rust-тесты от Perl не зависят. Perl используется только как дополнительный
оракул при разработке и в дифференциальных проверках.

## Как проводилось сравнение

### Оракул

`tools/differential/perl_oracle.pl` вызывает реальные интерфейсы
`okkama-pl`, без выдуманных флагов CLI:

```perl
Okkama::Lexer::scan_tokens($source)
Okkama::Parser->new(tokens => ..., mode => 'production'|'test', source_name => ...)->parse
Okkama::AST::JSONPrinter::print($program)
```

У Perl-CLI нет флага для печати AST, поэтому оракул — отдельный скрипт. В
эталонном `JSONPrinter` нет метода для вложенного оператора-блока
(`visit_block_stmt`), и он не печатает признак `async` у `test`. Оракул
добавляет оба метода только в своём процессе; `okkama-pl` не изменяется.

`tools/differential/CaptureSources.pm` подключается к прогону Perl-тестов
(`PERL5OPT=-MCaptureSources`), оборачивает `scan_tokens` и записывает каждый
исходный текст, который тесты отдают лексеру. Так значимые случаи из
`t/lexer` и `t/parser` (и, при полном прогоне, из всего `t/`) становятся
дифференциальными случаями без копирования тестов вручную.

### Нормализация

`tools/differential/differential.py` переводит JSON обеих реализаций в одну
каноническую форму и сравнивает её целиком. Форма сохраняет:

- виды узлов, операторы, значения литералов (целые — точным значением) и
  форму строки (`"…"`, ```` ```…``` ````, `endl`);
- все имена и номер строки каждого имени и литерала;
- признаки `async`, `variadic`, видимость и псевдоним `#projected`;
- все необязательные части (тип, default, fallback, условие, else-ветка).

Отбрасывается только то, что одна сторона выразить не может (байтовые
смещения и столбцы есть только у Rust, токены пунктуации — только у Perl), и
различия представления без синтаксического смысла. Например, Perl
разворачивает секцию `private:` в действия с флагом, а Rust хранит узел
секции, поэтому нормализатор её разворачивает.

Ошибки сравниваются по виду (лексическая или синтаксическая), номеру строки,
токену, на котором остановился разбор, и **точному тексту сообщения**.

Режимы сравниваются попарно:

| Perl | Rust |
|---|---|
| `mode => 'test'` | `--mode full` |
| `mode => 'production'` | `--mode production --prune-tests` |

Токены сравниваются отдельно: вид, лексема, строка.

**Контроль чувствительности.** На 40 случайных файлах корпуса в
каноническое дерево Rust внесено 1146 одиночных мутаций: заменён оператор,
изменено значение целого литерала, сдвинута строка имени. Все 1146
обнаружены, то есть сравнение не проходит «вхолостую».

### Команды

```sh
cargo build
python3 tools/differential/differential.py corpus --conformance --out <dir>
python3 tools/differential/differential.py cases <cases.json>

# захват исходников из Perl-тестов (запускать из okkama-pl)
OKKAMA_CAPTURE_FILE=/path/captured.jsonl \
  PERL5OPT="-I$PWD/lib -I$PWD/../okkama-rs/tools/differential -MCaptureSources" \
  prove -j8 t/lexer t/parser
```

## Результаты

Все запуски выполнены 19.10.2026 на `okkama-pl` из этого репозитория
(Perl 5.42.2).

### Корпус

`std/` (506 файлов), `examples/` (445) и все `.ok` из `conformance/cases`
(827), итого 1778 файлов:

| Режим | Совпало дерево | Совпала ошибка | Известное расхождение | Прочие расхождения |
|---|---|---|---|---|
| production | 1636 | 140 | 2 | 0 |
| test / full | 1635 | 141 | 2 | 0 |

Токены совпали в 1759 файлах. Ещё 19 файлов отвергаются лексером в обеих
реализациях. Это намеренно некорректные conformance-случаи (`lex.*`,
`gram.test.lexical-error-in-body`).

Все 951 файл `std/` и `examples/` принимаются обеими реализациями в обоих
режимах. Намеренно некорректных фикстур среди них нет (см.
`crates/okkama-compiler/tests/corpus/expected-failures.txt`).

### Исходники из Perl-тестов

Из `t/lexer` и `t/parser` захвачено 424 уникальных исходных текста,
положительных и отрицательных. В обоих режимах все 424 совпали с Perl: либо
то же дерево, либо та же ошибка с тем же текстом, токеном и строкой.

Полный прогон Perl-набора `t/` (1020 файлов, все каталоги) с захватом дал
259 301 вызов лексера. 335 записей испорчены одновременной записью
параллельных тестовых процессов в один файл и пропущены. Осталось
12 589 уникальных текстов; из них 11 638 не совпадают ни с одним файлом
корпуса. По этим 11 638 расхождений нет:

| Режим | Совпало дерево | Совпала ошибка (текст, токен, строка) | Расхождения |
|---|---|---|---|
| production | 1708 | 9930 | 0 |
| test / full | 1699 | 9939 | 0 |

Большинство совпавших ошибок приходится на фрагменты, которые тестовые
помощники Perl отдают лексеру без заголовка `module`. Обе реализации
отвергают их одним и тем же сообщением на том же токене.

### Conformance-ожидания

`tests/corpus.rs` проверяет каждый случай `conformance/cases` по его
`case.json`, без Perl:

- 583 случая обязаны разбираться — разбираются все;
- 88 случаев обязаны отвергаться лексером или парсером — отвергаются все;
- 93 случая допускают отказ на стадии parse или позже.

## Намеренные расхождения с okkama-pl

Расхождения перечислены в `tools/differential/known-divergences.json`.
Других расхождений сравнение не нашло.

1. **Висящая запятая в shorthand-конструкторе** `Pair(:a, :b,);`. Грамматика
   разрешает её (`field_param_list = field_param ("," field_param)*
   trailing_comma?`), и conformance-случай
   `L01.gram.constructor.shorthand-trailing-comma` требует её принимать.
   `okkama-pl` отвергает её, что записано как дефект conformance DEF-001.
   Rust следует грамматике.
2. **CR внутри fenced raw string.** По решению владельца языка D-030 (как
   в Go) CR отбрасывается из значения. `okkama-pl` его сохраняет (DEF-006).
   Различается только декодированное значение токена; лексема и форма дерева
   одинаковы.
3. **Production-режим не теряет узлы.** `okkama-pl` в production-режиме
   пропускает тела `test`/`fake` и не создаёт для них узлов вовсе. Rust
   сохраняет узлы с телом `SkippedBody`, а удаление выполняет отдельным
   проходом `prune::strip_test_items`. После этого прохода деревья совпадают.
   Это требование задачи: не терять test/fake без явно выбранного режима.
4. **Ограничение вложенности.** У Perl явного ограничения нет. Rust отвергает вложенность глубже
   `ParseOptions::max_nesting` (по умолчанию 64) диагностикой
   `Nesting is too deep`. В корпусе максимальная вложенность — 20.
5. **Восстановление лексера.** На неизвестном escape (`"\q …"`) Perl
   прекращает разбор строки и дальше читает её содержимое как код, что даёт
   каскад сообщений. Rust сообщает об ошибке и дочитывает литерал до
   кавычки. Обе реализации файл отвергают. Различаются только последующие
   сообщения.
6. **Значения числовых литералов.** Perl превращает десятичные литералы в
   число Perl (`0 + $text`): до 2^64−1 значение точное, больше — становится
   приближённым float (`18446744073709551616` → `1.84467440737096e+19`).
   Rust хранит цифры и основание без преобразования; диапазон `int` —
   вопрос семантического анализа. Принятие и отказ не меняются.

## Семантика IR и JVM backend

Lowering в OIR-1 и сгенерированный байткод сверяются с `okkama-pl` на
программах тестов `tests/lowering*.rs` и `okkama-cli/tests/jvm.rs`: ожидаемые
коды завершения получены запуском тех же исходников в Perl. Совпадают:
остаток `%` со знаком делителя, сдвиги и битовые операции в слове signed-64,
D04 (successor читает исходные поля, побеждает последнее `^field`), вызов
defaults при каждой конструкции (R09), накопление rebind в цикле, правила
must-use (последний алиас в сообщении, литеральные `if true`/`if false`,
обязательство переживает цикл, rebind гасит прежнее и новое значение), запрет
чтения голого имени поля и вызова actions на `self` в конструкторе.
Совпадают и коллекции: `map`/`filter`/`reduce`, `xs[i] else`, `@int(...)`/
`@string(...)` со спредом, `split` (буквальный, пустые части сохраняются,
пустой разделитель — по code points), `replace` с пустой целью, `trim` по
множеству `\s` Perl, `chomp` (ровно один CRLF/LF/CR), длина и срезы строк по
code points, глубокое `==` массивов, словарей и объектов. Словари: литерал
(повтор ключа — последнее значение), `m[k]`, `m[k] else`, `size`/`has`/
`keys`/`values`, `map`/`filter`/`reduce` с привязками `k, v`, `[:].has(k)` и
`[:][k] else`. Тексты ошибок тоже совпадают: индекс и срез массива или
строки, диапазон, `first()`/`last()` пустого массива, `Map key not found:
"z"` (строка в кавычках, `bool` — `1`/`0`, `byte` — числом, `char` — как
строка). `byte` и `char`: приведения `byte(...)`/`.byte()`/`@byte(...)` с
текстом ошибки диапазона, арифметика двух `byte` в `int`, битовые операции,
сдвиги и действия `byte` и `int` (`bit_count`, `leading_zeros`,
`trailing_zeros`, `rotate_left`/`rotate_right`, `reverse_bits`,
`swap_bytes`) с текстами `Shift count must be in 0..7`/`0..63`, равенство
`char`, `byte`/`char` в массивах и ключах словаря.
Enum и `match`: `Enum.case`, `==`/`!=`, enum в полях, массивах и ключах
словаря (`Map key not found: "amber"`), `match` по любым значениям с `==`
(первое совпадение, ленивые образцы слева направо, образцы — любые
выражения, `return` из `case`, `match` без совпадения и без `else` ничего не
делает).

Решения `docs/compiler/OIR-1.md` §23, где Rust намеренно отличается:

| ID | okkama-pl | Rust / OIR-1 |
|---|---|---|
| R01 | `int` — нативное число Perl: диапазон −2^63…2^64−1, дальше ошибка «cannot be represented exactly» | точный bigint (`BigInteger` на JVM) |
| R02 | смешивает числовые категории без приведения: `1 < 1.5`, `1.5 + 1`, `b + 1`, `b < 9`, `xs[b]`, `b..3` (`byte` расширяется до `int`, `int` до `float`) | разные типы взаимодействуют только после явного каста (`float(n)`, `b.int()`); иначе ошибка компиляции `Operator + cannot be applied to float and int`, `Array index must be int, got byte`, … |
| R06 | `keys()` и обход map — по строковому представлению ключа | естественный порядок типа ключа |
| R10 | поля объекта сравниваются в порядке Perl-хэша (исход с `any` случаен) | порядок объявления полей |

Rust отвергает при компиляции то, что Perl обнаруживает во время исполнения
(неизвестное имя, неверный тип операнда, непроинициализированное поле, ветви
`if`/`try` разных типов, `throw` значения без `Error`, private-реализацию
роли, `let x is T` со значением другого типа, неизвестное builtin-действие
вроде `"a".more("b")` — у строк есть только `less` и `less_or_equal`,
неконвертируемый аргумент `@int(...)`, `for` по словарю, неверное число
привязок функционального блока, функциональная операция над `[:]` и
`[].map()`). Текст сообщения тот же, что у Perl. Ключ не того типа (`m[1]` у
`%string:int`) Rust отвергает как `Map key must be string, got int`, а Perl во
время исполнения сообщает `Map key not found: 1`.

Владение, `defer` и `destroy` сверены с Perl на программах, где `destroy`
бросает типизированный отказ: победивший отказ виден в `catch` (код
завершения) и в диагностике. Совпадают обратный порядок уничтожения,
«родитель раньше детей», свежий аргумент или receiver, принятый вызванным
(уничтожен при его выходе), временные значения до конца блока, возврат и
`keep`, rebind без досрочного уничтожения, итерации цикла, отказ
конструктора (связанные поля уничтожаются, объект — нет), Error в `catch`,
значение ветви `if`/`match`/`try` во внешнем блоке, приоритет «тело → первый
defer → первый destroy», все defer исполняются, ленивое чтение привязок в
defer, тексты `Successor assignment is not allowed inside destroy`,
`return is only allowed inside an action`, `cannot declare more than one
destroy block` и печать `Secondary cleanup failure:`. Расхождение: отказ
defer или destroy на выходе `next`/`last` Perl теряет и продолжает цикл
(`for … { defer fail(n + 10); next if n == 1; }` даёт в Perl 12, в Rust —
11, как требует спецификация языка §19).

Модули и std (`import "path" take A, B;`): поиск, как в Perl (каталоги
`OKKAMA_IMPORT_DIRS`, каталог импортирующего файла, `OKKAMA_STDLIB_DIR`),
тексты `Import "p" not found`, `Import "p" has no declaration "X"`,
`Import "p" already takes "X"`, `Import cycle detected: a -> b -> a`,
`Native declaration "byte" conflicts with builtin callable "byte"`. Varargs
(`...T`, `values...`, `Variadic parameter "values" must be unpacked with
"values..."`), `#projected` и `prefix Object(...)`, сужение роли
(`let n is Named = labeled;` — проверка во время исполнения, текст `Cannot
initialize variable …`; расширение роли — ошибка компиляции), поле
конструктора, связанное не на всех путях (`Object "Gate" field "a" was not
initialized` — во время исполнения, после тела), читаемые в теле
shorthand-конструктора поля списка. `import` без `take` и с `as` пока не
поддержаны (`unsupported`). Natives JVM: `runtime/stdio`, `runtime/utf`,
`runtime/bigint`, `runtime/decimal`, `runtime/hex`, `runtime/base32`,
`runtime/base64`, `runtime/base85`, `runtime/quoted_printable`,
`runtime/uuid`, `runtime/unicode_normalization` — перенос providers Perl один
к одному, включая их особенности. Ожидаемый сбой provider — `thrown` с
системным `NativeFailure` (`domain`, `code`, `operation` — канонический
символ `runtime/bigint@1::bigint_quotient/2`, `message`; `text()` —
`message`), его ловят `catch … is NativeFailure` и `catch … is Error`.
Неперехваченный печатается как в Perl: `NativeError: <message>`, затем строки
`code:`, `domain:`, `operation:` (без строк `at …`, как и прочие отказы JVM).
Прочий сбой provider (неверный алфавит, порядок байтов, недопустимый вход
декодера) — `RuntimeError: Native invocation "<символ>" failed`.
Нормализацию Unicode делает `java.text.Normalizer`: версия Unicode JDK может
отличаться от `Unicode::Normalize` Perl.

Массив на границе `Sequencing<E>`/`Iterating<E>`/`Sizing`/`ByteSource` и
скаляр на границе `Comparing<T>` (а также `xs.cursor()`) — адаптеры, которые
строит lowering (системные объекты `core::ArraySequence<S, T>`,
`core::ArrayCursor<S, T>`, `core::ScalarOrder<T>`, `core::ByteArraySource`):
элемент `S` пересекает границу `T` при чтении. Тексты ошибок — Perl:
`Cannot read first item of an empty sequence`, `Array cursor is exhausted`
(и у `item()`, и у `successor()` исчерпанного курсора), `Array index out of
bounds`.

`for` в позиции значения даёт значение тела последней итерации; `next`
оставляет прежнее, `last v` выходит со значением `v`. Источник без итераций —
`RuntimeError: A void result cannot be used as a value` (как в Perl; анализ
предупреждает заранее, а для заведомо пустого источника — отвергает).

`sink <- source` — вызов `write` роли `Writing` с `ByteSource`: строка
(`str.utf8`, строгий UTF-8, адаптер `core::StringSource`), `@byte` или объект;
`source...` пишет элементы по порядку, пустой — ничего; значение — исходный
sink. Значение диапазона (`let r = 2..=4`) — `range.new` после той же проверки
порядка, что у `for a..b` (`Range start must be less than or equal to range
end`); равенство — границы и `inclusive`, обход — int-цикл до эксклюзивной
границы `range.end`.

Анонимные actions и bound actions — значения `fn` (`fn.closure`, `call.fn`):
захваты — снимок значений на момент создания, `self` окружающего action
захватывается первым; на JVM — класс `<Main>$fn$k`, реализующий
`okkama.rt.Fn`. Bound action (`obj.action` без скобок) вызываем только после
границы типа action: `let b = obj.action; b(1)` Rust отвергает при компиляции
(`Bound action requires an exact action-type boundary before it can be
called`), Perl — тем же текстом во время исполнения. Bound action ссылки роли
пока не поддержан.

Async (§18): вызов async-действия — холодный `Future` (тело — при первом
`await`, исход кэшируется вместе с отказом), `spawn` исполняет тело сразу до
первой приостановки, завершение Future сразу продолжает ожидающих в порядке
ожидания — как обратные вызовы Perl-интерпретатора. На JVM каждая задача —
поток, но исполняется ровно одна (передача управления семафорами), поэтому
порядок детерминирован. `cancel()` холодного — отказ `Cancelled` без тела;
приостановленной задаче отмена доставляется в её `await` (отказ `Cancelled`,
defer выполняются; `Cancelled.text()` — `Operation was cancelled`). После
`async main` незавершённые задачи `spawn` отменяются, ненаблюдённый отказ
задачи — отказ программы (D-034). Если корень ждёт и событий нет, Rust
сообщает `RuntimeError: async main cannot complete: no task can make
progress` (Perl ждёт событий цикла). `spawn` синхронного действия
(процесс-worker) и async natives пока не поддержаны.

Intrinsics `async/*` — `Channel`/`Sending`/`Receiving`, `Event`, `Atomic`,
`Cancellation`/`CancellationToken`, `FutureGroup`, `AllFutures`, `Raced` —
функции `[intrinsic "okkama.…"]` без тела; их реализует рантайм
(`okkama.rt.Intrinsics`, перенос состояний Perl: FIFO-очереди ожидающих,
рандеву при ёмкости 0, `close` с доставкой буфера, CAS строгим равенством,
отмена незавершённых входов при первом отказе). Error std (`ChannelClosed`,
`InvalidChannelCapacity`, `AtomicClosed`, `NoFutures`, …) рантайм создаёт
как объекты программы. `Lock`, `Semaphore`, `Barrier`, `FutureScope`,
`FirstSuccessful`, `FutureCompletions` и тайм-ауты пока не поддержаны.

Caps (§11.2.1) — `cap.make`/`call.cap`: значение cap на JVM — сам владелец,
поле — функция над ним, каждое чтение вычисляется заново. Слот роли с
результатом `^Role` реализуется переходником (`succ.take`, затем
`role.wrap`). Native модуля программы без provider — ошибка вызова Perl
`Native symbol "app@1::name/1" is not registered`; символы natives в OIR —
канонические (`модуль@major::имя/арность`). Программа без `main` в режиме
`run` — `Program requires main() declaration`.

Тестовый режим (§14): `okkama check|ir|build --tests` и режим `test` OCS.
Fake роли — объект `Role$fake` (поля из defaults, `does Role`), тесты
объектов и ролей — тесты модуля `Owner :: name` в порядке исходника. Отчёт —
`=== RUN`/`--- PASS`/`--- FAIL` и итог `PASS`/`FAIL` (как Perl, без строк
`at …`), код выхода 0 только если прошли все; пустой набор — `Test run
requires at least one test`. `fake.storage.get(k)` получает тип из контекста
(в том числе от другого операнда оператора: `prefix +
fake.storage.get(id)`); без контекста — ошибка компиляции (Perl типизирует
динамически).

Многофайловый модуль (§5.1): `okkama check|ir|build a.ok b.ok …` и
`sources` запроса OCS — файлы одного модуля. Объявления общие, импорты у
каждого файла свои. Тексты ошибок — Perl: `source files declare different
modules "app" and "other"`, `module "app" has conflicting versions "v1.0.0"
and "v1.0.1"`, `Object "Greeter" is already declared` (повтор в другом
файле), `Module declares main() more than once`. `-` (stdin) нельзя
смешивать с файлами.

`any` — непрозрачный box (`any.box`, на JVM `okkama.rt.Any`): его передают,
хранят, считают; распаковки нет. Гетерогенный литерал без целевого типа —
`@any`/`%K:any` с box каждого элемента (R08; диапазоны внутри такого
литерала пока не поддержаны). Сравнение `any` и коллекций из `any`
(`@any == @any`, `%K:any == %K:any`) Rust отвергает при компиляции
(`Cannot compare @any and @any`): Perl в этих случаях падает всегда, во время
исполнения (`Cannot compare any without narrowing`). Объект с полем `any` в
`==` даёт ту же ошибку Perl во время исполнения.

Native objects (`native object H`) — непрозрачные значения natives: в OIR
тип `H`, на JVM — объект класса provider.

`order()` встроенных типов возвращает `compare.Order`; строки и `char`
упорядочены по code points. `string.less`/`less_or_equal` сравнивают **длины**
строк — так в Perl (`BuiltinActions.pm`), Rust повторяет. `bool.string()` —
`"1"`/`"0"` (Book, Perl).

Generics: вывод аргументов (ожидаемый тип, роли-свидетельства, образцы
полей и параметров, variadic-хвост), bounds, экземпляры в коллекциях,
generic successor и variadic-конструкторы совпадают с Perl; ошибки вывода и
bounds Rust сообщает при компиляции тем же текстом, что Perl при исполнении.

`float`: binary64 как `java.lang.Double`; арифметика `+ - * / %` и
сравнения — только двух `float` (R02); `%` — знак делителя; `int()` — усечение к нулю в
signed-64; тексты ошибок Perl (`Division by zero`, `Modulo by zero`, `Float
value must contain a finite number`, `Cannot convert float value 1e+30 to
int: expected signed-64 range`, `… to byte: expected 0..255`). **Текст
`float` следует решению владельца языка D-032** (правило Go
`FormatFloat(x, 'g', -1, 64)`: `0.30000000000000004`, `1e+06`, `-0`), а не
Perl (15 цифр, DEF-009). Равенство `int` с `float` — ошибка в обоих;
арифметику и упорядочивание `int` с `float` Rust по R02 отвергает при
компиляции, а Perl разрешает (DEF-011).

Conformance (21.10.2026, анализ и lowering из THIR): профиль `frontend` —
136 из 136; `portable-core` — 695 из 698, без `UNSUPPORTED`,
3 `FAIL`, общих с Perl (`L02.int.modulo-sign`, `L02.int.overflow-wraps`,
`L02.string.trim-whitespace-set`): реализация следует Perl (R01, `%` со знаком
делителя, `chomp` снимает одиночный `\r`), а случаи — спецификации;
`full-release` — 728 из 772 с теми же 3 `FAIL` (41 `UNSUPPORTED`: natives std, которых ещё нет в рантайме JVM, async natives, процесс-workers `spawn`, `Lock`/`Semaphore`/`Barrier`). Действия std, которые VM Perl
даёт интринсиками (`Atomic`, `Lock`, `Channel`, … — их тела в std —
`panic "… is a VM intrinsic"`), lowering честно отвергает как ещё не
реализованные. Правило R02 вошло в suite как решение D-046: случаи со
смешением категорий (включая `rat / int`) переписаны с явными кастами,
отрицательные `*-rejected` проверяют отказ, а неявное расширение в Perl
записано как DEF-011.

Семантический анализ (`analysis`) следует Perl там, где на правиле держится
std, и спецификации — там, где Perl отстаёт:

- как Perl: перегрузка fixed и variadic действия одного имени (запрещены
  только две variadic), конструкторы одной арности (выбор по именам; при
  нескольких подходящих — с наименьшим числом пропущенных полей shorthand),
  `self` можно передать из конструктора как значение (вызывать его действия
  нельзя), `for` в позиции значения, обход ссылки роли через сужение до
  `Iterating<T>`, массив как `Sequencing<E>` с поэлементной границей,
  контекстная `test`;
- строже Perl: объект пересекает параметр роли при выборе перегрузки
  статически; тела generic-объявлений проверяются символьно (действия
  параметра типа — только через ограничение); `byte` — не ключ словаря (D-007,
  Perl принимает — DEF-004); смешение числовых категорий отвергается
  (D-046, DEF-011);
- ключи словаря — ровно одного типа (D-047): `[1: "int", "1": "string"]` —
  ошибка `Map keys have different types: int and string` (`any` ключом не
  бывает; Perl такой литерал принимает — DEF-012). Разнородные значения дают
  `%K:any` (R08);
- `for` в позиции значения: если статически известно, что источник пуст
  (константный диапазон, пустой литерал), — ошибка `For loop has no value`;
  если неизвестно — предупреждение: значения нет, когда тело не исполнилось.
  Предупреждения выводят `okkama check`/`ir`/`build` (только корневого модуля);
  в std их 23 в 8 модулях (больше всего `collections/combinatorics.ok`).

В std под D-046 исправлены 24 места (`rat` с `int`): целая сторона явно
приводится `.rat()`; поведение Perl не меняется.

Значение на каждом пути Rust требует статически: `if` без `else` или `match`
без `else`, не покрывающий все case enum, в позиции результата (`main() is
int { if c { 5; } }`) — ошибка компиляции `Action "main" must produce a return
value`. Perl такую программу исполняет и падает, только если значения не
оказалось. Enum с именем объекта или роли Rust отвергает (`Enum "Color" is
already declared`): Perl такие имена различает, а в JVM-классах они бы
совпали. Ключи enum Rust упорядочивает по объявлению case, Perl — по имени
(R06).

`byte` с `int` Rust не смешивает нигде (R02): арифметика `b + 1`,
упорядочивание `b < 9`, индекс `xs[b]` и границы диапазона `b..3` — ошибки
компиляции, нужен `b.int()`. Perl это разрешает расширением `byte` до
`int`; по решению владельца языка это дефект Perl-версии (D-046, DEF-011).
Равенство `byte` с `int` запрещено в обоих (`Cannot compare byte and int`).
Ключи `byte`
словаря Rust упорядочивает по значению, Perl — по строке (R06).
Одно отличие: в `@T() argument N` Perl считает элементы после раскрытия
`xs...`, а Rust — операнды записи (`xs...` — один операнд), потому что длина
массива при компиляции неизвестна. Литеральные `if true`/`if false` Rust, как и анализатор Perl, считает
известными: типы мёртвой ветви с живой не сравниваются.
Множество принимаемых программ при этом не шире: Perl такую программу тоже
прерывает, но может успеть выполнить эффекты до ошибки.

## Хост JVM-рантайма: natives std

Natives `runtime/*` реализованы в `okkama.rt` (Java 8, `runtime/jvm/src`) и
через FFM (JDK 22+, `runtime/jvm/src22`: SQLite, Unix-сокеты, учётные записи,
терминал, locale, collation; `okkama run` добавляет
`--enable-native-access=ALL-UNNAMED`, исполняемый JAR — манифестом).
Std-тесты проходят во всех файлах (230 на 23.10.2026) на macOS (arm64) и в Linux-контейнере
(`eclipse-temurin:23-jdk`, тесты собраны в JAR на macOS; collation — с ICU
76.1, собранной `tools/build-icu-collation.sh` под Linux). FFM-natives
(терминал, учётные записи) на Windows сообщают `unsupported`: раскладки
структур и константы есть только для macOS и Linux. Наблюдаемые отличия от
Perl-provider:

- **Текущий каталог и окружение виртуальные.** JVM не меняет cwd и env своего
  процесса: `chdir`, `environment_set`/`remove` меняют копию в `Host`; от неё
  разрешаются относительные пути natives, её получают дочерние процессы.
- **Процессы** — `posix_spawn` и собственный `waitpid` через FFM: статус
  точный (выход с кодом 130 отличим от гибели от `SIGINT`), сигналы — `kill(2)`,
  потомок получает сигналы по умолчанию и только stdin/stdout/stderr (как у
  Perl: 5 дескрипторов в `/dev/fd` у `sh -c 'ls /dev/fd'`). Без JDK 22 —
  `ProcessBuilder`: гибель от сигнала N приходит кодом `128 + N`, поэтому коды
  129..192 трактуются как сигнал, `SIGINT` посылает утилита `kill`. Программа
  без `/` ищется по `PATH` окружения потомка, как `execvp` у Perl; `argv[0]` —
  найденный путь.
- **Сеть** — блокирующие каналы на рабочих потоках вместо неблокирующих
  дескрипторов и poll. Пара Unix-сокетов эмулируется временным listener (у JVM
  нет `socketpair`); её концы безымянны, как у Perl. Пути Unix-сокетов
  декодируются как UTF-8. Порядок адресов DNS — порядок резолвера JVM.
- **TLS** — `SSLEngine` JDK вместо OpenSSL. Имена версий приводятся к OpenSSL
  (`TLSv1_3`), наборы TLS 1.2 — к именам OpenSSL (`ECDHE-RSA-AES128-GCM-SHA256`).
- **X.509.** DER-конверт и снимок фактов — порт Perl-provider (снимок
  совпадает побайтно); проверку цепочки, которую Perl отдаёт OpenSSL, выполняет
  PKIX JDK. Якорем служит только самоподписанный корень (как OpenSSL без
  `PARTIAL_CHAIN`); прочие корни лишь достраивают путь. Проверки назначения
  (EKU/keyUsage/CA) повторяют `X509_PURPOSE_SSL_SERVER/CLIENT`, профиль
  `X509_V_FLAG_X509_STRICT` — его проверки RFC 5280 (у CA критический
  basicConstraints, keyUsage и SKI; AKI у не самовыпущенного; пустой subject —
  только с критическим SAN). На 31 цепочке (верные, без CA, без `keyCertSign`,
  pathlen, EKU клиента/сервера, критическое неизвестное расширение, без AKI,
  самоподписанные, лишние и переставленные промежуточные, сроки, имена, IP)
  исходы совпадают с Perl/OpenSSL. Системные корни — `SSL_CERT_FILE`/`SSL_CERT_DIR`
  или системный bundle (`/etc/ssl/cert.pem`, …); Perl берёт каталог своей
  сборки OpenSSL, поэтому набор корней на одном хосте может отличаться.
- **Collation** — та же закреплённая ICU 76.1 через FFM; каталог —
  `OKKAMA_ICU_LIBDIR`, иначе `okkama run` находит `.runtime/icu-76.1`
  рядом с std.
- **Терминал** — чтение блокирующее на потоке сессии (Perl делает дескриптор
  неблокирующим и ждёт готовности); владение дескриптором учитывается по
  номеру (`fd:0`, `fd:1`, `tty`), а не по `dev:ino`.
- **`spawn` синхронного действия** (§18.1) запускает дочернюю JVM с той же
  программой; вход воркера — сгенерированная функция (`worker.spawn`), receiver
  bound action восстанавливается конструктором из всех полей, как у Perl.
  Печать действия в воркере пересылается в stdout родителя (у Perl она ломает
  JSON-протокол воркера). Отказ воркера — программная ошибка
  `runtime: <тип>: <текст>`.
- **Диагностика** не печатает строки стека `at …` Perl-интерпретатора.
- **Лимиты класса.** Длинные функции делятся на части (`outline`, в том числе
  разрезанием длинных блоков), но пул констант одного класса (65535 записей)
  остаётся пределом.

## Криптография хоста и PostgreSQL

- **`crypto/*` и `digest/sha2|sha3|shake|blake2|read`** — объекты std над
  `runtime/host_crypto`, а примитивы — библиотека `okkama-native` (RustCrypto,
  C ABI, `cdylib`). JVM вызывает её через FFM (`HostCryptoNatives`, JDK 22+);
  `okkama build`/`run` вкладывают библиотеку платформы в JAR
  (`okkama/native/<os>-<arch>/`, распаковка во временный каталог по хешу),
  `OKKAMA_NATIVE_LIB` подменяет её, `OKKAMA_NATIVE_DIR` добавляет сборки других
  платформ. Без библиотеки — `CryptoUnavailable`. В Perl этих модулей нет
  (отложены 25.09.2026), поэтому оракул — векторы RFC/NIST в тестах
  `okkama-native` и std, плюс взаимная проверка с OpenSSL (Ed25519, ECDSA,
  RSA, PEM).
- **`rsa` 0.10.0-rc.19** — единственная линия `rsa`, совместимая с
  `sha2 0.11`/`pkcs8 0.11` остальных крейтов; подписи PSS/PKCS#1 и OAEP
  сверены с OpenSSL.
- **`db/postgres`** — драйвер протокола 3.0 на Okkama (TCP/TLS хоста,
  SCRAM/MD5 на `crypto/*`). Решения строгой реализации: только расширенный
  протокол (одна команда на `Statement`, плейсхолдеры `$n` без переписывания
  `?`), MD5 и cleartext — только явным включением, TLS без отката на
  plaintext, SCRAM без channel binding, сообщение `DbFailure` пишет драйвер
  (текст сервера может содержать значения параметров), NaN/бесконечности —
  отказ `data`. Проверено против PostgreSQL 18.6 (Docker): все методы
  аутентификации, TLS 1.3 с проверкой цепочки и имени, CRUD, потоковое
  чтение, транзакции и уровни изоляции, подготовленные запросы, SQLSTATE,
  FATAL при `pg_terminate_backend`, пул, 6 МБ `bytea`.

## Движки IR и Sparrow: расхождения с JVM

Оба движка исполняют общий рантайм `okkama-runtime-core`, поэтому всё
перечисленное одинаково для IR и Sparrow. Программы репозитория (std, examples,
OCS) этих расхождений не наблюдают; они перечислены, чтобы граница была явной.

- **Трансцендентные функции float** (`sin`, `exp`, `log`, `pow` и т. п.) —
  libm Rust, а не `StrictMath` JVM: возможна разница в последнем бите.
- **Регулярные выражения** — fancy-regex с обёртками семантики
  `java.util.regex` (замены, `split`, границы); версии таблиц Unicode
  (`\p{…}`, кластеры `\X`) — у крейтов Rust, а не у JDK.
- **TLS** — rustls (ring), а не SunJSSE: TLS 1.2/1.3 с наборами ECDHE + AEAD
  (AES-GCM, ChaCha20-Poly1305) в порядке предпочтения SunJSSE, группы X25519,
  P-256, P-384. Сервер, принимающий только DHE, CBC или обмен ключом RSA,
  рукопожатия не завершит (у JVM — завершит). Проверка пира отложена до
  `authorize`, как у JVM; подписи рукопожатия проверяются.
- **X.509 PKIX** — собственный построитель пути вместо `CertPathBuilder`:
  подписи RSA PKCS#1 v1.5 (SHA-1/224/256/384/512), RSASSA-PSS (MGF1 с тем же
  хэшем), ECDSA P-256/P-384/P-521, Ed25519; ограничения
  `jdk.certpath.disabledAlgorithms` (MD2/MD5, RSA < 1024, EC < 224);
  basicConstraints и pathLen, keyCertSign, нераспознанные критические
  расширения, AKI/SKI при выборе издателя. Не поддержаны подписи Ed448 и DSA
  и PSS с отличным от подписи хэшем MGF1 (путь не строится — `untrusted` или
  `invalid_signature`); из nameConstraints проверяются dNSName, iPAddress,
  directoryName и rfc822Name (а также CN без SAN dNSName, как у JDK);
  certificatePolicies/policyConstraints не вычисляются. Декодирование ключа
  при разборе сертификата повторяет проверки JDK для RSA, EC (только
  именованные P-256/384/521, несжатая точка), EdDSA и XDH.
- **Процессы** — `std::process` со своими разрешением PATH, точным статусом
  `waitpid` и сигналами, как `PosixSpawn` JVM; диспозиции сигналов потомка:
  Rust сбрасывает только SIGPIPE, JVM — все.
- **Sparrow: проверка байткода** структурная (ссылки, регистры, переходы,
  обработчики, инициализация на всех путях); типы операндов проверяет
  исполнение — неверный тип даёт ошибку состояния VM. SPB 1–8 не читаются.

Найдено при сверке и исправлено в JVM-пути: генерация JVM зависала на
функциях с тысячами блоков (вынос областей был O(B²) на шаг и повторял вынос
целой функции); теперь большие литералы режутся цепочкой builder и линейные
отрезки выносятся в функции (`codegen/jvm/outline.rs`).

Рекурсия (§11.6.1, 24.10.2026): JVM-путь падал с `StackOverflowError` на
нехвостовой рекурсии около 10⁴–10⁵ кадров (стек главного потока), а IR и
Sparrow исполняли её с кадрами в куче. Теперь `Rt.launch` (и `Tests.run`)
исполняет программу в потоке со стеком 4 GB (резервируется, выделяется по мере
роста), хвостовой самовызов на всех движках — цикл (OIR-проход
`ir/recursion.rs`), а действие, которое не может завершиться без рекурсии, —
семантическая ошибка компиляции.

## Решения по ходу реализации

- **Три движка, JVM по умолчанию** (24.10.2026, слияние `feature/rs-runnable`):
  `okkama run` собирает JVM-байткод и запускает `java`; `--engine ir` — IR-интерпретатор
  в Rust-процессе, `--engine sparrow` — байткод `.spb` и VM Sparrow
  (`okkama build --target sparrow`, бинарник `sparrow`). `OKKAMA_ENGINE` меняет
  умолчание. Все три следуют R01 (точный `int`); IR и Sparrow пока покрывают
  часть языка и std (OCS: 601 и 599 из 772), неподдержанное — ошибка без
  перехода на JVM.

- **`%` — знак делимого** для `int`, `float` и `rat` (решение D-031 «как в
  Go» для `int`; для `float` и `rat` — то же правило, как `math.Mod`, ради одной
  семантики оператора). Perl использует floored-деление (DEF-007).
- **`int` точный** (R01, заменяет D-016): conformance-кейс
  `L02.int.overflow-wraps` ожидает точные значения.
- **`chomp`** снимает ровно один CRLF или LF; одиночный CR остаётся (D-033).
- **Массив объектов не становится массивом роли через переменную**: `let xs =
  [A()]; f(xs)` при `f(items is @Named)` — ошибка; литерал в позиции аргумента
  типизируется ожидаемым `@Named`. Perl принимает (проверка элементов при
  исполнении). Явная граница — правило строгой реализации.
- **`fake.storage.get()` требует ожидаемый тип из контекста** (ошибка
  компиляции без него); Perl решает при исполнении.
- **`spawn` синхронного действия** статически проверяет передаваемые типы
  аргументов и результата (OIR-1 `proc.spawn`): `spawn cannot transfer value of
  type T`; Perl проверяет при отправке.
- **`okkama build -o X.jar`** — один исполняемый JAR (DEFLATE, манифест
  `Main-Class` и `Enable-Native-Access`); `-o X.class` — классы рядом.

## Прочие наблюдения

- В `conformance/cases` у пяти случаев `L04.projection.*`
  (`duplicate-prefix`, `non-constructor-target`, `same-type`,
  `undeclared-prefix`, `with-parameter`) указано `outcome: "error"`, но блок
  стадий записан под ключом `rejection`, а не `failure`. Корпусный тест
  читает стадии из любого из двух ключей. Сам набор conformance здесь не
  изменялся.
- Perl-тест `t/parser/14-test-mode-pruning.t` закрепляет, что production
  отбрасывает тесты на уровне токенов. Rust воспроизводит это поведение
  (принятие и отказ совпадают на всех случаях), но сохраняет узлы до явного
  прохода `prune`.
