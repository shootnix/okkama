# SQLite: rusqlite против Python — 2026-11-02

Свежая release-сборка текущего рабочего дерева. 5 последовательных повторов с ротацией порядка движков, 4 прогрева каждой фазы; 5000 строк, 500 поисков/вставок. Все контрольные суммы совпали. В таблице медианы в миллисекундах; запуск процесса и компиляция вне таймера.

| Фаза | Python | Sparrow | IR | Sparrow / Python |
|---|---:|---:|---:|---:|
| projection_only | 0.961 | 9.228 | 45.879 | 9.6× |
| scan_raw | 2.016 | 19.153 | 43.102 | 9.5× |
| scan_stream | 2.918 | 32.654 | 102.358 | 11.2× |
| scan_all | 3.102 | 33.269 | 109.002 | 10.7× |
| lookup_prepared | 0.769 | 40.553 | 68.286 | 52.7× |
| lookup_statement | 0.840 | 43.559 | 66.755 | 51.8× |
| insert_transaction | 0.324 | 10.537 | 20.602 | 32.5× |

Цель отставания 1.2–1.5× не достигнута. Сам перенос на rusqlite не устранил накладные расходы публичного API. projection_only читает уже полученную строку без выполнения SQL: его отставание показывает, что существенная работа остаётся выше драйвера. Этот тест не позволяет приписать всё отставание конкретно планировщику, объектам или преобразованиям; для этого нужен профиль.

Ограничения: Okkama использует async worker и типизированный API, Python — синхронный sqlite3.Row. SQLite in-memory: Okkama bundled 3.50.2, Python 3.51.0. Это сравнение пользовательских сценариев, не изолированный тест одинаковых SQLite-сборок. Четыре прогрева не гарантируют полную стабилизацию JIT. PostgreSQL, MySQL/MariaDB и JVM здесь не измерялись. Успешные бенчмарки не заменяют полного регрессионного тестирования нового драйвера.

Повторить:

```sh
env -u OKKAMA_JIT_THRESHOLD DB_BENCH_WARMUPS=4 python3 benchmarks/db/run.py --runs 5 --rows 5000 --lookups 500 --engines python,ir,sparrow --out benchmarks/db/results/rusqlite-python.json
```
