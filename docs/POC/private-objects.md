# POC: скрытые объявления модуля (`hidden`)

Статус: реализовано 2026-11-04 (спецификация §5.1.1, контракт conformance `MOD.HIDDEN`). Открытые вопросы §9 остаются открытыми.

## 1. Зачем

Сейчас любое объявление модуля доступно снаружи. `take` скрывает
невзятые имена только у того, кто импортирует через `take`; обычный
`import "payments";` открывает всё: `payments.Payment(...)`.

Из-за этого:

- **нельзя закрыть реализацию.** Роли и фабрика задуманы как API, но
  конкретный класс всё равно можно назвать и создать;
- **State Views обходятся статически.** `hidden object Payment` за публичными
  ролями `Created`/`Authorized`/… и фабрикой `Payments` — недостающий кусок
  паттерна из [исследования typestate](../research/role-oriented-typestate.md):
  без него неверный переход через конкретный класс ловит только `confirm`
  во время исполнения;
- **std тащит наружу служебное**: адаптеры, внутренние ошибки, помощники.

## 2. Рассмотренные варианты

```okkama
// ver1: модификатор private у объявления
private role Debugging { debug() is void; }
private object Utils does Debugging { ... }

// ver2: секция private: на уровне модуля
private:
role Debugging { debug() is void; }
object Utils does Debugging { ... }

// ver3: модификатор hidden у объявления
hidden object Utils does Debugging { ... }
hidden role Debugging { debug() is void; }
hidden enum E = (...);
```

**Выбран ver3, `hidden`.**

- `private` уже означает другое правило: действие объекта вызывается только
  через `self`. Видимость в модуле — другое правило («тип нельзя назвать за
  пределами модуля»); одно слово с двумя смыслами путает. Пара «`private` —
  объект, `hidden` — модуль» запоминается легко.
- Секция `private:` на уровне модуля (ver2) делает видимость зависимой от
  положения строки: перенос объявления при рефакторинге молча меняет API.
  Внутри объекта секция терпима, объект маленький; модуль — нет.
- `hidden` стоит у самого объявления и описывает эффект для читателя модуля
  снаружи. Альтернатива `internal` (C#, Kotlin) точна по смыслу, но длиннее и
  уже встречается в `std` как сегмент пути (`locale/internal/...`).

## 3. Синтаксис

```okkama
module payments v1.0.0;

role Created { authorize(gateway is Gateway) is Authorization; }
role Authorized { capture() is ^Captured; }

hidden enum Stage = (created, authorized, captured);

hidden object Payment does Created, Authorized {
    has key is string;
    has stage is Stage = Stage.created;
    Payment(:key);
    ...
}

object Payments {
    Payments();
    open(id is string) is Created { Payment(key: id); }   // наружу — только роль
}
```

Грамматика:

```ebnf
item_decl  = "hidden"? ( object_decl | role_decl | enum_decl ) | ... ;
```

- `hidden` — **контекстное** ключевое слово: только перед `object`, `role`
  и `enum` на уровне модуля. Как имя поля или локальной оно остаётся
  обычным идентификатором (`has hidden is int` уже есть в conformance).
- `hidden` у `native`, `cap` и тестов в первой версии не поддерживается
  (§9).

## 4. Семантика видимости

Скрытое объявление видно:

- во всех файлах своего модуля (многофайловый модуль делит объявления, §5.1
  спецификации);
- в `test`-блоках и fake'ах этого модуля;
- в телах, defaults и fake'ах этого модуля, даже когда они выполняются по
  вызову из другого модуля (имена разрешаются в области модуля-владельца,
  как сейчас).

Скрытое объявление **не** видно из других модулей:

| Попытка | Диагностика |
|---|---|
| `import "payments" take Payment;` | `Import "payments" cannot take hidden declaration "Payment"` |
| `payments.Payment(key: "x")` | `Type "payments.Payment" is hidden in module "payments"` |
| `let p is payments.Payment = ...` | то же |
| `catch e is payments.PaymentError` | то же |

Значения скрытых типов при этом **могут** выходить наружу, но только под
публичным типом: роль, `Error`, `any`. Это и есть цель: снаружи объект виден
только через ограниченную ссылку роли, а привести её к конкретному классу
нельзя (§12.1).

## 5. Правило утечки: публичная сигнатура не называет скрытый тип

Если публичная сигнатура упоминает скрытый тип, вызывающий получит значение
типа, который не может назвать. Это ошибка в модуле-владельце:

```text
Public action "open" of "Payments" exposes hidden type "Payment"
```

Проверяются места, видимые снаружи:

- список `does` публичного объекта: публичный объект не может реализовывать
  скрытую роль (см. 5.1 ниже);
- параметры и результаты публичных действий публичных объектов (включая
  successor `^T`, async, типы действий `(T) is R`), параметры их конструкторов
  (в том числе `Payment(:key)` — тип поля становится типом параметра);
- сигнатуры публичных ролей;
- payload публичных enum (включая error enum);
- аргументы generic и границы (`Box<Payment>`, `T: HiddenRole`);
- поля публичных cap.

Не проверяются: приватные действия, поля объектов (они и так недоступны
снаружи), тела, скрытые объявления целиком.

Разрешено и задумано:

- скрытый объект реализует публичную роль (`hidden object Payment does Created`);
- скрытый объект реализует скрытую роль;
- публичное действие возвращает роль, а внутри создаёт скрытый объект.

### 5.1. Публичный объект не реализует скрытую роль

```okkama
hidden role Debugging { debug() is void; }

object Connection does Connecting, Debugging { ... }
// error: Public object "Connection" does hidden role "Debugging"
```

Список `does` — часть публичного контракта объекта: реализация роли делает её
действия публичным API объекта. Скрытая роль в нём означала бы, что внутренний
контракт модуля просачивается наружу через каждый публичный объект, который её
делает, хотя саму роль снаружи нельзя ни импортировать, ни назвать. Поэтому
скрытая роль — только для скрытых объектов. Если публичному объекту нужно
внутреннее поведение, его выносят в скрытый объект и держат полем
(композиция), а не ролью публичного объекта.

## 6. Ошибки

Скрытый error enum можно бросить за пределы модуля: снаружи его поймает только
`catch e is Error` (или `try?`). Без `throws` (фаза 3 обработки ошибок на холде)
сигнатуры не говорят, что бросается, поэтому правило утечки сюда не дотягивается.

Решение для первой версии: **разрешить**, а `okkama lint` предупреждает, если
публичное действие явно бросает (`throw`) скрытый error enum: «callers cannot
catch "PaymentError" by type». Ошибки, которые должен разбирать вызывающий,
делаются публичными.

## 7. Связь с остальным

- **State Views.** `hidden object Payment` + публичные роли + фабрика:
  через `payments.Payment(...)` больше не пройти, неверный переход
  отвергается статически при любом импорте. `confirm` в переходах остаётся
  второй линией (значения из `any`, будущие ABI).
- **Направление `does`.** Скрытое может реализовывать публичное (так прячут
  реализацию), публичное не может реализовывать скрытое (так не прячется
  ничего, а утекает контракт).
- **Throw/catch-лазейка** из исследования (восстановление полного объекта
  через `catch e is Concrete`) закрывается для скрытых классов автоматически:
  их нельзя назвать в `catch`. Окончательно — с фазой 2 ошибок.
- **Прототип qualified export** (`docs/qualified-export-prototype.md`) решает
  более общую задачу политик пакетов; `hidden` — минимальная языковая часть,
  не требующая политики. Логику обхода публичных сигнатур можно взять оттуда.
- **std.** После реализации — отдельная задача: пометить служебные объявления
  (`locale/internal/*`, адаптеры, помощники) и проверить, что публичные
  сигнатуры их не называют.

## 8. Реализация

Только front-end; IR, Sparrow и JVM не меняются (скрытие — свойство имён,
а не значений).

| Шаг | Где | Объём |
|---|---|---|
| Контекстное `hidden` перед `object`/`role`/`enum`, флаг в AST | `syntax/parser/decl.rs`, `syntax/ast` | часы |
| Форматтер, печать AST | `syntax/format.rs`, `syntax/print/build.rs` | часы |
| Множество скрытых имён модуля; отказ в `take` и `ns.Name` | `analysis/registry.rs`: `expose_imports`, `find_qualified`, `bind_taken` | часы |
| Правило утечки: обход публичных сигнатур и списков `does` | `analysis/registry.rs` после сбора сигнатур и `collect_does` | ~1 день |
| LSP: не предлагать скрытое в дополнении, не разрешать в hover/definition чужих модулей | `ide/index.rs` (`resolve_type` дублирует `find_qualified`), `ide/complete.rs` | часы |
| Lint: публичное действие бросает скрытый error enum | `ide/lint.rs` | часы |
| Спецификация (импорты §5, видимость), грамматика, книга, context pack, подсветка VS Code | docs, `vscode-okkama` | часы |
| Conformance: `L06` (модули) — take/namespace/тип/catch скрытого, утечка в каждой позиции, разрешённые случаи | `conformance/cases/L06-*` | ~0,5 дня |

Итого 2–3 дня. Риск низкий: новых правил типов нет, только видимость имён
и одна проверка сигнатур.

## 9. Открытые вопросы

1. `hidden native` — нужны ли скрытые native-объявления в substrate-модулях
   `std/runtime/*`? Сейчас их закрывает соглашение «natives только в
   substrate-модулях». Предлагаю отложить.
2. `hidden cap Owner::Card` на уровне модуля — cap уже ограничивает доступ;
   скрывать сам тип cap, вероятно, не нужно. Отложить.
3. Нужно ли предупреждение на `hidden` объявление, которое нигде в модуле не
   используется (аналог `unused-private`)? Дёшево, полезно — предлагаю
   добавить в lint.
4. Нужен ли обратный режим «всё скрыто, кроме перечисленного» (список
   экспорта в `module`)? Не в этой версии: явный `hidden` у объявления
   читается локально и не требует второго списка имён.
