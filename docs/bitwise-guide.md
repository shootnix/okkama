# Побитовая арифметика

Операторы `&`, `|`, `^`, `~`, `<<`, `>>`, `>>>` работают над словами
фиксированной ширины. Для int это 64 бита со знаком, для byte — 8 бит без знака.
Новые литералы `0b1010_0011` и `0x7FFF_FFFF_FFFF_FFFF` имеют тип int;
для байта пишется `byte(0xFF)`. Разделитель `_` допустим только между цифрами.
Литералы с основанием неотрицательны и ограничены INT64_MAX.

```okkama
let flags = 0b1010;
let mask = 1 << 2;
let enabled = flags | mask;          // 14
let cleared = enabled & ~mask;       // 10
let toggled = flags ^ mask;          // 14
let present = (enabled & mask) != 0;  // true
```

`&`, `|`, `^` требуют два int или два byte. Результат сохраняет категорию;
смешивание требует явного `.int()` или `byte(...)`. Инверсия тоже сохраняет тип:
`~0` даёт int(-1), `~byte(0)` — byte(255). bool, string, char, float, rat,
массивы и объекты не преобразуются. Для any нужно существующее явное сужение.

Сдвиги принимают слева int/byte, справа именно int. Count — 0..63 для int,
0..7 для byte; выход за границы — ошибка, без маскирования count.

```okkama
1 << 63;              // -9223372036854775808
byte(128) << 1;       // byte(0): выдвинутый бит отброшен
-3 >> 1;              // -2: арифметический сдвиг, заполнение знаком
-1 >>> 1;             // 9223372036854775807: заполнение нулями
-1 >>> 0;             // -1: категория и ширина сохраняются
```

На int допускается точный signed-64 диапазон. Положительные значения int выше
INT64_MAX, которые существующий backend способен хранить, отвергаются при битовой
операции. Это не новая общая спецификация переполнений `+`, `-`, `*` и конверсий.
Непредставимые десятичные литералы и целочисленные результаты дают диагностику
языка вместо внутреннего исключения конструктора Perl.

Оба операнда вычисляются слева направо ровно один раз, затем проверяются типы.
Короткого замыкания нет: `0 & expression` вычисляет expression. Ошибка или отмена
вычисления слева предотвращает правую сторону. Те же правила действуют с await.

Приоритет от слабого к сильному:

```text
|| ; && ; <- ; == != ; .. ..= ; < <= > >= ; | ; ^ ; & ;
<< >> >>> ; + - ; * / % ; префиксные ! - ~ ; постфиксные вызовы/члены/индексы
```

Бинарные битовые операторы левоассоциативны. `flags & mask != 0` означает
`(flags & mask) != 0`, а `1 << 2 + 1` — `1 << (2 + 1)`.
Инфиксный `^` означает XOR. Префиксные `is ^Type` и `^field = ...` сохраняют
семантику преемников: `^bits = bits ^ mask;` однозначно разбирается парсером.
Составные присваивания `&=`, `^=`, `<<=` и т.п.
не добавлены, неизменяемость объектов и правила rebinding не меняются.

## Битовые методы

Методы int и byte, аргументы только позиционные:

| Действие | Результат |
| --- | --- |
| `bit_count()` | int: количество единичных битов |
| `leading_zeros()` | int: ведущие нули; у нуля — ширина слова |
| `trailing_zeros()` | int: замыкающие нули; у нуля — ширина слова |
| `rotate_left(count)` | Тот же тип: циклический сдвиг влево |
| `rotate_right(count)` | Тот же тип: циклический сдвиг вправо |
| `reverse_bits()` | Тот же тип: обратный порядок битов |
| `swap_bytes()` | int: обратный порядок 8 байтов; byte: исходное значение |

Вращения проверяют count так же, как сдвиги. Receiver не меняется.
Примеры: `(-1).bit_count()` → 64, `byte(128).rotate_left(1)` → byte(1),
`byte(1).reverse_bits()` → byte(128), `(0).leading_zeros()` → 64.

## Миграция потоков

Запись в поток теперь обозначается `<-`, прежний `<<` всегда означает сдвиг.

```okkama
writer <- "mask=" <- mask.string() <- "\n";
writer <- (value << 2).string();
```

Контракт Writing, адаптация string/@byte и порядок записи не изменились.
`a<-b` — запись; для сравнения с отрицательным числом нужны раздельные токены:
`a < -b`. `<<<` и бинарная `~` не являются потоковыми операторами.
Удалённые проекции `&Object()` по-прежнему запрещены. Форма `Object&(argument)`
теперь грамматически является бинарным И и не создаёт/не проецирует объект.

Соседние `>>`/`>>>` в типовом контексте закрывают вложенные generic-типы;
в выражениях это сдвиги. `xor` остаётся обычным идентификатором.
