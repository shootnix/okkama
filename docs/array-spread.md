# Распаковка массивов и потоковая запись

`expression...` явно передаёт элементы массива как последовательность
аргументов или источников потоковой записи. Операнд может быть переменной,
литералом массива или выражением, возвращающим массив. Настоящий вариадический
параметр также распаковывается через `name...`. Источник вычисляется один раз,
остаётся иммутабельным; снимается ровно один уровень массива.

## Преобразовать готовый массив

```okkama
let nums is @int = [1, 2, 3, 4, 5];
let bytes = @byte(nums...);
let framed = @byte(0, nums..., 255);
let combined = @int(nums..., 6, nums...);
```

В `@int(...)`, `@float(...)`, `@byte(...)`, `@string(...)` разрешено любое
количество позиционных распаковок в любом месте. После разворачивания
каждое значение проходит обычное одиночное преобразование. Без `...`
массив остаётся одним аргументом: `@byte(nums)` не преобразует его элементы.

Пустой источник добавляет ноль аргументов. Например, `@byte(empty...)`
возвращает пустой `@byte`, если `empty` — пустой массив. Тип результата
задаётся целевым типом, а не типом источника.

При `nums = [111, 256]` выражение `@byte(0, nums...)` сообщает об ошибке
аргумента 3 — номера в развёрнутой последовательности. Частичного результата
нет. Строки не разбираются, вложенные массивы не разворачиваются повторно,
упакованные в `any` значения не раскрываются.

## Записать элементы в поток

```okkama
out <- @string(1, 2, 3)... <- endl;
```

Это записывает `123` и перевод строки. `...` остаётся постфиксным оператором
с высоким приоритетом: запись разбирается как
`out <- (@string(1, 2, 3)...) <- endl`, без изменения приоритета `<-`.
Массив получается целиком один раз, затем его элементы по порядку передаются
обычному протоколу записи. Можно писать `out <- factory.words()...;`.

Каждый элемент должен быть строкой, `@byte` или формальным `ByteSource`.
Числа не преобразуются в текст автоматически; `@string(...)` делает это явно.
`out <- @byte(65, 66)` пишет сырые байты `AB`, а добавление `...` пытается
передать отдельные `byte` и приводит к ошибке типа источника.

Пустой массив не вызывает `write` и возвращает проверенный приёмник. Для
`Writing` используется тот же приёмник, для старого `ByteSink` каждый следующий
элемент получает результат предыдущей записи. При ошибке оставшиеся элементы
и источники цепочки не записываются; уже записанный префикс не откатывается.
Эффекты вычисления самого массива к этому моменту уже произошли.

Для ожидающего массива нужны скобки: `out <- (await source.words())...;`.
Постфиксный приоритет `...` выше `await`, поэтому распаковывается именно
полученный массив, а не `Future`.

## Передать массив вариадическому действию или конструктору

У обычного вариадического вызова разрешена одна последняя позиционная
распаковка. Все фиксированные параметры передаются явно перед хвостом:

```okkama
object Packet<T> {
    has content is @T;
    Packet(values is ...T) { content = values...; }
    items() is @T { content; }
}

object Sink {
    Sink();
    count(label is string, values is ...byte) is int {
        let content = values...;
        content.size();
    }
}
```

```okkama
let nums is @int = [1, 2, 3];
let bytes = @byte(nums...);
let packet = Packet(bytes...);          // T = byte
let count = Sink().count("body", bytes...);
let empty = @byte();
let empty_packet = Packet(empty...);    // пустой источник тоже задаёт T = byte
```

`Sink().count("body", nums...)` — ошибка типов: обычный вызов проверяет каждый
`int` против `...byte` и не добавляет преобразование. Вариадический параметр
можно передавать через `...` по тем же правилам, что и массив. Передача
`@any` в `...any` сохраняет непрозрачные оболочки без повторной упаковки.
У пустого нетипизированного `[]` нет свидетельства для вывода `T`; тогда нужна
явная ожидаемая специализация, например `let packet is Packet<int> = Packet(empty...);`.

Распаковка не заполняет пропущенные фиксированные параметры и не меняет
выбор фиксированных перегрузок. Скалярные касты, нативные вызовы и обычные
вызовы с фиксированной арностью не принимают `...`. Граница передачи
`spawn` сохраняет свой отдельный контракт и не принимает значения распаковки.

## Порядок вычисления и другие позиции

Получатель вызова вычисляется первым. Аргументы обрабатываются слева направо;
каждый источник распаковки читается один раз, элементы сохраняют свой порядок.
Затем выполняются проверки и преобразования. Уже выполненные эффекты
аргументов при ошибке не откатываются. Для `await` сохраняются те же правила:
продолжение удерживает уже прочитанный иммутабельный источник.

Массив допустим также в существующих позициях полного выражения распаковки:
`let copy = nums...;`, связывание поля конструктора и `for nums... -> item`.
Распаковка внутри литерала `[nums...]` и именованная распаковка остаются
недопустимыми позициями. Строки, диапазоны и непрозрачный `any` источниками
распаковки не становятся. Выражение-операнд проходит обычный семантический
анализ, включая проверки `void`, областей видимости и successor-результатов.
