# Object Capabilities (`cap`) 0.0.1

Полное название механизма — **Capability**, краткая форма в синтаксисе — `cap`.
Ранее механизм назывался Object Masks и объявлялся словом `mask`; переименование
не меняет семантику. Старый синтаксис объявлений больше не поддерживается.
В исторических R13–R14 и аудитах сохранены исходные имена, код и результаты:
их точное воспроизведение требует соответствующей прежней версии интерпретатора.
Cap ограничивает интерфейс конкретной ссылки и не добавляет общей модели
авторизации, чистоты вычислений или отзыва других ссылок.

Cap — именованный интерфейс вычисляемых значений конкретного завершённого
immutable объекта. Владелец хранит приватное состояние; cap задаёт стабильные
имена и типы значений для потребителя. Cap удерживает владельца без копирования
его состояния. Изменение внутреннего представления не меняет API потребителя,
пока сохранены контракты вычисляемых полей.

## Объявление и использование

```okkama
object Customer {
    has given_name, family_name is string;
    Customer(:given_name, :family_name);

    cap BusinessCard {
        full_name is string { given_name + " " + family_name; }
    }
}

object Printer {
    Printer();
    text(card is Customer::BusinessCard) is string { card::full_name; }
}
```

```okkama
let customer = Customer(given_name: "Ada", family_name: "Lovelace");
let card is Customer::BusinessCard = customer::BusinessCard;
Printer().text(card);
customer::BusinessCard::full_name;
```

Получение работает от произвольного объектного выражения. Это выражение
вычисляется ровно один раз. Вид `::` определяется доступным типом слева:
полный объект предоставляет объявленный cap, cap — своё вычисляемое поле.
Регистр имени не определяет вид операции. Чтение через `.field` и вызовы
методов cap отсутствуют. Поле с callable result можно вызвать обычным
синтаксисом: `card::callback()`.

Cap можно объявить отдельно от объекта в том же модуле:

```okkama
cap Customer::BusinessCard {
    full_name is string { Customer::given_name + " " + Customer::family_name; }
}
```

Это альтернативное место объявления того же номинального контракта.
Объект должен быть объявлен в этом модуле; расширять импортированный тип нельзя.
Порядок объявлений не важен, файлы одного связанного модуля могут различаться.
Во внешнем теле приватные поля обязательно квалифицируются типом владельца.
`Customer::given_name` читает поле конкретного экземпляра, от которого получен
cap; это не статическое поле и не ссылка на владельца. Квалификатор обозначает
пространство типа даже при одноимённом локальном binding. Методы владельца и
соседние cap через него недоступны. Внутренняя форма сохраняет короткие имена.
Дублирование имени между двумя формами — ошибка. Внешний cap наследует generic-параметры владельца: `cap Box::Public { value is T { Box::item; } }` для
`object Box<T>`. Получение и тип значения остаются `box::Public` и
`Box<int>::Public`. Импорты тела берутся из файла объявления cap. Обычное имя импортированной
функции или namespace не затеняется одноимённым приватным полем: оно доступно
только с квалификатором владельца.

## Номинальные границы

`Customer::BusinessCard`, `Customer::Billing` и `Supplier::BusinessCard` — разные
типы даже при совпадении полей. Идентичность включает объявляющий модуль,
ABI major и конкретные generic arguments владельца. Пример generic-аннотации:
`Box<int>::Public`; типы результатов проходят обычную подстановку параметров.
Импорты `take` и namespace aliases сохраняют существующие правила видимости:
`domain.Customer::BusinessCard`.

Передавать следует явно полученный cap. `Printer().text(customer)` — ошибка.
Cap не преобразуется во владельца, соседний cap или роль и не создаётся
через `Customer::BusinessCard(...)`. Restricted role reference не позволяет
получить cap спрятанного concrete origin.

Cap сохраняют свой тип и интерфейс в locals, параметрах, returns, полях других
объектов, коллекциях, generic API, captures и локальных async/Future API.
`any` переносит cap непрозрачно и не восстанавливает владельца cap или
интерфейс. Существующие ограничения process spawn и native ABI сохраняются.

## Область видимости тела

Форма поля: `name is Type { обычное тело Okkama }`. Действуют обычные выражения,
локальные bindings, control flow, explicit return, typed errors и panic.
Объявленный тип результата проверяется обычными правилами, включая role
restriction возвращаемого значения. Статически определимые нарушения
отвергаются анализатором; зависимые от значений — runtime guard.

В теле доступны для чтения приватные поля непосредственного владельца.
Совпадающее имя обозначает поле владельца:

```okkama
cap Card {
    name is string { name; }
}
```

Локальные bindings и параметры вложенных closures могут затенять эти имена.
Привилегия чтения не распространяется на приватные поля вложенных объектов.
Публичный вызов через явно доступное значение использует обычные правила.

`self` недоступен, в том числе внутри вложенного замыкания. Не создаются
скрытые `owner`, `origin`, `parent`, receiver cap или неявный receiver метода
владельца. Обращения к соседним вычисляемым полям по голому имени нет.
Присваивание owner fields, successor-присваивание и публикация cap
незавершённого владельца запрещены.

## Вычисление, эффекты и lifetime

Получение cap не выполняет тела полей. Каждое чтение выполняет тело заново;
значения и ошибки не кешируются. Ошибка одного чтения не портит cap и не
запрещает следующее чтение. Сохраняются различия typed error и panic.

Cap остаётся связанным с тем immutable значением, от которого получен.
После successor прежний cap видит прежнее состояние, новый — новое.
Вложенные shared capabilities сохраняют свои эффекты и разделяемость.

Cap удерживает весь граф владения исходного объекта, включая скрытые
ресурсы. Cap может пережить локальную переменную владельца, вернуться из
функции, получиться от временного выражения, храниться в коллекции, объекте
или замыкании. Cleanup владельца происходит по обычным правилам lifetime.

Поле имеет собственный синхронный контекст. Async-поля и `await` внутри поля
не поддерживаются; разрешение `await` вызывающего кода не наследуется.
Синхронное поле может вернуть явно объявленный `Future<T>`, который ожидает
вызывающий. Синхронный вызов capability может иметь эффект: обещания pure нет.

## Ограничения версии

В cap разрешены только вычисляемые поля с уникальными именами. Запрещены
`does`, методы, конструкторы, собственные `has`, successor-действия, lifecycle
blocks, тестовые blocks и вложенные cap. Cap не реализует роли.

Equality, ordering и пользовательское hashing cap не поддерживаются.
Равенство также отвергается для содержащих cap структурных значений и
при сравнении через generic/доверенный assertion transport `any`. Cap не
получает автоматическую stringification, сериализацию или enumeration
состояния владельца. Debug и диагностика могут безопасно назвать тип cap.

Результат поля имеет собственный контракт: автор может явно вернуть широкий
объектный тип. Cap ограничивает предоставленный интерфейс; общей гарантии
секретности, отсутствия эффектов или отзыва других полных ссылок cap не даёт.

Object views удалены: старые объявления `view` отвергаются. Слово `view`
остаётся допустимым обычным идентификатором. Роли, `allow` и `#projected`
сохраняют свои отдельные контракты. OIR Profile 0 остаётся int-only и явно
отвергает программы с объектами и cap.
