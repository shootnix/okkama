# Явные результаты действий

Каждое действие, включая анонимные действия, `main`, сигнатуры ролей и native,
обязано объявлять `is <тип>` или `is void`. Пропуск результата — ошибка синтаксиса.
`void` — маркер отсутствия результата, а не тип и не значение. Он недопустим
для полей, параметров, переменных, элементов коллекций и аргументов generic.
Синхронный void-вызов и await асинхронного void-вызова разрешены ради эффекта.
Использование отсутствующего результата в инициализаторе, аргументе, операторе,
цепочке вызовов или результате типизированного действия отклоняется analyzer,
если контракт известен статически; runtime также проверяет эту границу.

Последнее выражение void-тела выполняется, но его значение отбрасывается
и не передаётся вызывающему коду. Временные объекты освобождаются на обычной
границе области; сохраняются правила `destroy` и `defer`.
Типизированное действие по-прежнему возвращает и проверяет последнее значение.
Возврат получателя требует явного типа и выражения `self`; правила
действий-преемников `^Type` сохраняются.

Сигнатура callback допускает `(T) is void`; анонимное действие объявляет
параметры и результат явно: `(value is T) is void { ... }`. `async ... is void` и `async (T) is void` разрешены для именованных действий,
ролей, native-объявлений и связанных callbacks. `await repository.commit();`
ждёт завершения и не производит значения. Захват результата этого `await`,
передача в аргумент, помещение в коллекцию или возврат как значения запрещены.
`void` остаётся маркером результата: пользовательского `Future<void>`, null
или Unit нет. Typed throw, panic, отмена, `defer` и освобождение локальных
объектов сохраняют обычные async-правила.
Сам вызов создаёт ленивое ожидание: `let pending = repository.commit();`
можно ожидать несколько раз через `await pending;`. Его внутренний контракт
выводится автоматически и не имеет записи типа в исходном коде.
`spawn` запускает такое действие сразу. Анонимные async-действия пока не поддерживаются.

```okkama
module example v1.0.0;

object Counter {
    Counter();
    value() is int { 42; }
    inspect() is void { self.value(); }
    identity() is Counter { self; }
}

main() is int {
    let counter = Counter();
    counter.inspect();
    let callback is () is void = () is void { counter.inspect(); };
    callback();
    counter.identity().value();
}
```

Нельзя написать `let result = counter.inspect();`,
`counter.inspect().value()` или `let result is void = ...`.
`inspect()` без `is void` тоже недопустим.

Конструктор `Counter()`, блоки `destroy` и корневые `test`
не являются объявлениями действий: их синтаксис сохраняется.
Native-провайдер объявляет `is_void => 1, return_type => undef`;
его host-результат отбрасывается после обработки ошибки провайдера.
Старые провайдеры с обычным результатом сохраняют `is_void => 0`.

При миграции сначала определите контракт: команда получает `is void`,
значение — свой конкретный тип, возврат получателя — явный тип и `self`.
Вызовы команд в цепочках разделяются на инструкции. Оператор потоковой
записи `<-` сохраняет собственный контракт и не означает возврат значения
от действия `write`.
