# Узкий контракт чтения клиента

`public/customers.CustomerReading` предоставляет одну операцию:
`async customer_record(tenant, id) is Loaded<Customer>`. Хранилище проверяет оба
идентификатора; `Loaded` несёт значение и ожидаемую версию хранения.

`http/customer_read.CustomerReadController` получает эту роль и функцию
аутентификации. Сначала функция получает Principal, затем проверяются права,
затем вызывается чтение. Ответ выбирает существующий `Customer::Http`.
В `main.ok` явно связываются SqliteBilling и FixtureAuthentication; тест может
передать MemoryCustomers и отдельную функцию, сохранив тот же контракт.

Остальные SQL-команды и владельцы транзакций остаются на своих прикладных
границах. Ограничение методов роли проверяет обычный компилятор. Модульная
видимость R17 рассматривается отдельно в IMP25.
