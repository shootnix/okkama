# HTTP JSON: явный прикладной codec

Сначала проверяйте учётные данные и права. Затем `await request.json(4096)`
ограничивает тело и возвращает `RequestJson`: ошибки синтаксиса и повторные ключи
дают400, ошибки типов и отсутствующие поля —422. `text`, `int`, `integer` и
`number` сохраняют точные типы; `int` проверяет диапазон signed64.

Прикладной codec связывает имена полей с конструкторами предметной области.
В StructuredCustomerCodec
верхний объект и адрес имеют закрытые наборы полей, имя/email читаются один раз,
а BillingAddress и BillingContact выполняют свои проверки. Tenant передаёт
авторизованный обработчик. Сохранение и идемпотентный ключ остаются в application/
infrastructure, вне codec.

Ответ составляется из выбранного typed cap через `JsonObject`, `JsonMember` и
`JsonText`; точные суммы передавайте через `JsonNumber(Decimal(value.string()))`.
`web/reply.Json` использует `CompactJson` и UTF8. Для структурированного адреса
ответ содержит customer_id/address; для других представлений выбирается свой
явный набор полей.

HTTP-обработчик,
действующие схемы OpenAPI
и проверки показывают полный
путь: запрос → проверка → immutable domain object → SQL → выбранное представление.
Генератор OpenAPI остаётся источником документационных схем; тесты сверяют
выбранные поля и закрытую политику с реальным HTTP-поведением.
