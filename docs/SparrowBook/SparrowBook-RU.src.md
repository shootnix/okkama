# Книга об ассемблере Sparrow

Sparrow — байткод Okkama: его пишет `okkama build --target sparrow`, а рантайм
Sparrow (`sparrow`, `okkama exec`; его текущая версия — Tomato) проверяет его и исполняет
как машинный код. Книга учит текстовой форме байткода — ассемблеру Sparrow
(`.spa`) — настолько, чтобы читать то, что выдаёт компилятор, и писать
программы вручную. Описана версия SPB 12, формат Okkama 0.4.1.

Все примеры лежат в [examples/](examples/); при сборке книги каждый из них
ассемблируется, проверяется и запускается, а показанный после примера
результат — то, что напечатал `sparrow run`.

## 1. Инструменты

```sh
sparrow --assemble prog.spa -o prog.spb    # текст -> байткод (с проверкой)
sparrow --disassemble prog.spb             # байткод -> текст
sparrow check prog.spb                     # проверка и контракты intrinsic
sparrow run prog.spb [ARGS...]             # проверка и запуск
sparrow test prog.spb                      # тесты тестового профиля
okkama build prog.ok --target sparrow -o prog.spb   # Okkama -> SPB
okkama exec prog.spb                       # запуск SPB внутри okkama
```

Ассемблер и дизассемблер точно обратны друг другу: `--disassemble` файла и
`--assemble` полученного текста дают те же байты. Поэтому быстрее всего
изучать идиому так: написать её на Okkama, собрать и прочитать дизассемблер.

`sparrow run` возвращает целый результат `main` (0–255) как код выхода;
неперехваченный отказ печатается в stderr, код выхода 1.

## 2. Первая программа

{{example:hello}}

```text
$ sparrow --assemble hello.spa -o hello.spb && sparrow run hello.spb
Hello, Sparrow!
```

Программа Sparrow — набор таблиц (типы, затем функции) и `entry`. У `f0` нет
тела: это native, её предоставляет хост, а имя задаёт символ ABI. `f1` —
обычный код: четыре пронумерованные инструкции над тремя регистрами, типы
которых перечислены в `registers`. `call _, …` отбрасывает результат.
Комментарии начинаются с `;`.

## 3. Устройство файла

```text
sparrow 16                      ; версия формата
module "name" "version"         ; имя и версия модуля (можно "")
type t0 …                       ; таблица типов по порядку
enum enum0 "Name" ["a", "b"]    ; enum и его варианты
role role0 "Name" { method "m" [t…] -> t… … }
object obj0 "Name" { field "f" t… … does role0 [f…] destroy f… }
handle "Name"                   ; непрозрачные типы хоста (handle)
cap cap0 "Name" obj0 { field "f" f… }
global g0 t3 f2 [data …]       ; константа модуля: тип, init (#153), значение данными (#506)
function f0 "symbol" [async] [native "…"] [intrinsic "…" [obj…] [f…]] { … }
entry f3                        ; main программы
tests { test "name" f5 … }      ; или тестовый профиль
```

Константа модуля (`const`, #153) — это global: его читает `global.get`, а
строит первое чтение. Константа, чьё значение — простые данные (скаляры,
массивы и словари из них), несёт это значение в файле после `data`, и рантайм
строит его сам, без исполнения кода (#506): скаляр записан как у `const`
(`str "a"`, `int 7`), массив — `array N` и N элементов, словарь — `map N` и
N пар ключ–значение. Init такой константы только читает global. Таблица из
тысяч строк стоит в файле по несколько байт на элемент и ни одной инструкции;
до формата 15 каждый элемент был инструкцией init.

Каждая таблица индексируется по позиции, и индекс пишется явно: `t3`, `obj2`,
`role0`, `f5`, `enum1`, `cap0`. Ассемблер проверяет, что индексы идут подряд,
так что объявление не может незаметно сдвинуться. Тип может ссылаться только
на более ранние типы (`type t3 array t0`).

Дизассемблер печатает объявления в таком порядке: типы, enum, роли, объекты,
handle, cap, функции, затем `entry` или `tests`; ассемблер принимает их в
любом порядке, у каждой таблицы своя нумерация.

## 4. Типы

| Тип | Значение | Машинная форма |
|---|---|---|
| `int` | точное целое любого размера | слово с тегом или указатель на BigInt |
| `bool`, `char`, `byte` | | слово |
| `float` | IEEE binary64 | регистр с плавающей точкой |
| `rat` | точная дробь | указатель |
| `str` | неизменяемый текст UTF-8 | указатель |
| `object objN` | объект объявленного вида | указатель |
| `successor objN` | объект, который строит `obj.next` | указатель |
| `role roleN` | ссылка через роль | указатель |
| `enum enumN` | вариант enum без полезной нагрузки | слово |
| `variant variantN` | значение enum с полезной нагрузкой: объект одного из его случаев | указатель |
| `array tN`, `map tK tV` | неизменяемые коллекции | указатель |
| `builder tN`, `mbuilder tK tV` | их линейные сборщики | указатель |
| `fn [t…] -> t` | замыкание | указатель |
| `future t`, `future void` | результат async-вызова | указатель |
| `failure` | летящий отказ | указатель |
| `region` | регион владения | указатель |
| `any`, `range`, `handle N`, `cap capN`, `never` | упакованное значение, диапазон целых, handle хоста, cap, нет значения | |

Машинную форму каждого регистра Sparrow берёт из его объявленного типа. Поэтому
типы проверяются так строго (глава 16): регистр `int`, в котором лежала бы
строка, был бы прочитан как число.

## 5. Функции и регистры

```text
function f2 "Lab.total" {
    registers [t2, t3, t3, t0, t0, t0]   ; r0.. и их типы
    params [r0, r1, r2]                  ; параметры по порядку
    result t0                            ; или `void`
    handler 0 3 @5 r4                    ; ноль или больше обработчиков отказа
    0: …                                 ; пронумерованные инструкции
}
```

Регистры — не SSA: в регистр можно писать много раз, лишь бы тип оставался
объявленным. Каждое чтение должно видеть запись на каждом пути к нему (это
проверяет верификатор). Номера инструкций начинаются с 0 и идут подряд;
управление не должно сваливаться с последней инструкции.

Метод объекта — функция, первый параметр которой — сам объект; компилятор
называет их `Type.method`, конструкторы — `Type.new#N`.

## 6. Арифметика и сравнения

Целые не переполняются: результат, не помещающийся в 64 бита, становится
BigInt.

{{example:factorial}}

```text
$ sparrow run factorial.spb
265252859812191058636308480000000
```

`int.cmp le, r4, r0, r3` пишет `bool`; сравнения — `eq ne lt le gt ge`. У
каждого вида чисел свои инструкции — `int.*`, `float.*`, `rat.*`, `byte.*`, а
`cvt` преобразует к типу назначения (выше — `int` в `str`). `int.mod` —
остаток усечённого деления; нулевой делитель — отказ, как и нулевой
знаменатель у `rat.new`.

## 7. Управление и присваивания рёбер

`jmp @N`, `br rC, @THEN, @ELSE` и `ret rX` завершают участок. Цель перехода
может нести *присваивания ребра*: `@5(r0 <- r1, r1 <- r5)` присваивает
регистры при переходе, все сразу — каждый источник читается до записи любого
назначения.

{{example:fibonacci}}

```text
$ sparrow run fibonacci.spb; echo $?
55
```

Обратное ребро в инструкции 10 сдвигает `a, b` в `b, a + b` за один шаг, без
временного регистра для `a`. Так компилятор передаёт параметры блоков, и
умение читать присваивания рёбер — ключ к чтению скомпилированного кода.

## 8. Строки

`str.concat`, `str.len`, `str.slice`, `str.split`, `str.replace`,
`str.replace_first`, `str.trim`, `str.chomp`, `str.cmp` и `str.utf8` (в
`array byte`) работают с неизменяемым текстом; остальное — поиск, края,
регистр, повтор и символы строки — называет `str.fn`. Длины и позиции считаются в
скалярных значениях Unicode. В строковых константах есть `\n`, `\t`, `\"`,
`\\` и `\u{…}`.

## 9. Объекты, successor и роли

{{example:shapes}}

```text
$ sparrow run shapes.spb; echo $?
17
```

- `obj.new r2, obj0, [r0]` строит объект из полей в порядке объявления;
  `obj.get r1, r0, 0` читает поле 0.
- Объекты неизменяемы. `obj.next r4, r3, [1: r0]` строит successor — копию
  `r3` с заменённым полем 1.
- `does role0 [f0]` перечисляет для каждого метода роли функцию, которая его
  реализует. `role.wrap` превращает объект в ссылку роли;
  `call.role r7, r5, role0, 0, []` вызывает на ней слот 0 роли.
- `role.narrow` переводит ссылку одной роли в другую; если объект не делает
  целевую роль — отказ с указанным сообщением.
- Enum с полезной нагрузкой — объявление
  `variant variantN "Имя" { case "c" objK … }`: у каждого случая свой
  объект, поля которого — полезная нагрузка этого случая, и только она.
  `variant.new rD, variant0, 1, [r0]` создаёт случай 1, `variant.tag` даёт
  номер активного случая, `variant.get rD, rV, 1, 0` читает поле 0 случая 1
  и отказывает, если активен другой, а `variant.of` делает объект случая
  значением его варианта. Sparrow нужно, чтобы случаи варианта были объектами
  подряд: номер случая он берёт из заголовка объекта.

## 10. Массивы, сборщики и словари

{{example:collections}}

```text
$ sparrow run collections.spb; echo $?
88
```

Массивы неизменяемы; `builder` накапливает элементы, а `builder.finish`
строит массив. Сборщик линеен: каждый `builder.push` возвращает сборщик для
следующего шага (здесь — тот же регистр). `arr.get` с неверным индексом —
отказ, а `arr.lookup` и `map.lookup` завершают участок и ветвятся: элемент
пишется в их регистр назначения только на ребре «найдено». Словари
(`map.new r11, [r10: r12]`) хранят ключи в естественном порядке.

Операторы `+` и `-` над коллекциями Okkama компилируются в одну инструкцию на
цепочку: `arr.concat rD, [rA, rB, rC]` выделяет результат один раз под сумму
длин частей, `arr.diff rD, rA, [rB, rC]` оставляет элементы `rA`, не равные ни
одному элементу остальных, а `map.merge` и `map.diff` делают то же для
словарей (при повторе ключа — значение самой правой части).
`arr.replace rD, rA, rI, rV` — это `replaced(index, value)` (#250): копия `rA`,
в которой элемент `rI` равен `rV`; неверный индекс — отказ, как у `arr.get`;
`arr.remove rD, rA, rI` — это `removed_at(index)` (#251), копия без элемента
`rI` (версия формата 14).

## 11. Вызовы, замыкания и natives

- `call rD, fN, [args]` вызывает функцию напрямую; `call _, …` отбрасывает
  результат.
- `fn.closure rD, fN, [captures]` строит замыкание: захваты заполняют первые
  параметры `fN`, а `call.fn rD, rClosure, [args]` передаёт остальные.

{{example:closures}}

```text
$ sparrow run closures.spb; echo $?
42
```

- У *native*-функции нет тела: `native "runtime/stdio@1::stdout_write/1"`
  называет провайдер хоста в таблице ABI, а верификатор сверяет с ней
  сигнатуру функции. `sparrow --native-capabilities` печатает все natives.
- *Intrinsic*-функцию (`intrinsic "okkama.atomic.Atomic.get" [obj…] [f…]`)
  предоставляет сам Sparrow — atomics, события, каналы, таймауты — вместе с
  объектами и функциями-помощниками, над которыми она работает. Контракт
  каждой intrinsic Sparrow проверяет при загрузке программы.

## 12. Отказы: throw, обработчики и catch

{{example:errors}}

```text
$ sparrow run errors.spb; echo $?
7
```

- Бросить можно только объект, делающий встроенную роль `Error` (`throw r3`);
  `panic rS` — отказ с сообщением, `trap` — с фиксированным кодом и
  сообщением.
- `handler START END @TARGET rF` покрывает инструкции `START..END-1`: при
  отказе в них управление переходит в `TARGET`, а сам отказ кладётся в `rF`
  (тип `failure`).
- `catch rF, object, N, rV, @MATCH, @OTHER` проверяет отказ: если это `objN`
  (с `role` — он делает `roleN`, с `variant` — это случай `variantN`),
  пойманное значение пишется в `rV` на
  ребре к `MATCH`, иначе управление идёт в `OTHER`.
- `raise rF` передаёт отказ дальше без изменений. `fail.caused` и
  `fail.secondary` строят отказы, несущие тот, который они заменили.

Обратите внимание на `jmp @7` в инструкции 2: без него успешный путь свалился
бы в обработчик и прочитал `r2`, что верификатор отвергает:

```text
sparrow: Sparrow assembly line 0: Sparrow @main instruction 2: register r2 may be read before it is written
```

## 13. Ресурсы: регионы и destroy

{{example:resources}}

```text
$ sparrow run resources.spb
closing data.txt
```

Вид объекта с `destroy fN` владеет ресурсом. Область открывает регион
(`region.enter`); новый ресурс записывается (`region.track`) и переходит во
владение региона (`region.adopt`); `region.leave` вызывает `destroy` всего,
чем владеет регион, от новых к старым. На пути отказа то же делает
`region.unwind` и возвращает отказ, к которому присоединены отказы самих
`destroy`. `region.transfer` передаёт владение другому региону, а
`region.leave r, rK` сохраняет достижимое из `rK` (возвращаемое значение).

## 14. Async-функции и future

{{example:tasks}}

```text
$ sparrow run tasks.spb; echo $?
11
```

Вызов `async`-функции возвращает *холодный* future, не выполняя его. `await`
выполняет его (или ждёт) и даёт его значение; `fut.spawn` запускает его
сейчас, и он работает, пока вызывающий идёт дальше; `fut
cancel|done|cancelled` отменяет future или смотрит его состояние.
Async-функция компилируется в возобновляемый автомат; `main` тоже может быть
async.

## 15. Тесты

{{example:testing}}

```text
$ sparrow test testing.spb
=== RUN   doubles small numbers
--- PASS: doubles small numbers
PASS
```

Файл с `tests` вместо `entry` — тестовый профиль: каждый тест — функция без
параметров, она исполняется на новом рантайме; отказ проваливает тест. Такие
файлы из тестов Okkama строит `okkama build -t`.

## 16. Что гарантирует верификатор

Байткод проверяется при ассемблировании, декодировании и загрузке — до
исполнения чего-либо. В принятом верификатором файле:

- таблицы в границах: типы ссылаются на более ранние типы, на существующие
  объекты, роли, enum, cap и handle; у каждой роли, которую делает вид
  объекта, есть свидетель с функцией на каждый метод;
- регистры, цели переходов, обработчики (отсортированы, не пересекаются) и
  индексы таблиц в границах; ни одна инструкция не сваливается с конца кода;
- каждый регистр записан до чтения на каждом пути, включая источники
  присваиваний рёбер и цели обработчиков;
- типы сходятся: операнды и результат каждой инструкции, арность, типы
  аргументов и результата каждого вызова, присваивания рёбер, `ret`, слоты
  ролей, поля cap, `destroy`, точка входа (без параметров, результат `int`),
  тесты и natives по таблице ABI.

```text
sparrow: Sparrow assembly line 0: Sparrow @main instruction 2: r1 has type str, expected int
```

Декодирование и проверка ограничены по памяти, а `sparrow check` ещё и
проверяет контракты intrinsic. Что остаётся открытым, перечислено в модели
доверия (`docs/security-model.md`).

## 17. Как Sparrow это исполняет

Sparrow компилирует каждую функцию в машинный код (Cranelift) при первом
вызове; интерпретатора нет. Регистры живут в машинных регистрах или в кадре
в зависимости от типа. Объекты выделяются прямо в коде из классов размеров;
точный неперемещающий сборщик находит указатели по картам стека в точках
вызова (safepoint). Отказ передаётся статусом, который проверяет каждая
инструкция, способная отказать, поэтому обработчики ничего не стоят, пока
отказов нет. Бюджеты (`--max-steps`, `--max-memory`, `--max-output`,
`--timeout`) заставляют машинный код опрашивать их на входах в функции и
обратных переходах.

## 18. Справочник инструкций

`rD` — регистр назначения, `_` — его отсутствие; `@T` — цель с необязательными
присваиваниями ребра; `[…]` — список.

{{reference}}
