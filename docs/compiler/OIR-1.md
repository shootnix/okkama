# OIR-1: промежуточное представление Okkama

**Редакция:** 20 октября 2026. **Статус:** проект спецификации, реализации нет.
**Предшественники:** [OIR-0](oir-0.md) (int-профиль Perl-компилятора),
[OASM-1.0](OASM-1.0.md) (проект ISA виртуальной машины),
`okkama-rs/crates/okkama-compiler/src/ir` (линейный int IR).

OIR-1 — единое промежуточное представление между фронтендом Okkama и любыми
backend: регистровой VM, C, LLVM, JVM. Оно полностью выражает семантику
Okkama 1.0 и при этом низкоуровневое: типизированный SSA-граф базовых блоков
без выражений, без вложенных областей и без неявного управления.

```text
.ok → parse → analysis (имена, типы, вывод, must-use) → lowering
    → OIR-1 high ── проходы ──→ OIR-1 low ──→ backend
                                              ├─ register VM / OASM
                                              ├─ C11
                                              ├─ LLVM IR
                                              └─ JVM class files
```

## 1. Принципы

1. **Статическая типизация без исключений.** У каждого значения OIR есть
   статически известный тип, записанный в тексте. Фронтенд выполнил вывод
   типов, разрешение имён, выбор overload и вывод generic-аргументов. В OIR
   нет динамического типа, `dyn`, поиска метода по имени и runtime-выбора
   overload.
2. **Нет неявного управления.** Каждый переход, каждый путь отказа, каждый
   запуск `defer` и каждое закрытие области записаны явно. Backend не обязан
   знать, что такое `defer`, `try` или `last`.
3. **Нет неявного владения.** Детерминированный `destroy` выражен явными
   операциями регионов (§7). Освобождение памяти — забота backend (GC, RC,
   арены) и на семантику не влияет.
4. **SSA с параметрами блоков.** Неизменяемость Okkama ложится на SSA
   напрямую: `let` — это определение значения, rebind — новое значение,
   передаваемое через параметр блока. Параметры блоков механически становятся
   phi (LLVM), присваиваниями перед `goto` (C), local slots (JVM) или
   регистрами (VM).
5. **Одна инструкция — одна семантика.** Мнемоника вместе с типами операндов
   однозначно определяет поведение. Перегруженных по типу opcode нет:
   `int.add` и `float.add` — разные инструкции.
6. **Классы отказа фиксированы.** Каждая инструкция относится к одному классу:
   чистая, trap, throwing или suspending (§16). По этому классу backend решает,
   где нужны проверки статуса.
7. **Сахар остаётся во фронтенде.** Проекции, `<-`, `confirm`, postfix `if`,
   `match`, функциональные блоки, именованные аргументы, unpack, shorthand
   конструкторы и литералы диапазонов в массивах в OIR не попадают (§19).
8. **Гарантии остаются в рантайме.** Точная арифметика, границы, ownership
   и кэширование Future описаны как контракты инструкций, а не как
   рекомендации.
9. **Два уровня одного языка.** `high` — то, что строит фронтенд: есть async,
   generics и successor-типы. `low` — то, что получают простые backend: после
   нормативных проходов (§20) в нём нет корутин, generic-параметров и
   `^T`-типов. Low является подмножеством high плюс несколько низкоуровневых
   инструкций.
10. **Текст канонический.** Текстовая форма однозначна и полна;
    бинарная форма (OIRB) — её прямая кодировка.

## 2. Модуль и символы

### 2.1 Заголовок

```oir
oir 1 high
module app v1.0.0
requires core, async
import io/stdout@1 as stdout
import collections/iteration@1 as iteration
file 0 "app/main.ok"
entry @main
```

- `oir 1 high|low` — версия и уровень. Неизвестная версия или уровень
  отвергаются.
- `module` — путь и версия исходного модуля Okkama. Несколько `.ok`-файлов
  одного модуля дают один модуль OIR.
- `requires` — используемые возможности: `core` (обязательна), `async`,
  `process`, `test`. Backend без поддержки возможности отвергает модуль, а не
  исполняет его частично.
- `import path@major as alias` — каноническая identity зависимости. Alias —
  только текстовое имя; в бинарной форме ссылки полностью квалифицированы.
  Циклы импорта запрещены. Пока загрузки модулей нет, lowering сохраняет
  исходную запись `import "path" [as alias] [take a, b]` — **неразрешённый
  импорт**. Backend такой модуль отвергают.
- `file N "path"` — таблица исходных файлов для отладочных меток.
- `entry @sym` — необязательная точка входа, только у корневого модуля.

Реализация `okkama-rs` пока **связывает** программу целиком: импортированные
модули загружаются, и всё становится одним модулем OIR без `import`.
Объявления импортированного модуля квалифицированы его путём (`/` → `.`):
тип `io.stdout::Stdout`, функция `@io.stdout::Stdout.writeln`. Раздельная
компиляция с `import path@major` — следующий шаг.

### 2.2 Символы

Функции и глобальные объявления называются символами `@...`, типы —
именами без сигила. Имя без alias относится к текущему модулю,
`alias::Name` — к импортированному. В бинарной форме все имена
квалифицированы: `app@1::Purse`.

Соглашение об именах функций (фронтенд обязан ему следовать, чтобы листинги
были сравнимы):

| Источник | Символ |
|---|---|
| `main()` | `@main` |
| action `total` объекта `Purse` | `@Purse.total` |
| overload `add`, k-й в порядке объявления | `@Purse.add#k` |
| k-й конструктор `Purse` | `@Purse.new#k` |
| shorthand `Purse(:a, :b)` (k-й), вызванный только с `a` | `@Purse.new#k.a` (поля в порядке объявления; со всеми полями — `@Purse.new#k`) |
| default поля `cents` | `@Purse.default.cents` |
| `destroy` | `@Purse.destroy` |
| поле cap `Card.name` владельца `Customer` | `@Customer::Card.name` |
| k-й анонимный action внутри `@f` | `@f.lambda#k` |
| fake роли `Package` и её action `open` | `@Package.fake.open` |
| k-й test в объявлении `X` / модуле | `@X.test#k` / `@test#k` |

Если overload один, суффикс `#0` опускается. Символ — непрозрачный
идентификатор: структура имени нужна людям и диагностике, а не семантике.

### 2.3 Отладочные метки

Любая инструкция и терминатор могут нести суффикс `!F:L:C` (файл, строка,
столбец; строки и столбцы с единицы). Метки не меняют семантику; без них
модуль исполним.

## 3. Типы

### 3.1 Перечень

| Тип OIR | Okkama | Вид |
|---|---|---|
| `int` | `int` | целое произвольной точности (bigint) |
| `float` | `float` | конечный IEEE-754 binary64 |
| `rat` | `rat` | нормализованная дробь произвольной точности |
| `byte` | `byte` | 0..255 |
| `bool` | `bool` | `true`/`false` |
| `char` | `char` | Unicode scalar value |
| `str` | `string` | неизменяемый UTF-8 |
| `range` | `a..b`, `a..=b` | границы int, флаг inclusive |
| `array<T>` | `@T` | неизменяемый массив |
| `map<K,V>` | `%K:V` | неизменяемый map, порядок по ключу |
| `E` (enum) | `enum E` | номинальное перечисление |
| `C<A..>` (object) | object | конкретная ссылка |
| `R<A..>` (role) | role | ограниченная ссылка |
| `Owner::Cap` | `cap` | capability над владельцем |
| `H` (native object) | `native object H` | непрозрачный handle |
| `any` | `any` | непрозрачный box |
| `fn(T..) -> R`, `async fn(T..) -> R` | `(T..) is R` | замыкание |
| `future<T>`, `future<void>`, `future<^C>` | `Future<T>` | ленивый Future |
| `^C` | результат successor | обязательство использования |
| `never` | — | элемент нетегированной пустой коллекции |
| `failure` | — | служебный: активный отказ |
| `region` | — | служебный: регион владения |
| `builder<T>`, `mbuilder<K,V>` | — | служебный: линейный сборщик |
| `type`, `frame<@f>`, `cell<T>` | — | только в low (§20) |

Объект или роль определяется объявлением имени, а не синтаксисом ссылки:
`Purse` — объект, если объявлен `object Purse`, и роль, если объявлен
`role Purse`.

`void` допустим только как результат функции, функционального типа и
Future. Это не тип значения.

`never` встречается только как `array<never>` и `map<never,never>`:
это тип литералов `[]` и `[:]`, которым фронтенд не нашёл целевой тип.
Значение `array<never>` переводится в любой `array<T>` инструкцией
`array.retag`.

Нетегированный гетерогенный литерал (`[1, "two"]`) имеет тип `array<any>`:
фронтенд вставляет `any.box` для каждого элемента. Map с значениями
разных типов — `map<K, any>`. Ключи разных типов — ошибка компиляции, потому
что ключ не может быть `any`.

Служебные типы (`failure`, `region`, `builder`, …) не являются значениями
Okkama. Их нельзя положить в коллекцию, поле, `any`, замыкание или Future,
передать в native или вернуть из функции. Исключение: `failure` и `region`
передаются как параметры блоков внутри функции.

### 3.2 Равенство типов

Типы равны структурно для встроенных конструкторов и номинально для
объявлений. Номинальная identity включает модуль, ABI major, объявление и
применённые аргументы: `Box<int>` ≠ `Box<float>` ≠ `other::Box<int>`.
Подтипирования нет. Есть ровно три явных преобразования ссылок:
`role.wrap` (конкретный → роль), `role.narrow` (роль → роль) и
`array.retag`/`map.retag` (`never` → `T`).

### 3.3 Plain-типы

Тип **plain**, если значение этого типа гарантированно не достигает
идентичности с `destroy` или fake storage:

- все скаляры, `str`, `range`, enum — plain;
- `array<T>` и `map<K,V>` — plain, если plain `T` (`V`);
- объект — plain, если у него нет `destroy`, он не fake и все типы его
  полей plain (после подстановки аргументов);
- роли, параметры типа, `fn`, `future`, `any`, handles, caps — **не**
  plain: за ними может скрываться что угодно.

Операции регионов над plain-значениями — no-op. Фронтенд вправе их не
выпускать; проходы low удаляют оставшиеся (§20).

## 4. Значения и идентичность

- Скаляры, `str`, `range`, enum — значения без наблюдаемой identity.
- Объекты, замыкания, Future, handles, caps — ссылки с identity. Identity
  наблюдается только владением и `destroy`. `val.eq` над объектами —
  глубокое сравнение, не сравнение указателей.
- Массивы и map — неизменяемые значения. Они сохраняют identity хранимых
  объектов.
- `any` — box из дескриптора типа и значения. Распаковки нет. В `okkama-rs` (JVM)
  box хранит только значение (`okkama.rt.Any`): классы значений различимы и
  так; `equals` box — trap `Cannot compare any without narrowing`.
- Ссылка роли — пара (исходное значение, таблица свидетельства роли).
  Восстановить конкретную ссылку из ссылки роли нельзя.

Все объекты неизменяемы и строятся снизу вверх (§8), поэтому граф объектов
ациклический. Цикл возможен только через изменяемые ячейки рантайма: буферы
каналов, fake storage, native memory. Это важно для backend с подсчётом
ссылок (§21.2).

## 5. Функции, блоки, SSA

### 5.1 Функция

```oir
func @Purse.total(%self: Purse) -> int [method Purse] {
^entry:
    %d: int = obj.get %self, digit
    %k: int = const 100
    %m: int = int.mul %d, %k
    %c: int = obj.get %self, cents
    %t: int = int.add %m, %c
    ret %t
}
```

Сигнатура: символ, необязательные параметры типа `<T, U>`, необязательный
список захватов `[...]` (только `lambda`), параметры, результат и атрибуты.
Параметры передаются строго позиционно. Именованные вызовы Okkama фронтенд
переупорядочивает, но аргументы вычисляет в исходном порядке (§19).

Атрибуты:

| Атрибут | Значение |
|---|---|
| `method C` | action объекта; первый параметр — `self: C` |
| `private` | вызов разрешён только из функций того же владельца |
| `ctor C` | конструктор; может выполнять `obj.new C` |
| `successor C` | результат `^C`; может выполнять `obj.next` |
| `destroy C` | hook уничтожения, `(self: C) -> void` |
| `default C.f` | default поля, без параметров |
| `cap Owner::Cap` | поле capability, первый параметр — владелец |
| `lambda` | тело анонимного action, имеет захваты |
| `async` | корутина; вызов даёт `future<R>` |
| `entry` | точка входа (`main`) |
| `test`, `fake R` | тестовый профиль (§15) |
| `intrinsic "name"` | тело предоставляет рантайм (§14.2), блоков нет |

Право читать поля (`obj.get`) имеют функции с атрибутом `method`, `ctor`,
`successor`, `destroy` или `fake` того же владельца, а также функции `cap`
этого владельца. Это проверяемое правило верификатора, а не соглашение.

### 5.2 Блоки

```oir
^loop(%i: int, %acc: int) unwind ^cleanup(%acc):
```

Блок — метка, параметры, необязательная цель unwind, последовательность
инструкций и ровно один терминатор в конце. Первый блок — вход функции,
его параметры совпадают с параметрами функции и в тексте не повторяются.
Вход не может быть целью перехода: цикл всегда начинается отдельным блоком.
Канонический принтер называет блоки `^b0…` в reverse postorder, а значения —
`%0…` в порядке определения, начиная с параметров функции.

Значения — SSA: каждое определяется ровно один раз, а каждое использование
должно доминироваться определением. Переприсваивания нет. Rebind Okkama —
это новое значение, которое в точке слияния приходит параметром блока.

### 5.3 Терминаторы

| Терминатор | Семантика |
|---|---|
| `br ^b(%args)` | безусловный переход |
| `cond %c, ^t(...), ^f(...)` | переход по точному `bool` |
| `switch.int %v, [0: ^a(...), 5: ^b(...)], else ^c(...)` | int, ключи уникальны |
| `switch.enum %e, [ready: ^a(...), failed: ^b(...)], else ^c(...)` | `else` можно опустить при полном покрытии |
| `ret %v` / `ret` | возврат значения / завершение void |
| `throw %e` | поднять типизированный отказ; `%e` — объект или роль, делающие `Error` |
| `panic %msg` | неперехватываемый отказ с точной строкой `str` |
| `trap CODE "text"` | программная ошибка (например, bare `confirm`) |
| `raise %f` | продолжить распространение отказа `failure` |
| `catch %f is T, ^h(...), ^n(...)` | выбор catch (§6.4) |
| `array.lookup`, `map.lookup` | ветвление по наличию элемента (§12) |
| `unreachable` | недостижимо; исполнение — программная ошибка |

Терминаторы, кроме `catch` и `*.lookup`, не создают значений.

Коды `trap`: `confirm` — не выполнен `confirm` без `else`; `range` — начало
диапазона больше конца; `empty` — `first()`/`last()` пустого массива;
`unreachable` — исполнение дошло до недостижимой точки lowering. Текст
диагностики — строка терминатора (`RuntimeError: <text>`); код нужен
инструментам и не меняет поведения.

## 6. Модель отказов

### 6.1 Каналы

Значение типа `failure` описывает активный отказ одного из видов:

| Вид | Источник | Ловит `catch` |
|---|---|---|
| `thrown` | `throw`, `confirm … else throw`, `NativeFailure`, `Cancelled` | да |
| `panic` | `panic "…"`, `confirm … else panic` | нет |
| `program` | trap: границы, деление на ноль, неконечный float, bare `confirm`, … | нет |

У `failure` есть: вид; для `thrown` — исходный Error-объект (identity
сохраняется); origin (место возникновения); список вторичных отказов
cleanup; цепочка причин (cause).

### 6.2 Цель unwind

Инструкции классов trap, throwing и suspending (§16) могут отказать. При
отказе управление переходит к **цели unwind** текущего блока:

```oir
^body unwind ^on_fail(%x):
    ...
^on_fail(%x: int, %f: failure):
```

Цели передаются явные аргументы, а значение `failure` добавляется последним
параметром. Явные аргументы должны быть определены до начала блока-источника:
это параметры блока или значения из блоков, доминирующих над ним. В цели unwind
можно использовать только такие значения. Значения, определённые внутри
блока-источника, на ребре отказа не существуют: отказать могла любая его
инструкция. Это правило совпадает с семантикой `invoke` в LLVM и с кадрами
exception handler в JVM.

Блок без `unwind` распространяет отказ из функции. Верификатор требует,
чтобы в таком блоке не было открытых регионов (§7). Отказывающие терминаторы
(`throw`, `raise`, `panic`, `trap`, `unreachable`) подчиняются тому же правилу:
отказ уходит в цель unwind своего блока, а без неё — из функции. Поэтому
`raise` во вложенном `try` автоматически доходит до внешнего dispatch.

Верификатор проверяет правило видимости доминированием на графе, где у
каждого блока два узла — начало и тело: обычные переходы идут из тела,
ребро unwind — из начала.

Отказавшая инструкция не определяет своё значение и не имеет частичных
эффектов, кроме уже выполненных внешних (I/O не откатывается).

### 6.3 Операции над failure

| Инструкция | Семантика |
|---|---|
| `%g: failure = fail.secondary %primary, %cleanup` | `%primary` с добавленным вторичным отказом |
| `%g: failure = fail.caused %new, %handled` | если `%new` — `thrown` и не тот же carrier, что `%handled`, к `%new` добавляется cause `%handled`; иначе `%new` без изменений |
| `%b: bool = fail.is_thrown %f` | наблюдение вида |

`fail.caused` реализует правило цепочек причин из §20 спецификации: bare
rethrow не добавляет self-cause, panic и программные ошибки причинами не
становятся.

### 6.4 Catch

```oir
catch %f is InvalidValue, ^handler(%f), ^next(%f)
```

Если `%f` — `thrown` и его Error совместим с `T`, управление идёт в
`^handler`, и к аргументам добавляется значение типа `T`. Если `T` — объект,
совместимость означает тот же конкретный тип; если `T` — роль `Error`, Error
оборачивается в ограниченную ссылку. Иначе управление идёт в `^next`. Допустимые
`T`: `Error`, конкретный объект, делающий `Error`, `NativeFailure`, `Cancelled`.
Несколько clauses Okkama дают цепочку `catch` в порядке исходника.

### 6.5 Приоритет отказов

Порядок «основной отказ тела, затем первый отказ defer, затем первый отказ
destroy» не встроен в инструкции. Фронтенд выражает его формой блоков cleanup
(§19.3): на пути отказа новые отказы присоединяются через `fail.secondary`,
на нормальном пути первый отказ становится основным. `region.leave` и
`region.unwind` (§7) применяют то же правило внутри себя.

## 7. Регионы владения

Регион — runtime-реестр идентичностей, принадлежащих одной лексической
области Okkama. Семантика повторяет §10 и §19 спецификации языка.

| Инструкция | Класс | Семантика |
|---|---|---|
| `%r: region = region.enter` | чистая | открыть дочерний регион текущего кадра |
| `region.adopt %r, %v` | чистая | зарегистрировать в `%r` все **свободные** идентичности, достижимые из `%v`, в порядке создания; уже принадлежащие кому-то не трогаются (заимствование) |
| `region.track %r, %v` | чистая | зарегистрировать свободные идентичности `%v` в `%r` **без владения**: их может принять вызванное следом действие; иначе `%r` уничтожит их при закрытии |
| `region.leave %r` | throwing | уничтожить принадлежащие `%r` идентичности в обратном порядке регистрации (родитель раньше своих детей), закрыть `%r` |
| `region.transfer %from, %to, %v` | чистая | передать идентичности `%v`, принадлежащие открытому `%from`, во внешний `%to` (значение уходит в поле объекта, переживающего `%from`) |
| `region.leave %r, keep [%v…]` | throwing | то же, но идентичности, достижимые из `%v…`, освобождаются (становятся свободными), а не уничтожаются |
| `%g: failure = region.unwind %r, %f` | чистая | закрыть `%r` на пути отказа: идентичности, достижимые из Error в `%f`, освобождаются, остальные уничтожаются; отказы destroy добавляются к `%f` как вторичные |

Правила:

- Регионы образуют стек внутри кадра. Закрывать можно только верхний
  открытый регион. Верификатор проверяет, что стек открытых регионов в каждой
  точке программы однозначен (как в OASM-1.0 цепочка scope).
- `region.leave` запускает **все** destroy, даже если какой-то упал. Отказ
  первого становится основным, остальные — вторичными. После `region.leave`
  регион закрыт в любом случае, поэтому цель unwind блока с `region.leave`
  не должна обращаться к этому региону.
- Каждая идентичность входит в destroy не более одного раза. Destroy
  вызывается рантаймом через `destroy`-функцию из дескриптора типа.
- **Вход в функцию.** Функция, у которой есть не-plain параметры, открывает
  корневой регион и выполняет `region.adopt` для этих параметров: свежие
  аргументы без владельца у вызывающего становятся собственностью callee
  (§19 спецификации, «Fresh receivers/arguments … are adopted»).
- **Выход из функции.** Возвращаемое значение не уничтожается: последний
  `region.leave … keep [%v]` освобождает достижимые из него идентичности, и их
  принимает вызывающий.
- **Временные значения** — как в Perl-интерпретаторе (сверено опытами):
  результат вызова учитывается регионом текущей области без владения
  (`region.track`). Если его передают receiver или аргументом действию,
  вызванный принимает его во владение на входе и уничтожает при выходе,
  если не вернул. Иначе значение принадлежит блоку и уничтожается при выходе
  из него; отдельного региона оператора нет:
  ```okkama
  let n = Res(name: "a").name_value(); // Res "a" уничтожен при выходе из name_value
  let k = [Res(name: "q")].size();     // Res "q" живёт до конца блока
  Res(name: "b");                      // Res "b" живёт до конца блока
  ```
  Выражение без привязки нельзя удалять: вызовы, конструирование и `destroy`
  наблюдаемы. Удалить можно только доказуемо чистое выражение.
- **Значение ветви.** Последний оператор выбранной ветви `if`, `match` или
  `try` отдаёт своё значение внешнему блоку (`region.leave … keep`, затем
  `region.track` внешней области), даже если результат оператора не
  используется: `if c { let f = Res(…); }` уничтожает `f` в конце внешнего
  блока. У блока `{ … }` и тела цикла значение не переходит.
- **Результат вызова**, переданный сразу аргументом, возвращённый или
  сохранённый в агрегат, принимает адресат.
- **Rebind** принимает новое значение в регион, которому принадлежит
  исходная привязка, а не в регион итерации. Прежнее значение не уничтожается
  досрочно.
- **Catch** принимает пойманный Error в регион тела handler.
- Регионы живут в кадре корутины и переживают приостановку.

Освобождение памяти от регионов не зависит: закрытый регион запускает
destroy, но не освобождает память, если на объект ещё есть ссылки.

## 8. Объекты, конструирование, successor

### 8.1 Объявление

```oir
object Purse {
    field digit: int
    field cents: int = @Purse.default.cents
    does Wallet { total = @Purse.total }
    destroy @Purse.destroy
}

object Box<T> {
    field value: T
}

object Heap<T: Comparing<T>> {
    field items: array<T>
}
```

Поля перечисляются в порядке объявления. Этот порядок определяет порядок
default, раскладку, глубокое сравнение и порядок обхода владения. `does R`
задаёт таблицу свидетельства: каждому action роли сопоставлена функция.
Верификатор проверяет полноту и точное совпадение сигнатур (с
ковариантностью successor-результата `^C` → `^R`).

### 8.2 Конструирование

Конструктор Okkama — функция `[ctor C]`. Она вычисляет значения полей как
обычные SSA-значения и завершается одной инструкцией:

```oir
%p: Purse = obj.new Purse { digit: %d, cents: %c }
```

- `obj.new` перечисляет **все** поля в порядке объявления, каждое один раз.
  Неполная конструкция невыразима, поэтому runtime-проверка полноты не нужна.
- Defaults вызываются в начале конструктора, в порядке полей, даже если тело
  потом переопределит поле: default наблюдаем через эффекты. Фронтенд вправе
  опустить вызов default, только если он доказуемо чистый.
- `self` в конструкторе не существует как значение. Чтение `self.field`
  после field-bind — это использование соответствующего SSA-значения.
  Поэтому неопубликованный объект не может утечь.
- Shorthand-конструкторы (`Cash(:digit)`) — такие же функции с параметрами
  в порядке списка.
- Вызывающий выполняет обычный `call @C.new#k(...)`; выбор конструктора
  статический.

### 8.3 Successor

```oir
func @Bottle.open(%self: Bottle) -> ^Bottle [successor Bottle] {
^entry:
    %t: bool = const true
    %n: Bottle = obj.next %self { opened: %t }
    ret %n
}
```

`obj.next %self { f: %v… }` создаёт **новую** идентичность: поля из `%self`
плюс перечисленные замены, каждая один раз. Конструкторы и defaults не
перезапускаются. Fake storage сохраняется (§15). Исходный объект не
меняется. Отказ до `obj.next` не оставляет частичного successor.
Последовательные `^f = …` Okkama — это просто SSA: в `obj.next` идёт последнее
значение.

### 8.4 Must-use

Вызов функции с результатом `^C` даёт значение типа `^C`. Использовать его как
`C` можно только после явного погашения обязательства:

```oir
%s: ^Bottle = call @Bottle.open(%b)
%opened: Bottle = succ.take %s
```

Правило верификатора: на каждом нормальном пути от определения значения `^C`
до `ret` должно выполниться хотя бы одно `succ.take` этого значения, либо
значение возвращается (`ret`), либо передаётся аргументом перехода — тогда
обязательство переходит к параметру блока и проверяется для него. Повторное
`succ.take` допустимо: это не линейный тип (§11.1 спецификации: «Already
consumed successors remain reusable»). Пути отказа (`throw`, `panic`, `raise`,
unwind) обязательство снимают. Значение `^C` можно сохранить в `future<^C>`;
всё остальное требует `succ.take`. `successor`-функция возвращает построенный
`obj.next` объект типа `C` при результате `^C`.

Слияние: если хотя бы одна ветвь не погасила `^C`, ветви, погасившие его,
передают исходное значение `^C`, и обязательство остаётся. Переменная, которая
входит в цикл с непогашенным `^C`, получает параметр заголовка типа `^C`:
rebind в теле передаёт новое значение `^C`, а после цикла обязательство ещё
нужно погасить (тело могло не выполниться).

Анализ потребления из §11.1 спецификации (алиасы, ветвления, циклы, defer,
замыкания) выполняет фронтенд и размещает `succ.take` там, где Okkama считает
значение использованным. Верификатор OIR проверяет только результат. В
рантайме `^C` стирается (§20).

### 8.5 Caps

```oir
cap Customer::Card {
    field name: str = @Customer::Card.name
}
```

`%k: Customer::Card = cap.make %customer` создаёт capability (owner +
дескриптор). В `okkama-rs` объявление `cap` модуля перечисляет поля и их
функции (`[method Customer]`: им доступны поля владельца); значение cap на JVM
— сам владелец. Чтение `card::name` — `call.cap %k, name()`: оно вызывает
`@Customer::Card.name(owner)` и каждый раз вычисляет заново. Функция cap
получает владельца и право читать его поля, но не `self` cap.

## 9. Роли и диспетчеризация

```oir
role Wallet {
    total() -> int
}

role Package {
    open() -> ^Package
    close() -> ^Package
}

role Comparing<T> {
    less(T) -> bool
}
```

Action роли называется `Role.name#k` (`#k` — индекс overload внутри роли)
и задаёт слот таблицы свидетельства. Порядок слотов — порядок объявления.

| Инструкция | Семантика |
|---|---|
| `%w: Wallet = role.wrap %p` | конкретный → роль; таблица выбирается статически по `does` |
| `%w: Comparing<T> = role.wrap %v` | `%v: T`, `T: Comparing<T>`: таблица берётся из свидетельства bound |
| `%o: Other = role.narrow %w, "text"` | роль → роль; trap с текстом `text`, если исходное значение не делает `Other`; статически цель — сужение (её действия — подмножество действий источника) |
| `%r: int = call.role %w, Wallet.total()` | вызов слота; реализация получает исходный полный `self` |

Вызовы по конкретной ссылке всегда прямые: `call @Purse.total(%p)`.
Перегрузки по роли выбираются статически по типам аргументов, в OIR
остаётся только номер слота. Именованные аргументы ролей уже переупорядочены
фронтендом по сигнатуре роли.

Результат `call.role` имеет тип из сигнатуры роли: `^Package`, а не
`^Bottle`. Ограничение ссылки сохраняется автоматически: инструкций, которые
открыли бы поля или чужие actions через роль, нет.

`Error` и `NativeFailure` — системные номинальные декларации модуля
`okkama/core@1`, доступные без импорта: `role Error { text() -> str }`;
`NativeFailure` — объект рантайма с `domain/code/operation/message/text`.
`Cancelled` — системный Error для отменённых Future.

## 10. Generics

Generic-функции и generic-объекты имеют параметры типа:

```oir
func @Box.new<T>(%value: T) -> Box<T> [ctor Box<T>] { ... }
func @Box.get<T>(%self: Box<T>) -> T [method Box<T>] { ... }

%b: Box<int> = call @Box.new<int>(%seven)
```

- Каждый вызов generic-функции явно указывает аргументы типа. Вывод (§6.5
  спецификации: уравнения из аргументов, ожидаемый тип, bound) уже выполнен
  фронтендом. Противоречивые уравнения отвергаются при компиляции.
- Generics **реифицированы**: `Box<int>` и `Box<float>` — разные типы во всех
  наблюдаемых местах: глубокое равенство, `any`-box, отладочный вывод,
  совпадение catch.
- Внутри generic-кода параметр `T` — обычный статический тип. Над значением
  `T` разрешены только операции, допустимые для любого `T`: передача,
  хранение, `val.eq` (trap для запрещённых категорий), `any.box`,
  `region.adopt`, `role.wrap` через bound.
- Backend выбирает стратегию: мономорфизация (C, LLVM, VM) или передача
  дескрипторов типов (JVM, а также полиморфная рекурсия). Обе стратегии
  обязаны давать одинаковое наблюдаемое поведение. Проход `mono` (§20)
  выполняет мономорфизацию, а при её невозможности переводит параметры типа в
  явные параметры `type`.

Bound `T: Comparing<T>` проверяется при компиляции в каждой точке
инстанцирования, потому что аргументы типа статические.

Реализация `okkama-rs` мономорфизирует уже во фронтенде: generic-объект и
generic-роль — шаблоны, экземпляр (`Box<int>`) — обычный объект или роль OIR
со своим `ObjectId` и функциями (`@Box<int>.get`), создаётся один раз на
набор аргументов. Параметры типа в OIR поэтому не появляются. Вывод на месте
конструирования (`Box(value: 7)`): ожидаемый тип `let` (экземпляр шаблона или
роль, которую он делает), затем образцы параметров конструктора; `[]`/`[:]`
не свидетельствуют; конфликт и отсутствие свидетельства — ошибки компиляции с
текстами Perl (`cannot be both int and string`, `Cannot infer generic
parameter "T" for object "Box"`).

## 11. Замыкания и связанные actions

### 11.1 Анонимные actions

```oir
func @main.lambda#0[%factor: int](%value: int) -> int [lambda] {
^entry:
    %r: int = int.mul %value, %factor
    ret %r
}

%f: fn(int) -> int = fn.closure @main.lambda#0 [%factor]
%y: int = call.fn %f(%x)
```

- Захваты — снимок значений на момент `fn.closure`, по типам из
  `[...]`-списка функции-лямбды. Изменяемых захватов нет. Rebind внешней
  переменной после создания замыкания на него не влияет.
- Если лямбда использует `self`, `self` — обычный захват.
- Каждый вызов лямбды — отдельный кадр со своими регионами.
  `next`/`last`/`return` не пересекают границу лямбды.
- Типы функций точные: `fn(int) -> void` ≠ `fn(int) -> int`.

### 11.2 Связанные actions

`controller.response` без скобок:

```oir
%h: async fn(Request) -> Response = fn.bind %controller, @Controller.response
%h2: fn(int) -> int = fn.bind.role %w, Worker.apply()
```

Связанное значение удерживает receiver. Приватные actions связывать нельзя.

В `okkama-rs` `fn.bind %o, @m` записывается как `fn.closure @m [%o]`: action
объекта — функция, чей первый параметр (receiver) и есть захват. Лямбда —
функция с атрибутом `[lambda N of C]`: первые `N` параметров — захваты,
`C` — объект окружающего action (ей доступны его поля). JVM: класс на каждую
функцию `fn.closure`, `call(Object[])` в коллекционном представлении
значений.

## 12. Коллекции

### 12.1 Массивы

| Инструкция | Класс | Семантика |
|---|---|---|
| `%a: array<int> = array.new [%x, %y]` | чистая | литерал из уже вычисленных значений |
| `%n: int = array.len %a` | чистая | число элементов |
| `%v: T = array.get %a, %i` | trap | `%i: int` или `byte`; вне границ — программная ошибка |
| `array.lookup %a, %i, ^found(...), ^missing(...)` | терминатор | для `xs[i] else fallback`: `^found` получает элемент последним аргументом |
| `%s: array<T> = array.slice %a, %from, %to` | trap | end-exclusive, без clamp |
| `%t: array<T> = array.retag %e` | чистая | `%e: array<never>` → `array<T>` |
| `%s: str = array.join %a, %sep` | чистая | только `array<str>` |

### 12.2 Сборщики

Сборщик — линейное служебное значение: после использования его нельзя
использовать снова. Поэтому реализация может дописывать элементы на месте.
Линейность считается по путям: заголовок цикла `map` отдаёт свой параметр
`builder` и телу (`builder.push`), и выходу (`builder.finish`). Это два
использования в тексте, но на каждом пути — одно.

```oir
%b0: builder<int> = builder.new
%b1: builder<int> = builder.push %b0, %x
%b2: builder<int> = builder.append %b1, %other     // array<int>
%b3: builder<int> = builder.append.range %b2, %r    // только builder<int>
%a:  array<int>   = builder.finish %b3
```

Сборщики обслуживают `map`/`filter`, спред диапазонов в литералах, unpack в
`@T(...)`, `values...` и т. п. `mbuilder<K,V>` аналогичен: `mbuilder.new`,
`mbuilder.put %m, %k, %v`, `mbuilder.finish`. Сборщик не может пересечь
`await`, если только он не сохранён в кадре корутины проходом `coro`.

### 12.3 Map

| Инструкция | Класс | Семантика |
|---|---|---|
| `%m: map<str,int> = map.new [%k1: %v1, %k2: %v2]` | P | при повторе ключа побеждает последнее значение |
| `%n: int = map.len %m` | чистая | |
| `%b: bool = map.has %m, %k` | чистая | |
| `%v: V = map.get %m, %k` | trap | отсутствующий ключ — программная ошибка |
| `map.lookup %m, %k, ^found(...), ^missing(...)` | терминатор | `else` fallback |
| `%ks: array<K> = map.keys %m` | чистая | порядок ключей |
| `%vs: array<V> = map.values %m` | чистая | в порядке `keys` |
| `%k: K = map.key_at %m, %i` / `%v: V = map.value_at %m, %i` | trap | i-я пара в порядке ключей, для `for` |
| `%t: map<K,V> = map.retag %e` | чистая | из `map<never,never>` |

Ключи — `int`, `float`, `bool`, `char`, `str`, enum. У одного map все
ключи одного статического типа. `keys`, `values`, обход и сравнение идут в
естественном порядке этого типа:

| Тип ключа | Порядок |
|---|---|
| `int`, `byte`, `float` | по значению; `-0.0` и `0.0` — один ключ |
| `str` | по Unicode code points (совпадает с порядком байтов UTF-8) |
| `char` | по code point |
| `bool` | `false < true` |
| enum | порядок объявления case |

Обход словаря (`map`/`filter`/`reduce` с привязками `k, v`) lowering
выражает счётным циклом по массивам `map.keys` и `map.values`. Так обращение
к i-й паре стоит O(1) в любом backend; `map.key_at`/`map.value_at` остаются
для backend, у которых словарь индексируется напрямую. `filter` словаря
собирает результат в `mbuilder`, `map` — в `builder` массива. `for` по
словарю — ошибка (`For source must be an array or range`), как в Perl.
`[:]` получает тип на первой типизированной границе (`map.retag`), в том
числе когда другая ветвь `if` даёт типизированный словарь; то же для `[]` и
`array.retag`.

### 12.4 Диапазоны

`%r: range = range.new %a, %b, inclusive|exclusive` (trap при `a > b`;
операнды `int`; границу `byte` фронтенд принимает только после явного
`.int()`, R02). `range.start`, `range.end`
(эксклюзивная верхняя граница в int, с trap при переполнении `..=MAX`),
`range.len`. Обход диапазона — обычный int-цикл. В `okkama-rs` lowering проверяет
порядок явно (`cond` + `trap range`) перед `range.new`; `range.len` не
выпускается. JVM — `okkama.rt.Range`.

### 12.5 Строки и символы

`str.concat`, `str.len` (code points), `str.utf8` (строгий UTF-8 → `array<byte>`), `str.slice`, `str.split`,
`str.replace`, `str.replace_first`, `str.trim`, `str.chomp`, `str.eq`,
`str.ne`, `char.eq`, `char.ne`. Семантика полностью совпадает с §6.6.2
спецификации языка (пустой разделитель, границы code points, отсутствие
регулярных выражений).

### 12.6 Обход `Iterable<T>`

Отдельных opcode нет: `for` по объекту, делающему
`iteration::Iterable<T>`, — это `call.role … cursor()` один раз и цикл из
`available()`, `current()`, тела и `advanced()` (§19.4).

## 13. Async, Future, spawn

### 13.1 Корутины

Функция `[async]` с результатом `R`:

- `call` такой функции даёт **холодный** `future<R>` и не исполняет тело;
  receiver и аргументы удерживаются Future;
- `%v: R = await %fu` — точка приостановки (класс suspending). Первый
  `await` холодного Future запускает его, повторный возвращает кэшированный
  исход: значение, тот же Error или ту же отмену;
- `await` допустим только в функциях `[async]`;
- для `future<void>` пишется `await %fu` без результата;
- `await` Future типа `future<^C>` даёт `^C`.

Все SSA-значения, живые после `await`, переживают приостановку. Регионы,
сборщики и активные `failure` тоже. Фронтенд не делает никакой
«перепроигрыш» выражений: `await` внутри выражения — это обычная инструкция
в середине последовательности.

В `okkama-rs`: функция `[async]` хранит в `result` тип `R` тела; `call` и
слоты ролей дают `future<R>` (`Function::call_result`). JVM: метод тела
`name$body` и метод `name`, возвращающий `Future.cold(fn)` над аргументами;
`await` — `Scheduler.await`. Задачи — потоки, исполняется ровно одна
(передача управления), так что порядок совпадает с моделью обратных вызовов
Perl: запуск исполняет тело до первой приостановки, завершение сразу
продолжает ожидающих. `Cancelled` — объект `[builtin]` без полей.

### 13.2 Операции Future

| Инструкция | Okkama | Семантика |
|---|---|---|
| `fut.spawn %fu` | `spawn obj.async_action()` | запланировать немедленно; результат — тот же Future |
| `fut.cancel %fu` | `pending.cancel()` | идемпотентная кооперативная отмена |
| `%b: bool = fut.done %fu` | `done()` | наблюдение |
| `%b: bool = fut.cancelled %fu` | `cancelled()` | `true` только после unwind и defer |

Отмена задачи доставляется в её ближайшей точке приостановки как отказ
`thrown` с Error `Cancelled` на ребре unwind инструкции `await`. Внутри
cleanup-блоков фронтенд использует `await.shielded`: этот вариант откладывает
доставку отмены до конца cleanup (правило explicit return из
`okkama-llm-context-1.0.md` §15: «Cancellation requested during deferred
cleanup is delivered after that cleanup completes»).

### 13.3 Процессный spawn

```oir
%job: future<int> = proc.spawn @Worker.new#0(%seed), @Worker.calculate(%input)
```

Требует `requires process`. Аргументы конструктора и action уже вычислены
(конструктор раньше action). Верификатор проверяет **статически**, что типы
аргументов и результата transferable: `int`, `float`, `str`, `char`, `byte`,
`bool`, массивы и map из transferable. Worker загружает тот же граф модулей,
строит receiver и вызывает action по символам. Сбой worker приходит в
Future по правилам §18.1 спецификации.

В `okkama-rs` `proc.spawn` записывается через значение-функцию входа:

```oir
%entry: fn(int, int) -> int = fn.closure @Worker.calculate$worker#7 []
%job: future<int> = worker.spawn.direct %entry(%seed, %input)
```

`@…$worker#k` — сгенерированная функция `[lambda 0]`: параметры —
аргументы конструктора, затем action; тело конструирует receiver и вызывает
action. Bound action (`spawn action(x)`, std `parallel/map`) — `worker.spawn
%f(%x…)`, где `%f` создан `worker.bind %action, %entry, [%field…]` функцией
объекта `@…$bind#k`: вход воркера получает все поля receiver (по порядку
объявления) и восстанавливает его конструктором, принимающим ровно эти поля.
`worker.bind` выпускается только если программа запускает значения-action
в воркерах. Transferable проверяется при отправке (`spawn cannot transfer
value of type T`), как у Perl. JVM: воркер — дочерняя JVM той же программы
(`OKKAMA_SPAWN_WORKER`), вход находится по имени класса `fn`.

### 13.4 Каналы

`async/channel` (`Channel<T>`, `Sending<T>`, `Receiving<T>`) — обычные
объекты std, чьи actions объявлены `[intrinsic "okkama.channel.*"]` (§14.2).
Ни новых типов, ни opcode каналы не требуют.

### 13.5 Async main

`entry @main` с атрибутом `async`: launcher вызывает `@main`, получает Future
и крутит планировщик до исхода. Синхронный `main` планировщик не крутит.

## 14. Native ABI и intrinsics

### 14.1 Native

```oir
extern @time::wall_clock() -> int = "runtime/time@1::wall_clock/0"
extern @fs::open(array<byte>, int) -> FileHandle = "runtime/fs@1::open/2"
native object FileHandle
```

- `call.native @sym(%args)` — класс throwing: ожидаемый сбой provider
  приходит как `thrown` с `NativeFailure`.
- Типы ABI: скаляры, `str`, enum, массивы и map из них, `array<byte>`, `any`,
  native objects. Объекты, роли, замыкания и Future пересечь ABI не могут.
  Это проверяется статически.
- В `okkama-rs` native — функция без блоков с атрибутом
  `[extern "runtime/stdio@1::stdout_write/1"]` (канонический символ); вызов —
  обычный `call`. JVM backend передаёт её методу класса-provider модуля
  (`okkama.rt.Natives.runtime_stdio__stdout_write`,
  `okkama.rt.BigIntNatives.runtime_bigint__bigint_order`, …); неизвестный
  backend native — ошибка кодогенерации, а не исполнение.
- `NativeFailure` в `okkama-rs` — объект модуля с атрибутом `[builtin]`:
  поля `domain code operation message: str`, `does Error`, actions — чтения
  полей (`text` — `message`). `obj.new` для него запрещён: значения создаёт
  только рантайм; класс даёт backend (JVM — `okkama.rt.NativeFailure`).
- В `okkama-rs` native object — объявление модуля `native object H` и тип
  `H` (`Type::Handle`); `val.eq` над ним невыразим. JVM передаёт значение
  как `java.lang.Object` класса provider.
- Native objects нельзя создать, сравнить, положить в `any` или прочитать.
  Проверки generation, authority и use-after-close выполняет таблица handles
  рантайма.

### 14.2 Intrinsics

`[intrinsic "name"]` — функция без блоков, тело которой даёт рантайм.
Закрытый перечень OIR-1:

| Имя | Назначение |
|---|---|
| `okkama.channel.new`, `.send`, `.item`, `.close` | каналы `async/channel` |
| `okkama.future.*` | структурные Future std (`FutureGroup`, `Raced`, …), если std объявляет их intrinsic |
| `okkama.dump` | `okkama.Dump` |

Неизвестное имя intrinsic отвергается при загрузке. Расширение перечня —
изменение версии OIR.

В `okkama-rs` перечень — `ir::INTRINSICS`: действия и конструкторы объектов
std `async/*` (`okkama.channel.Sending.send`, `okkama.event.Event.wait`,
`okkama.atomic.Atomic.compare_and_replace`, …; конструктор —
`new` и имена параметров: `okkama.channel.Channel.new_capacity`). Атрибут
`[intrinsic "имя" Объекты…]` перечисляет объекты модуля, которые рантайм
создаёт (результаты, Error std), затем `helpers @f…` — функции программы,
которые рантайм вызывает (`limit.seconds()`, `clock.wait(…)` у
`async/timeout`): переходники `member.<имя>` над receiver. Async-действие
остаётся `[async]`: его вызов даёт `future<R>`. JVM: аргументы в
коллекционном представлении, состояние — в `Obj.intrinsic`, объекты
программы — через отражение. Тот же переходник с атрибутом `[lambda 1]` —
bound action ограниченной ссылки роли (`fn.closure @member.f [%r]`).

На рёбрах unwind и неявных рёбрах отказа параметр-successor `^C` принимает
значение `C` и наоборот: обязательство не наблюдаемо на пути отказа.

## 15. Тестовый профиль

Требует `requires test`. Production-загрузчик отвергает модуль с
тестовыми объявлениями, а не пропускает их.

```oir
test "open then close returns original" = @test#0

fake Package {
    field opened: bool = @Package.fake.default.opened
    does Package { open = @Package.fake.open, close = @Package.fake.close }
}
```

| Инструкция | Семантика |
|---|---|
| `%x: Package = fake.new Package` | `Package.fake()`; только в test mode |
| `fake.storage.set %k, %v` / `%v: T = fake.storage.get %k` / `has` / `remove` / `clear` / `size` | storage текущей fake-идентичности; только в функциях `[fake R]` |
| `test.ok %b`, `test.is %a, %b`, `test.isnt %a, %b`, `test.fail %msg` | контекстные assertions; trap вне активного теста |

`obj.next` над fake сохраняет identity storage. `test.is` над `any` — доверенная
граница, сравнивающая содержимое box.


В `okkama-rs` тестовый модуль — `Module::tests = Some([...])` (печать:
`requires test`, `test "имя" = @test#k`); тест — функция без результата
(`[async]` у `async test`). Fake — обычный объект `Role$fake`; утверждения и
хранилище fake — intrinsics `okkama.test.*` и `okkama.fake.storage.*`. JVM:
`main` вызывает `okkama.rt.Tests.run`.

## 16. Набор инструкций

Классы: **P** — чистая, не может отказать; **T** — trap: только программная
ошибка; **X** — throwing: любой вид отказа; **S** — suspending: точка
приостановки, любой вид отказа, включая отмену.

### 16.1 Константы и преобразования

| Инструкция | Класс | Примечание |
|---|---|---|
| `%x: int = const 42` | P | каноническое десятичное целое любой длины |
| `%x: float = const 2.5` / `const 1e-3` | P | конечный binary64, каноническая запись |
| `%x: rat = const 1/3` | P | нормализованная, знаменатель > 0 |
| `%x: byte = const 255` | P | 0..255 |
| `%x: bool = const true` | P | |
| `%x: char = const 'x'` | P | escapes OASM-1.0 §2.1 |
| `%x: str = const "text\n"` | P | |
| `%x: Status = enum.case Status.ready` | P | |
| `%y: T = cvt %x` | T/P | пара (тип `%x`, `T`) из таблицы ниже; результат задан аннотацией |

Допустимые `cvt` (§6.6.1 спецификации): `int→float` (T: ближайшее,
результат должен быть конечным), `float→int` (T: trunc, конечное),
`int→byte`, `float→byte`, `rat→byte` (T: trunc, затем 0..255), `byte→int`,
`byte→float`, `byte→rat`, `int→rat` (P), `float→rat` (P, каноническая
десятичная запись), `rat→int` (P, trunc), `rat→float` (T: результат
должен быть конечным), `int|byte|float|rat|bool→str` (P). Других `cvt` нет.

`float` в `okkama-rs`: `float.add sub mul div mod pow neg abs sqrt`,
`float.eq … ge`, `float.sign` (→ `int`), `cvt int|byte→float`,
`cvt float→int` (усечение, signed-64), `cvt float→str`, `byte.from` от
`float`. Константа хранится битами, печатается кратчайшим текстом
(`const 0.1`, `const -0`). Текст значения — правило Go
`FormatFloat(x, 'g', -1, 64)` (D-032).

`rat` в `okkama-rs`: `rat.new %n, %d` (два `int`, нормализация, `d == 0` —
trap `Division by zero`) — это и `int.div`, и `rat(n, d)`; деление двух
`byte` — `cvt byte→int` обоих операндов, затем `rat.new`. Далее
`rat.add sub mul div mod neg abs`, `rat.eq … ge`, `rat.sign` (→ `int`),
`rat.numerator`/`rat.denominator` (→ `str`), `cvt` в обе стороны с
`int`/`float`, `cvt byte→rat`, `cvt rat→str` (`n/d`, у целого — `n`),
`byte.from` от `rat`. Константы `rat` lowering не порождает: литерал
`1 / 3` — это `rat.new` от двух `int`-констант. JVM: класс `okkama.rt.Rat`
(`BigInteger` числитель и знаменатель).

`%v: T = undef` — произвольное значение типа `T`: заглушка поля конструктора
на пути, где оно не связано. Читать его можно только под признаком
связывания; конец конструктора проверяет признаки
(`trap unbound "Object \"Q\" field \"v\" was not initialized"`).

Variadic-хвост `...T` внутри действия — `array<T>`; место вызова собирает
его `array.new` (или сборщиком при финальной распаковке `xs...`).

`int→byte` записывается отдельной инструкцией `%b: byte = byte.from %x` или
`byte.from %x, "@byte() argument 3"`. Значение вне 0..255 — программная
ошибка `Cannot convert int value N to byte: expected 0..255`; необязательная
строка — префикс диагностики (`@byte() argument 3: …`), как у Perl. Литерал в
0..255 (`byte(200)`) lowering сразу превращает в `const 200: byte`.

### 16.2 Арифметика

| Семейство | Инструкции | Класс |
|---|---|---|
| `int.` | `add sub mul neg` (точные, переполнения нет) | P |
| `int.` | `mod` — остаток усечённого деления со знаком делимого (как `%` Go, решение D-031: `-7 % 3 == -1`, `7 % -3 == 1`); делитель 0 — trap | T |
| `int.` | `div` → результат `rat` (0 — trap); в `okkama-rs` — `rat.new` | T |
| `int.` | `and or xor not shl shr ushr rotl rotr bit_count leading_zeros trailing_zeros reverse_bits swap_bytes`: слово signed-64; операнд вне signed-64 — trap; счётчик сдвига и поворота `int` в 0..63, иначе trap | T |
| `byte.` | те же битовые операции над словом 8 бит; счётчик в 0..7 | T |
| `float.` | `add sub mul div mod neg` (`mod` — знак делителя; неконечный результат или делитель 0 — trap) | T |
| `rat.` | `add sub mul div mod neg` (`mod` — знак делителя; делитель 0 — trap) | T |
| `rat.` | `numerator denominator` → `str` | P |

Арифметика над двумя `byte` в Okkama даёт `int` или `rat`: фронтенд вставляет
`cvt byte→int` (`+ - * %`, унарный `-`). Смешение `byte` с `int` (`b + 1`,
`b < 9`, индекс `xs[b]`) — ошибка компиляции: нужен явный `b.int()` (R02). Битовые `& | ^ ~`
остаются в `byte` только для двух `byte` (`byte.and`, `byte.not`, …); сдвиг
`byte` — на счётчик `int` в 0..7 (`byte.shl %b, %n`). Смешение `byte` и `int`
в битовой операции и счётчик сдвига не `int` — ошибки компиляции. Битовые
действия печатаются с семейством операнда: `%n: int = byte.bit_count %b`,
`%r: int = int.rotl %x, %k`; счётчики (`bit_count`, `leading_zeros`,
`trailing_zeros`) дают `int`, остальные — слово того же типа. Арифметика
`float` — только двух `float`. Разные числовые категории (`int`, `byte`,
`float`, `rat`) в одной операции без явного каста — ошибка компиляции (R02):
`1.5 + float(1)`, а не `1.5 + 1`; неявных `cvt` фронтенд не вставляет.

### 16.3 Сравнения

| Инструкция | Класс | Семантика |
|---|---|---|
| `int.eq ne lt le gt ge`, то же для `byte.`, `float.`, `rat.` | P | одинаковые типы операндов |
| `bool.eq ne`, `enum.eq ne` | P | |
| `char.eq ne lt le gt ge`, `str.eq ne lt le gt ge` | P | упорядочивание — по code points (как порядок ключей §12.3); операторов `<` над `str`/`char` в языке нет, его даёт `order()` роли `Comparing` |
| `%b: bool = val.eq %a, %b` / `val.ne` | T | глубокое типизированное равенство одинаковых статических типов |
| `%b: bool = bool.not %a` | P | |

Сравнение разных категорий (`1 == 1.0`) и упорядочивание разных числовых
категорий (`1 < 2.5`, `b < 9`, `1 < rat`) без явного каста — ошибки компиляции. В
OIR такие инструкции невыразимы.

`val.eq` (§8.4 спецификации, порядок детерминирован):

- массивы — длина, затем элементы по индексу; map — размер, множество ключей,
  затем значения в порядке ключей (§12.3); range — `start`, `end`, `inclusive`;
- объекты — один конкретный тип, затем поля **в порядке объявления**;
  ссылки ролей сравниваются по исходным значениям;
- `fn` и `future` — по identity; runtime capabilities (Channel, Lock, …) —
  по identity внутреннего состояния;
- первое найденное различие даёт `false`, дальше сравнение не идёт;
- встреча `any`, native handle или cap до первого различия — trap.

`&&` и `||` — короткое замыкание через `cond`.

### 16.4 Вызовы

| Инструкция | Класс |
|---|---|
| `%r: R = call @f<Targs>(%a…)` | X |

## 17. Верификатор

Модуль проверяется до исполнения или генерации кода. Ошибка верификации —
ошибка инструмента, а не программы.

**Структура.** Известные версия, уровень, `requires`. Уникальность символов.
Существование всех ссылок. Нет циклов импорта. Генерик-арность точная.
Каждый блок заканчивается ровно одним терминатором. Нет недостижимых блоков
без `unreachable`.

**Типы.** Аннотация каждого определения совпадает с правилом инструкции.
Аргументы ветвлений совпадают с параметрами целей. Цель unwind имеет
последним параметром `failure`. Служебные типы не попадают в запрещённые
позиции.

**SSA.** Однократное определение. Доминирование использований. Значения,
доступные в цели unwind, доминируют над началом блока-источника.

**Авторитет.** `obj.get`, `obj.new`, `obj.next`, `fake.storage.*` и
вызовы `private`-функций разрешены только из функций своего владельца
(§5.1). `await` — только в `async`. `test.*` и `fake.new` — только при
`requires test`.

**Объявления.** `obj.new` перечисляет все поля один раз. Таблицы `does` полны
и сигнатуры точны. Bounds выполнены в каждой точке инстанцирования.
Transferable-типы в `proc.spawn` и ABI-типы в `extern`.

**Регионы.** Стек открытых регионов однозначен в каждой точке. Закрывается
только верхний регион. Перед `ret` и при распространении отказа из функции
открытых регионов нет. После `region.leave` и `region.unwind` регион не
используется.

**Линейность.** Ни одно использование `builder`/`mbuilder` не достижимо из
другого своего использования (или из самого себя по циклу), пока путь не
прошёл через определение значения. Рёбра одного терминатора взаимоисключающие:
передача в обе цели `cond` — одно использование. Аргумент unwind конфликтует с
любым другим использованием в том же блоке, ведь отказ после дописывания на
месте увидел бы изменённый сборщик. Сборщик не пересекает `await` в high.

**Must-use.** На каждом нормальном пути значение `^C` погашено ровно одним
`succ.take`, `ret` или сохранением в `future<^C>` (§8.4).

### 19.3 Области, defer, try

Область Okkama с defer-выражениями `D1…Dn` (в порядке регистрации) и
регионом `%r` порождает:

- **Тело** разбито на блоки по точкам регистрации defer: блок после
  регистрации `Dk` имеет цель unwind `^fail_k`. Так defer, до которого
  исполнение не дошло, не выполняется на пути отказа.
- **Нормальный выход** (конец области, `return`, `next`, `last`, выход
  значения выражения): блоки `^ok_k(…payload)` для k = n…1 исполняют `Dk` с
  unwind на `^okfail_k`, затем `^ok_leave`: `region.leave %r [keep payload]`
  и переход к продолжению. Если выходов несколько, фронтенд либо дублирует
  цепочку, либо передаёт номер продолжения параметром и завершает её
  `switch.int`. Обе формы эквивалентны.
- **Отказ в теле** `^fail_k(%f)`: исполняет `Dk…D1`; отказ `Dj` даёт
  `fail.secondary %f, %g`; затем `region.unwind %r, %f` и переход к цели unwind
  охватывающей области (или `raise`).
- **Отказ в defer на нормальном пути** `^okfail_k(%g)`: `%g` становится
  основным, исполняются оставшиеся `D(k-1)…D1` по схеме пути отказа.
- Defer-выражение читает **текущие** SSA-значения привязок в точке выхода:
  это даёт позднее чтение и учёт rebind без ячеек.
- Отказ defer или destroy на выходе `next`/`last` поднимается, как и на
  любом другом выходе. Perl-интерпретатор такой отказ теряет и продолжает
  цикл; это его ошибка, OIR ей не следует.

Реализация `okkama-rs`: регион получает каждая блочная область и корень
функции, если в модуле есть `destroy` (иначе все типы plain и регионов нет).
Цели отказа `F_k` занимают один слот области в стеке целей unwind (тот же
механизм, что у `try`): изменяемые переменные, видимые при регистрации
`D_k`, передаются аргументами. Проверка дисциплины стека регионов в
верификаторе пока не реализована; блоки только с чистыми инструкциями тоже
получают цель unwind, и её убирает будущий проход low.
- `return` внутри defer — обычный переход, заменяющий pending return. Он не
  может обойти уже активный отказ, потому что на пути отказа такого перехода
  нет.

`try { B } catch e is T1 { C1 } catch e is T2 { C2 }`:

0. Переменные, которые `B` или тела catch перепривязывают (rebind, поля
   конструктора, staged-поля), передаются в dispatch аргументами unwind.
   Аргументы unwind определены до начала блока, поэтому присваивание такой
   переменной внутри `B` начинает новый блок: его цель unwind получает новое
   значение. Dispatch и handlers видят значение на момент отказа; если на
   входе в `try` значение было `^C`, параметр имеет тип `^C` и обязательство
   сохраняется (catch анализируется от состояния входа в try, §11.1).
1. Тело `B` — отдельная область с регионом `%rt`. Её отказ проходит cleanup
   `B` и `region.unwind %rt`. Error-payload освобождается, потому что
   достижим из `%f`. Отказ `region.leave %rt` (destroy при нормальном
   завершении `B`) тоже идёт в `^dispatch`, то есть его ловят catch этого
   же `try`.
2. `^dispatch(%f)`: `catch %f is T1, ^c1(%f), ^d2(%f)`;
   `^d2`: `catch %f is T2, ^c2(%f), ^outer(%f)`.
3. `^ck(%h: failure, %e: Tk)`: открывает регион handler, `region.adopt` для
   `%e`, исполняет `Ck`. Его отказы идут через `fail.caused %g, %h`. Bare
   `throw;` — это `raise %h`.
4. Нормальные результаты `B` и `Ck` сходятся параметром блока слияния, если
   `try` — выражение.
5. Нормальное завершение, `return`, `next`, `last` проходят мимо catch.

### 19.4 Циклы

- `for array` — int-индекс, `array.len`, `array.get`; `for range` — int от
  `range.start` до `range.end`; `for map` — индекс и `map.key_at`/`value_at`;
  `for Iterable` — `%cur = call.role %src, Iterable.cursor()` один раз, затем
  `available` → `current` → тело → `advanced`. При `next` курсор
  продвигается, при `last` и при отказе тела — нет.
- Каждая итерация — своя область (регион итерации, если нужен).
- Переменные, которые тело перепривязывает, становятся параметрами
  заголовка цикла.
- `loop { … last v; }` — результат `v` идёт параметром блока выхода. Хвост
  тела `loop` отбрасывается. Bare `last` в `for` сохраняет накопленное
  значение.
- `map`/`filter`/`reduce` — тот же цикл. Результат блока идёт в `builder.push`
  или в параметр-аккумулятор. Выходной тип элемента уже выведен фронтендом.
- `for` в позиции значения (`okkama-rs`) — тот же цикл с состоянием
  `[ran: bool, last: T]` (`last` — `undef` до первой итерации). Тело даёт
  `[true, v]`, `next` передаёт состояние входа итерации, `last v` — выход со
  значением. Исчерпание проверяет `ran`: `false` — `trap empty "A void result
  cannot be used as a value"`.
- Массив или скаляр на границе стандартной роли (`okkama-rs`) — объект-адаптер
  (`core::ArraySequence<S, T>`, `core::ArrayCursor<S, T>`,
  `core::ScalarOrder<T>`, `core::ByteArraySource`): `call` его конструктора,
  затем `role.wrap`. Конструктор и actions адаптера lowering строит прямо в
  OIR (`obj.get`, `array.get`, `array.lookup`, `trap empty`).

## 20. Профиль low и проходы

Low — то, что получают простые backend. Нормативные проходы high → low
выполняются в этом порядке:

1. **`succ-erase`** — `^C` → `C`, `succ.take` удаляется.
2. **`mono`** — мономорфизация generic-функций и типов по всем статически
   достижимым инстанцированиям. Если множество бесконечно (полиморфная
   рекурсия), оставшиеся параметры типа становятся явными параметрами
   `%T: type`, а `type.of<T>` даёт дескриптор. Переход к дескрипторам
   разрешён и для любого подмножества функций (например, ради размера кода).
3. **`plain-elide`** — удаление `region.adopt`/`keep` над plain-значениями и
   регионов, которые никогда ничем не владеют.
4. **`coro`** — каждая `async`-функция превращается в:
   - тип кадра `frame<@f>` с полями для значений, живых через `await`, для
     открытых регионов и номера состояния;
   - функцию запуска `@f`: `frame.alloc`, сохранить аргументы, вернуть
     `future` через runtime-вызов `rt.future.new(frame, @f.resume)`;
   - функцию возобновления `@f.resume(%fr: frame<@f>) -> void`:
     `switch.int` по номеру состояния, восстановление значений `frame.load`,
     сохранение перед каждой точкой приостановки `frame.store`,
     `call.resume`/`rt.await` с возвратом управления планировщику.
   Unwind-рёбра `await` становятся обычными рёбрами отказа функции resume.
   После прохода в модуле нет `async` и `await`.

Low добавляет только `type`, `type.of`, `frame<>`, `frame.alloc/load/store`,
`cell<T>` (изменяемая ячейка, нужна только `coro`) и runtime-вызовы
планировщика. Всё остальное в low — те же инструкции high.

## 21. Трансляция в backend

### 21.1 Регистровая VM (OASM)

- Out-of-SSA: каждое значение получает виртуальный регистр. Параметры блоков
  становятся параллельными копиями на рёбрах (разрыв критических рёбер,
  временный регистр для циклов копий). Распределение регистров по интервалам
  жизни необязательно.
- Цель unwind блока — запись таблицы исключений
  `(начало_блока, конец_блока) → handler` с регистром для `failure`.
  Классы инструкций говорят интерпретатору, где проверять отказ.
- Регионы, `obj.*`, `val.eq`, коллекции — opcode VM или runtime helpers один
  к одному.
- Async можно исполнять напрямую (кадр VM в куче) или после `coro`.
- OIR-0 структурно — частный случай: `const`/`add.int`/`ret` =
  `const`/`int.add`/`ret` одного блока без регионов. Семантика `int` в OIR-0
  другая (checked signed-64).

### 21.0 Представление `int` во всех backend

`int` — bigint с быстрым путём (допустимо и чистое представление bignum:
текущий JVM backend использует `java.math.BigInteger` для всех значений `int`).
Малое значение хранится как i64. Если
результат `add`/`sub`/`mul`/`neg` выходит за i64, он переходит в
heap-bignum, а при уменьшении нормализуется обратно в i64. Пример: C — tagged
`okk_int` (i64 или указатель на limbs), LLVM — то же через
`llvm.*.with.overflow` и вызов `okk_int_*_slow`, JVM — `long` с переходом на
`java.math.BigInteger` в классе `OkkInt`. Ни один backend не имеет права
обрезать или оборачивать значение.

### 21.2 C11

```c
/* func @Purse.total(%self: Purse) -> int */
okk_fail *app_Purse_total(okk_ctx *cx, okk_int *out, const app_Purse *self) {
    okk_int m = okk_int_mul(cx, self->digit, OKK_INT_SMALL(100)); /* i64 или bignum */
    *out = okk_int_add(cx, m, self->cents);
    return NULL;                       /* точная арифметика int не отказывает */
}

/* trap-инструкция, например array.get */
if (i_out_of_bounds) { f = okk_trap(cx, OKK_BOUNDS, LOC(0, 31, 9)); goto unwind_body; }
```

- Функция возвращает `okk_fail*` (NULL — успех), результат пишет через
  out-параметр. Каждой инструкции классов T/X/S соответствует проверка
  `if (f) goto unwind_label;`.
- Значения — локальные переменные C, блоки — метки, параметры блоков —
  присваивания перед `goto`.
- Объект — `struct` с заголовком `{ const okk_desc *desc; okk_owner owner; }`
  и полями в порядке объявления. Роль — `struct { void *obj; const R_witness *w; }`.
  Замыкание — `{ fnptr, env* }`. Enum — `uint32_t` + статический дескриптор.
- Память: граф объектов ациклический (§4), поэтому подсчёт ссылок корректен
  без сборки циклов, кроме изменяемых ячеек рантайма (каналы, fake storage,
  native memory), которые нужно разбирать отдельно или явно. Допустим и
  трассирующий GC.
- Generics — после `mono`; async — после `coro` (кадр — `struct`, resume —
  `switch`).

### 21.3 LLVM

- SSA переносится напрямую, параметры блоков становятся `phi`.
- Рекомендуемая модель отказа — та же, что в C (возврат `ptr` failure): она
  детерминирована и не зависит от unwinder платформы. `invoke`/`landingpad`
  допустимы, если сохраняется §6.2.
- Быстрый путь `int` — `llvm.sadd/ssub/smul.with.overflow.i64`, при
  переполнении — переход в bignum (§21.0).
- Async — `coro` (§20) либо `llvm.coro.*` в режиме switched-resume. Семантика
  должна совпадать с `coro`.
- `range`, `str`, `rat`, коллекции и регионы — вызовы runtime-библиотеки
  `libokkama-rt`.

### 21.4 JVM

- Функция — `static`-метод. `float`→`D`, `bool`→`Z`, `byte`/`char`→`I`,
  `int`→`OkkInt` (§21.0; допустимо специализировать в `J` там, где проход
  анализа диапазонов доказал, что значение помещается в i64), остальное —
  ссылки на классы runtime (`OkkStr`, `OkkRat`, `OkkArray`, …).
- Объект — `final class` с `final`-полями, `obj.new` — конструктор,
  принимающий все поля.
- Роль — пара (объект, witness) в общем случае. Если ни один объект не делает
  разные применения одной generic-роли, можно взять `interface` +
  `invokeinterface`.
- Отказ — `OkkFailure extends RuntimeException` без stack trace. Цель
  unwind блока — запись exception table на диапазон байткода блока. Правило
  доступности значений §6.2 совпадает с требованием StackMapTable: кадр
  handler равен кадру начала блока.
- Быстрый путь `int` — `Math.addExact`/`multiplyExact`. При
  `ArithmeticException` вычисление переходит на `BigInteger`, а не
  становится отказом.
- Блоки параметров и явные типы делают StackMapTable вычислимой без анализа
  типов байткода.
- Реализация `okkama-rs` сейчас: `int` — всегда `java.math.BigInteger`;
  массив и сборщик — `java.util.List` (`ArrayList`, элементы `bool` —
  `Boolean`); роль — `interface`, системная роль `Error` — `okkama.rt.Error`;
  отказ — `okkama.rt.Failure`. Проверки и операции с текстами диагностики
  Perl (`%`, битовые слова, индексы и срезы, строки по code points) живут в
  Java-рантайме `okkama.rt.Rt`. Его class-файлы (Java 8) встроены в
  компилятор и выдаются рядом с программой в `okkama/rt/`. `val.eq` —
  `Objects.equals`: у классов объектов есть `equals`/`hashCode` по полям в
  порядке объявления. Словарь и `mbuilder` — `java.util.Map` (`TreeMap` с
  компаратором `okkama.rt.KeyOrder`: `int` по значению, `bool` — `false <
  true`, `str` — по code points, а не по UTF-16). `byte` и `char` — JVM `int`
  (`I`: 0..255 и code point), в коллекциях — `Byte` и `Integer`, чтобы
  порядок ключей и диагностика их различали. Значение enum — синглтон
  `okkama.rt.Case` (номер и имя case) в `static final` поле класса
  `<Главный>$<Enum>`; `enum.eq` сравнивает номера, порядок ключей словаря —
  номер case.
- Generics — дескрипторы `OkkType` (стратегия «дескрипторы» прохода `mono`)
  или мономорфизация. Async — `coro` (кадр — объект, resume — метод).

## 22. Полный пример

Исходник:

```okkama
module app v1.0.0;

object InvalidCents does Error {
    has cents is int;
    InvalidCents(:cents);
    text() is string { "invalid cents"; }
}

object Purse {
    has digit is int;
    has cents is int = 0;

    Purse(digit is int, cents is int) {
        digit = digit;
        cents = cents;
        confirm self.cents >= 0 && self.cents < 100
            else throw InvalidCents(cents: self.cents);
    }

    total() is int { digit * 100 + cents; }
    spend() is ^Purse { ^cents = 0; }
    destroy { digit; }
}

main() is int {
    let purse = Purse(digit: 7, cents: 65);
    defer purse.total();
    let spent = purse.spend();
    return spent.total() - 700;
}
```

OIR-1 high:

```oir
oir 1 high
module app v1.0.0
requires core
file 0 "app.ok"
entry @main

object InvalidCents {
    field cents: int
    does Error { text = @InvalidCents.text }
}

object Purse {
    field digit: int
    field cents: int = @Purse.default.cents
    destroy @Purse.destroy
}

func @InvalidCents.new(%cents: int) -> InvalidCents [ctor InvalidCents] {
^entry:
    %e: InvalidCents = obj.new InvalidCents { cents: %cents }
    ret %e
}

func @InvalidCents.text(%self: InvalidCents) -> str [method InvalidCents] {
^entry:
    %s: str = const "invalid cents"
    ret %s
}

func @Purse.default.cents() -> int [default Purse.cents] {
^entry:
    %z: int = const 0
    ret %z
}

func @Purse.new(%digit: int, %cents: int) -> Purse [ctor Purse] {
^entry:
    %unused: int = call @Purse.default.cents()    // defaults раньше тела
    %zero: int = const 0
    %ge: bool = int.ge %cents, %zero               // self.cents = текущее SSA-значение
    cond %ge, ^upper, ^invalid
^upper:
    %hundred: int = const 100
    %lt: bool = int.lt %cents, %hundred
    cond %lt, ^valid, ^invalid
^invalid:
    %err: InvalidCents = call @InvalidCents.new(%cents)
    throw %err
^valid:
    %p: Purse = obj.new Purse { digit: %digit, cents: %cents }
    ret %p
}

func @Purse.total(%self: Purse) -> int [method Purse] {
^entry:
    %d: int = obj.get %self, digit
    %k: int = const 100
    %m: int = int.mul %d, %k
    %c: int = obj.get %self, cents
    %t: int = int.add %m, %c
    ret %t
}

func @Purse.spend(%self: Purse) -> ^Purse [successor Purse] {
^entry:
    %z: int = const 0
    %n: Purse = obj.next %self { cents: %z }
    ret %n
}

func @Purse.destroy(%self: Purse) -> void [destroy Purse] {
^entry:
    %d: int = obj.get %self, digit                 // хвост вычисляется и отбрасывается
    ret
}

func @main() -> int [entry] {
^entry:
    %r0: region = region.enter
    %seven: int = const 7
    %c65: int = const 65
    br ^before_defer
^before_defer unwind ^fail_0:
    %purse: Purse = call @Purse.new(%seven, %c65)
    region.adopt %r0, %purse
    br ^after_defer                                // `defer purse.total()` зарегистрирован
^after_defer unwind ^fail_1:
    %s: ^Purse = call @Purse.spend(%purse)
    %spent: Purse = succ.take %s                   // `let spent` потребляет successor
    region.adopt %r0, %spent
    %t: int = call @Purse.total(%spent)
    %c700: int = const 700
    %res: int = int.sub %t, %c700
    br ^ok_1(%res)                                 // return: значение до cleanup

// нормальный выход: D1, затем destroy
^ok_1(%v: int) unwind ^okfail_1:
    %d1: int = call @Purse.total(%purse)           // позднее чтение `purse`
    br ^ok_leave(%v)
^ok_leave(%v2: int):
    region.leave %r0                               // destroy spent, затем purse
    ret %v2

// отказ после регистрации D1
^fail_1(%f: failure) unwind ^fail_1_d1(%f):
    %d2: int = call @Purse.total(%purse)
    br ^fail_0(%f)
^fail_1_d1(%f1: failure, %g: failure):
    %fg: failure = fail.secondary %f1, %g
    br ^fail_0(%fg)
// отказ D1 на нормальном пути становится основным
^okfail_1(%g2: failure):
    br ^fail_0(%g2)
// общий хвост пути отказа
^fail_0(%f0: failure):
    %fu: failure = region.unwind %r0, %f0
    raise %fu
}
```

Что видно на примере:

- defer не выполняется, если `Purse.new` упал: `^before_defer` уходит в
  `^fail_0`, где D1 нет;
- `%purse` доступен в `^fail_1`, потому что определён в блоке, доминирующем
  над `^after_defer`;
- `region.leave` стоит в блоке без unwind: его отказ уходит из функции, а
  регион к этому моменту уже закрыт;
- порядок «defer → destroy (LIFO: `spent`, затем `purse`)» явный.

C для `@main` получается механически: метки на блоки, `goto` на рёбра,
`if (f) goto …` после каждой инструкции T/X.

## 23. Принятые решения и расхождения с Perl

Perl-интерпретатор — эталон и не меняется. Решения ниже фиксируют поведение
OIR и Rust-реализации там, где спецификация языка молчит или где поведение
Perl случайно. Расхождения с Perl отмечаются в
`tools/differential/known-divergences.json` и в
`okkama-rs/docs/compatibility.md`, а не исправляются в Perl.

| ID | Решение OIR / Rust | Perl | Где в документе |
|---|---|---|---|
| R01 | `int` — точный bigint | нативные числа: диапазон −2^63…2^64−1, вне него ошибка «cannot be represented exactly» | §3.1, §16.2, §21.0 |
| R02 | Разные числовые категории взаимодействуют только после явного каста: арифметика, упорядочивание, индекс, границы диапазона | разрешает (расширяет `byte`→`int`, `int`→`float`, целые→`rat`) — дефект Perl-версии | §12.4, §16.2, §16.3 |
| R03 | Временные значения принадлежат блоку, если их не принял вызванный (параметры и receiver действия); значение ветви `if`/`match`/`try` переходит во внешний блок; несвязанное выражение не удаляется | так же | §7 |
| R04 | Отказ destroy try-области ловится catch этого же `try` | — | §19.3 |
| R05 | Повтор ключа в литерале map: последнее значение побеждает | так же | §12.3 |
| R06 | Порядок ключей map — естественный порядок типа ключа | сортирует строковое представление (`-3,10,100,9`; enum по имени) | §12.3 |
| R07 | Отмена — `thrown Cancelled`, ловится в самой задаче | так же | §13.2 |
| R08 | Гетерогенный литерал — `array<any>` / `map<K,any>` с неявным `any.box` | — | §3.1 |
| R09 | Default поля вызывается всегда, до тела, даже если конструктор связывает поле | так же | §8.2 |
| R10 | `val.eq`: поля в порядке объявления, значения map в порядке ключей, первое различие — `false` | порядок Perl-хэша, исход между запусками случаен (`false` или ошибка `any`) | §16.3 |

Значения, при которых Rust и Perl совпадают: `int` в −2^63…2^63−1, map без
наблюдения порядка ключей, равенство без `any`/handles в полях. Для
conformance это означает, что кейсы R01, R02, R06 и R10 получают ожидания
Rust-реализации с пометкой расхождения.

Расхождения OASM-1.0 с действующей Okkama, которые OIR-1 не наследует:
`fixup` (в языке его нет), запрет отмены Future (в языке есть
`Future.cancel()`), запрет `async -> void` (в языке поддержан), отсутствие
битовых операций, caps, каналов, `<-` и async bound actions, а также
runtime-выбор overload и конструктора (в OIR он статический).

## 24. План внедрения в okkama-rs

Каждый шаг — один вертикальный слой: структуры `ir`, lowering, печать
текста, верификатор, JVM backend и тесты. Следующий шаг начинается только
после зелёного предыдущего.

| Шаг | Содержание | Конструкции Okkama |
|---|---|---|
| 0 | Перевести `ir::Module` на модель §5: типизированные значения с аннотацией, `Block { params, unwind, insts, term }`, `Terminator::{Ret, Br, Cond}`; текстовый принтер §18 | текущий int `+` |
| 1 | Скаляры `int bool`, все int-операции §16.2–16.3 с классами T/P, `let`, `if`/`else`, `&&`/`\|\|`, параметры блоков | арифметика, условия |
| 2 | `loop`/`last v`/`next`, rebind через параметры блоков | циклы |
| 3 | Объекты: `object`, `obj.new/get/next`, `call`, `ret`, `succ.take`, верификатор must-use | конструкторы, actions, successors |
| 4 | Модель отказов: `unwind`, `throw/panic/trap/raise`, `catch`, `fail.*` | `confirm`, `try` |
| 5 | Регионы, `destroy`, `defer` (§19.3) | ownership |
| 6 | `str`, `float`, `byte`, `rat`, `char`, `cvt` | все скаляры |
| 7 | Массивы, map, range, builders, `for`, функциональные блоки | коллекции |
| 8 | Роли, `role.wrap/narrow`, `call.role`, enum, `switch.enum`, `match` | роли |

`match` в `okkama-rs` сейчас — цепочка `cond`. Субъект вычисляется один
раз. Образцы одного `case` проверяются слева направо и лениво: короткое
замыкание собирает результат в параметр `bool` блока слияния. Сравнение — тот
же `==`, что в выражениях (`int.eq`, `str.eq`, `enum.eq`, `val.eq`, …). Если
образцы-константы покрывают все case enum (или оба `bool`) и `else` нет,
последний `case` исполняется без проверки. `switch.enum` остаётся для прохода,
который соберёт такие цепочки в переход по номеру case.
| 9 | Generics + проход `mono` | generics |
| 10 | Замыкания, `fn.bind`, caps, `any` | анонимные actions |
| 11 | `async`, `await`, Future, проход `coro`; затем `proc.spawn`, каналы | async |
| 12 | `extern`, native objects, тестовый профиль | stdlib, тесты |

Шаг 0 почти механический: текущие `InstructionKind::IntConst/IntAdd`
становятся `const`/`int.add` с аннотацией `: int`, `BasicBlock` получает
пустые `params` и `unwind: None`, `Terminator::Return` печатается как
`ret`. JVM backend и тесты `tests/lowering.rs`, `tests/codegen.rs` меняют
только ожидаемый текст листинга.

Шаг 1 также переводит `int` на bigint (R01): `IntConst(i64)` хранит
произвольное целое, `LoweringError::IntegerOutOfRange` для литералов
исчезает, а JVM backend заменяет `Math.addExact`-trap на представление
`OkkInt` из §21.0.
