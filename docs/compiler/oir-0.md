# OIR-0: типизированная регистровая машина

Статус: первый профиль работает от исходника до кода завершения процесса.
Реализованы компилятор, верификатор, исполнитель, launcher и текстовый OASM-0.
Бинарный формат ещё не реализован.
Возможности добавляются по одной: RED → код → GREEN.

## 1. Единая модель

OIR — внутренние данные программы. OASM — планируемое текстовое представление
той же модели, а не второй промежуточный язык.

```text
AST → Compiler->build → Module → Verifier → VM
                         ├→ OASM
                         └→ будущие backend
```

Сейчас работает весь путь AST → Module → Verifier → VM. `OASM-1.0.md` остаётся архитектурным
проектом: его противоречия действующей Okkama ещё требуют правок. Прототип
`okkama-pl/compiler-draft/oifr-perl-vm` не исполняет этот формат.

Результат компиляции содержит только данные: сигнатуры, типы, константы,
инструкции. В нём нет AST-узлов, Perl callbacks или объектов runtime.
Кадры вызовов, изменяемые регистры и native implementations принадлежат VM.

## 2. Поддерживаемый исходный код

```okkama
module app v1.0.0;
main() is int { return 42; }
```

Неявный возврат `main() is int { 42; }` компилируется точно так же.

Профиль поддерживает один синхронный `main() is int` без параметров. Тело
содержит непустую последовательность `let` и безусловных выражений, а также
необязательный явный `return` последним оператором. Без него возвращается
значение последнего оператора, включая `let`.
Выражение — целочисленный литерал, ранее объявленное имя или дерево сложений `+`;
допускаются группирующие скобки и непосредственный унарный минус перед литералом.
Этот минус сворачивается в константу. Другие арифметические операции пока
не поддержаны; точный контракт сложения описан в разделе 9.

Поддержаны принятые парсером десятичные, двоичные и шестнадцатеричные литералы,
включая разделители `_`. `00042`, `4_2`, `0x2A`, `0b10_1010` нормализуются в
десятичную строку `'42'`; `-0` нормализуется в `'0'`.

Константы ограничены signed-64: `-9223372036854775808..9223372036854775807`.
Это ограничение профиля компилятора, а не новое правило переполнения арифметики
всего языка. Проверка использует точную запись из токена AST, не потенциально
округлённое число Perl.

## 3. Каноническая Perl-структура

Публичный интерфейс: `my $ir = Okkama::Compiler->build($ast);`.
Для приведённой программы результат строго такой:

```perl
{
    format_version => 0,
    entry          => 0,
    functions => [{
        name       => 'main',
        parameters => [],
        result     => 'int',
        registers  => ['int'],
        constants  => [
            ['int', '42'],
        ],
        code => [
            ['const', 0, 0],
            ['ret',   0],
        ],
    }],
}
```

- `format_version` — версия структуры, сейчас `0`.
- `entry` — индекс функции в `functions`, сейчас `0`.
- `name`, `parameters`, `result` — сигнатура; сейчас только `main() is int`.
- `registers->[n]` — постоянный тип регистра `rn`; длина задаёт размер окна.
- `constants->[n]` — тип и точная каноническая запись константы `kn`.
- `code->[pc]` — инструкция; адреса и индексы начинаются с нуля.

`['int', '42']` описывает целое, а не строку Okkama. Строковая запись числа
сохраняет точность при дампе и переносе между реализациями. Каждый `build`
возвращает независимую структуру и не меняет AST.

## 4. Контракт инструкций

| Инструкция | Семантика исполнителя |
|---|---|
| `['const', A, K]` | Загрузить `constants[K]` в регистр `A`, затем увеличить PC. Тип должен совпадать с объявленным типом регистра. |
| `['add.int', A, B, C]` | Сложить два `int` из `B` и `C` с проверкой signed-64 переполнения, записать новый `int` в `A`, затем увеличить PC. |
| `['ret', A]` | Вернуть одно значение регистра `A` из текущего вызова согласно его сигнатуре. |

Операнды имеют фиксированные роли: в `const` первый индекс обозначает регистр,
второй — константу. Дополнительные теги внутри инструкции не нужны. Мнемоники
регистрозависимы и пишутся строчными буквами.

Регистры изменяемые, но сохраняют объявленные типы. При входе они не
инициализированы; чтение до записи запрещено. Каждый вызов получает своё окно
регистров. Перезапись регистра не разрешает мутировать объекты Okkama.

`ret` не вызывает системный `exit`. Запускающий код получает результат
точки входа, проверяет настоящий `int` и диапазон `0..255`, затем устанавливает
статус процесса. Значение не печатается и не усекается до восьми бит.
Поэтому компилятор принимает `return 256;` и `return -1;`: они представимы
в IR, но launcher отвергает такой результат `main`.

Читаемый листинг тела:

```asm
const r0, k0
ret   r0
```

Полная текстовая грамматика с сигнатурой, типами регистров и константами
реализована и описана в [OASM-0](oasm-0.md). Её заголовок — `.oasm 0`;
версия `1.0` из большого архитектурного проекта пока не поддерживается.

## 5. Граница профиля и ошибки

`build` проверяет всю поддерживаемую форму до выдачи результата. Пока не
поддержаны импорты и объединённые модули, дополнительные декларации, async,
projections, вложенные области, перепривязка, условия, арифметика кроме целочисленного `+`, вызовы,
коллекции и cleanup.
Отвергаются также пустое тело, `return` без значения, условный postfix и любое
тело с операторами после `return`. Локальные объявления поддержаны только
с выводимым типом `int` или явным `is int`, см. раздел 10.

Это ограничения компилятора первого шага. Программа с `defer` может быть
правильной Okkama, но этот профиль не должен молча удалять её очистку.
Формы, не принимаемые парсером, до компилятора вообще не доходят.

Ошибки имеют префикс `OIR-0 compilation error:` и причину отказа.
Компиляция не запускает программу, не загружает её импорты и не использует
AST-интерпретатор для вычисления результата.

## 6. Верификатор и исполнитель

```perl
use Okkama::Compiler::OIR::Verifier;
use Okkama::Compiler::OIR::VM;
use Okkama::Compiler::OIR::Launcher;

Okkama::Compiler::OIR::Verifier->verify($ir); # 1 или исключение
my $result = Okkama::Compiler::OIR::VM->run($ir);
# { type => 'int', value => Math::BigInt->new('42') }
my $status = Okkama::Compiler::OIR::Launcher->run($ir); # отдельное исполнение
```

`verify` не меняет Module. Проверяются обязательные и неизвестные поля, версия,
entry, единственная функция `main() is int`, все типы регистров и все константы
(включая неиспользуемые), форма каждой инструкции, точное число операндов,
границы индексов и инициализация читаемых регистров. Запрещены неизвестные opcode,
отсутствующий `ret` и любой код после `ret`. Ошибка начинается с
`OIR-0 verification error:`. Первый профиль принимает только тип `int`.

Индексы имеют каноническую неотрицательную десятичную запись. Текстовое значение
константы должно быть каноническим десятичным целым в signed-64: без ведущего
плюса, лишних нулей, разделителей, пробелов и `-0`. Это требования к IR;
компилятор предварительно нормализует разрешённые исходные литералы.

`VM->run` всегда сначала вызывает верификатор. Предыдущий успешный `verify` не
позволяет запустить изменённый некорректный модуль. Для каждого исполнения
создаются свежие регистры и PC. `const` создаёт типизированное runtime-значение
с точным `Math::BigInt`; `add.int` вычисляет новую сумму без изменения операндов;
`ret` возвращает значение. VM не читает AST и не вызывает
существующий AST-интерпретатор. Runtime-значения не хранятся в Module.

`Math::BigInt` — представление целого в эталонном Perl-исполнителе, а не новый
тип языка. Оно исключает зависимость точности от разрядности чисел хоста.
Результат не связан изменяемой ссылкой с таблицей констант или другим запуском.

`Launcher->run` исполняет Module, проверяет диапазон `main` и возвращает обычное
целое `0..255`. Сам launcher не завершает процесс и ничего не печатает.
Обёртка `bin/okkama-ir` завершает процесс этим статусом. Ошибка компиляции,
верификации или результата даёт статус `1` и сообщение в stderr; неправильные
аргументы запуска и ошибка открытия входного файла дают статус `2`.

## 7. Проверка и примеры

Из каталога `okkama-pl`, с Perl 5.42 в PATH:

```sh
prove -lv t/compiler
perl examples/compiler/constant-return.pl
perl examples/compiler/constant-return.pl --run
perl bin/okkama-ir examples/compiler/answer.ok
perl bin/okkama-ir --emit-oasm examples/compiler/answer.ok > /tmp/answer.oasm
perl bin/okkama-ir /tmp/answer.oasm
perl bin/okkama-ir examples/compiler/addition.ok
perl bin/okkama-ir examples/compiler/addition.oasm
perl bin/okkama-ir examples/compiler/locals.ok
perl bin/okkama-ir examples/compiler/locals.oasm
```

`constant-return.pl` по умолчанию печатает структуру через `Data::Dumper`;
с `--run` исполняет тот же IR и возвращает статус из исходника внутри примера.
`answer.ok` возвращает статус `42` без вывода в stdout. Ненулевой статус этого
примера ожидаем: он демонстрирует точную передачу результата `main`.
`addition.ok` и `addition.oasm` вычисляют `40 + 2` и также завершаются со
статусом `42`, без вывода. Они показывают уже арифметическое исполнение.
`locals.ok` показывает именованные значения и явный тип локальной переменной;
`locals.oasm` — соответствующий код с поясняющими комментариями. Оба возвращают
`42`. Имена переменных в исполняемый Module не входят.

`okkama-ir` — отдельный экспериментальный runner первого профиля. Основной
`bin/okkama` продолжает работать как прежде. Неподдерживаемые конструкции
никогда не переключают новый runner на AST-интерпретатор.

`--emit-oasm` выдаёт проверенный текст в stdout и завершает процесс с `0`, не
исполняя `main`. Файлы `.oasm` читаются как assembly; флаг также может
нормализовать их. `Text->write($ir)` и `Text->read($text, source_name => $name)`
дают тот же round-trip из Perl. Reader обязательно вызывает верификатор,
передавая карту исходных строк отдельно от Module.

Тесты сначала были запущены без `build` и завершились RED. После реализации
проверяют явный/неявный возврат, основания и нормализацию литералов, границы
signed-64, запрет неподдерживаемых форм, сериализуемость и независимость сборок.
Тесты VM и launcher также добавлены до реализации. Они проверяют ошибочные
модули, перезапись регистров, независимость запусков, точность целых и реальный
статус дочернего процесса с отдельной проверкой stdout/stderr.
Тесты текстового формата и CLI написаны до реализации: проверяются точный
канонический вывод, round-trip, крайние целые, грамматика, порядок деклараций,
неверные инструкции, расположение ошибок и исполнение загруженного OASM.

## 9. Контракт первого арифметического шага: add.int

`['add.int', A, B, C]` читает два инициализированных регистра `B` и `C` типа
`int`, вычисляет точную сумму, проверяет signed-64 диапазон и записывает новый
`int` в регистр `A`. Все три регистра объявлены и находятся в границах окна.
Чтение обоих операндов предшествует записи, поэтому `A == B`, `A == C`, `B == C`
и совпадение всех трёх индексов разрешены. Запись не изменяет исходные значения
в других регистрах и не мутирует константы Module.

Переполнение в любую сторону — `OIR-0 execution error`, выполнение прекращается
до записи результата. Нет wraparound, насыщения, перехода к float или расширения
языкового `int` до bigint. Math::BigInt используется только для точного расчёта.
Верификатор проверяет типы и инициализацию, а диапазон вычисляемой суммы — VM.

Это явный контракт нового IR-профиля. Старый AST-интерпретатор не меняется:
на проверенном Perl он допускает `9223372036854775807 + 1`, а результат
`-9223372036854775808 + -1` отвергает как непредставимый точно. Эти края нельзя
считать совместимыми между backend до отдельного решения для всего языка.

Компилятор поддерживает деревья целочисленного `+` и группирующие
скобки. Операнды вычисляются слева направо; каждая сумма проверяется отдельно.
`(MAX + 1) + -1` падает на первой сумме, `MAX + (1 + -1)` допустим.
Дерево не сворачивается в одну константу. Для каждой загрузки и каждой суммы
выделяется свежий регистр; одинаковые литералы пока не объединяются.

Для `return 40 + 2;` контракт кода:

```perl
registers => ['int', 'int', 'int'],
constants => [['int', '40'], ['int', '2']],
code => [
    ['const', 0, 0],
    ['const', 1, 1],
    ['add.int', 2, 0, 1],
    ['ret', 2],
],
```

Смешанные типы, конкатенация строк, остальные арифметические операции и унарное
отрицание вычисляемого выражения пока не поддержаны. Минус непосредственно перед
целочисленным литералом сохраняет прежнее поведение.

Перед объектами необходим контракт завершения кадров: возврат, исключения,
`defer`, `destroy`, передача владения; затем будут successors и async.
Бинарный ABI, JVM, LLVM и JIT не входят в первый профиль.

## 10. Локальные переменные первого профиля

Поддерживаются `let name = expression;` и `let name is int = expression;`
в единственной области тела `main`. Инициализатор — любое поддерживаемое
целочисленное выражение: литерал, ранее объявленное имя, скобки или `+`.
Имя появляется после компиляции инициализатора; чтение до объявления и
самоссылка без предшествующего объявления — ошибки. Имена регистрозависимы,
включая допустимые в исходном языке имена из заглавных букв.

Повторное объявление в той же области запрещено. Таблица имён создаётся заново
при каждом `build`, не попадает в Module и не переносится между программами.
Неявный результат — значение последнего оператора, включая последний `let`,
как в AST-интерпретаторе. Явный `return` по-прежнему допускается только последним:
код после него этот профиль отвергает, а не молча отбрасывает.

`let` связывает имя с регистром результата инициализатора. Чтение имени
использует этот регистр без `move` или новой инструкции. Например,
`let copy = original;` не вычисляет инициализатор `original` повторно и не
создаёт новый регистр. Компилятор выделяет свежие регистры для загрузок и сумм,
поэтому последующие вычисления не перезаписывают значения связанных имён.

```okkama
main() is int {
    let left = 40;
    let right is int = 2;
    return left + right;
}
```

Код совпадает с непосредственным `return 40 + 2;`: две `const`, одна `add.int`,
одна `ret`. Неиспользуемые инициализаторы и предшествующие выражения сохраняются
в порядке исходника: например, переполнение неиспользуемой суммы остаётся
ошибкой исполнения.

Вложенные области, затенение, перепривязка `name = expression;`, типы кроме
`int`, условия и cleanup в этот шаг не входят. Это ограничение компилятора,
не изменение соответствующих возможностей языка. Неизвестные имена и неверные
объявления диагностируются при компиляции.
