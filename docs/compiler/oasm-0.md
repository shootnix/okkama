# OASM-0: текстовое представление первого исполняемого профиля

Этот контракт задаёт текст для Module из [OIR-0](oir-0.md). Это ограниченный
профиль версии `0`, а не реализация большого проекта `OASM-1.0.md`.
Текст содержит все данные Module; исходные `.ok` и AST для исполнения не нужны.

## 1. Полный пример

```asm
.oasm 0
.entry main
.function main() -> int
.reg r0 int
.const k0 int 42
.code
    const r0, k0
    ret r0
.end
```

Заголовок задаёт `format_version => 0`, `.entry main` — `entry => 0`.
Единственная функция имеет имя `main`, пустые `parameters`, результат `int`.
`.reg` перечисляют `registers`, `.const` — `constants`, инструкции — `code`.
Директивы, пустые строки и комментарии не занимают адресов инструкций.

Локальные `let` в исходном коде не требуют отдельной инструкции OASM:
компилятор связывает имена с регистрами. Например, `let left = 40;` загружает
константу, а `let copy = left;` использует тот же регистр без повторной загрузки.
`let sum = left + right;` связывает имя с регистром результата `add.int`.
Текст сохраняет исполняемые данные, но не имена исходных локальных переменных;
для пояснений в ручном листинге можно использовать комментарии после `;`.

## 2. Порядок и грамматика

Строго по порядку: `.oasm 0`, `.entry main`, `.function main() -> int`,
ноль или больше `.reg`, ноль или больше `.const`, `.code`, инструкции, `.end`.
После `.end` допускаются только пустые строки и комментарии.

```text
register    = "r", index
constant    = "k", index
index       = "0" | nonzero-digit, { digit }
integer     = "0" | [ "-" ], nonzero-digit, { digit }
reg-decl    = ".reg", WS, register, WS, "int"
const-decl  = ".const", WS, constant, WS, "int", WS, integer
load        = "const", WS, register, [ HSPACE ], ",", [ HSPACE ], constant
return      = "ret", WS, register
add         = "add.int", WS, register, [ HSPACE ], ",", [ HSPACE ], register,
              [ HSPACE ], ",", [ HSPACE ], register
```

`WS` — один или больше ASCII-пробелов/табуляций, `HSPACE` — любое их количество.
В сигнатуре допускаются пробелы/табуляции вокруг `(`, `)`, `->`.
Имена, типы и инструкции регистрозависимы. Номера регистров и констант начинаются
с `0`, идут подряд без дыр и повторов. После первой `.const` нельзя объявлять
регистры, после `.code` нельзя объявлять регистры или константы.

Одна директива/инструкция на строку. Начальные и конечные пробелы/табуляции
незначимы. `;` начинает комментарий до конца строки; отдельные комментарии
и комментарии после инструкций допустимы. Поддержаны LF и CRLF, последняя
строка может не иметь перевода строки. Другие управляющие символы не разделители.

Константы — только канонические десятичные signed-64; `+42`, `042`, `-0`,
`4_2`, `0x2a`, дроби и экспоненты не принимаются в OASM. Компилятор нормализует
такие разрешённые исходные записи до текстового вывода. Константы всегда
читаются как точные десятичные строки, без преобразования через float.

`add.int rA, rB, rC` вычисляет точную сумму двух `int` и проверяет signed-64
диапазон до записи результата. Оба источника должны быть инициализированы;
совпадение любых регистров разрешено. Переполнение — ошибка исполнения, а не
чтения текста. Полный контракт и отличия от AST-интерпретатора — в разделе 9
[OIR-0](oir-0.md). Пример:

```asm
.oasm 0
.entry main
.function main() -> int
.reg r0 int
.reg r1 int
.reg r2 int
.const k0 int 40
.const k1 int 2
.code
    const r0, k0
    const r1, k1
    add.int r2, r0, r1
    ret r2
.end
```

Версия `0` остаётся развиваемым профилем: старый reader, не знающий `add.int`,
должен отвергнуть инструкцию, а не игнорировать её или заменить другим действием.

## 3. API и проверка

```perl
use Okkama::Compiler::OIR::Text;
my $text = Okkama::Compiler::OIR::Text->write($ir);
my $copy = Okkama::Compiler::OIR::Text->read($text, source_name => 'answer.oasm');
```

`write` сначала проверяет Module существующим верификатором. Затем выдаёт
канонический текст: без комментариев и пустых строк, LF, четыре пробела перед
инструкциями, одна завершающая новая строка. Исходный Module не меняется.
`read(write($ir))` восстанавливает эквивалентный Module, включая неиспользуемые
регистры/константы и повторные записи. `write(read(text))` нормализует текст.

`read` отвергает неправильную грамматику и затем обязательно вызывает тот же
верификатор, что и VM. Ограничения типов, диапазонов, индексов, инициализации и
возврата не определяются второй раз в reader. В диагностике есть имя источника
и номер физической строки (с единицы, включая комментарии/пустые строки).
Карта строк передаётся верификатору отдельно и не добавляет полей в Module.
Для отсутствующей обязательной строки ошибка указывает EOF, для отсутствующего
`ret` — строку `.end`. Текст никогда не исполняется как Perl.

## 4. Командная строка

Из `okkama-pl`, Perl 5.42:

```sh
perl bin/okkama-ir --emit-oasm examples/compiler/answer.ok > /tmp/answer.oasm
perl bin/okkama-ir /tmp/answer.oasm
```

Файл с расширением `.oasm` читается как OASM-0; остальные файлы — как Okkama.
`--emit-oasm` проверяет и печатает канонический OASM вместо исполнения,
завершаясь с `0`. Для `.oasm` этот флаг выполняет нормализацию.
Обычный запуск возвращает статус `main`, не печатая значение.
Неподдерживаемая версия или ошибка текста даёт статус `1`, сообщение в stderr
и отсутствие вывода в stdout. Ошибки аргументов/открытия файла дают статус `2`.
