# Чтение SQL: строки и границы материализации

`RowReading` выдаёт `Row` по одному вызову `await rows.row()`. `RowsEnded`
обозначает конец; ошибки значений сохраняют свой тип. Закрывайте rows и соединение
в своих областях владения, используйте `RowReader` для строгих int/text/flag.

В текущем исследовательском PG-адаптере ответ bridge целиком буферизуется в JSON,
а типизированные значения и Row создаются при чтении конкретной строки. Поэтому
чтение первой строки с последующим close не создаёт остальные типизированные Row.
Ошибка поздней строки возникает при её чтении; неверная строка не пропускается.
Bridge и адаптер сохраняют максимум1024 строки и отдельные лимиты транспорта;
превышение даёт resource/ROW_LIMIT. Финансовый загрузчик отдельно ограничен256
строками и получает заголовок/строки одним SELECT.

Это отложенное декодирование внутри буферизованного ответа. Точная область
измерений и реальные проверки находятся в
IMP-15 и
профиле.
