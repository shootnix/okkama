# Okkama trust model

State of 0.4.1. This document says which input Okkama handles safely, where
each boundary stands today, and which open issues move it. "Safe" means that
untrusted input does not corrupt memory or abort the process, and that a
failure of the program comes back as a structured error. Limits on time,
memory and host access are a separate question, answered for every boundary.
Update this document in the same change that closes or opens a boundary issue.

## In short: how to run untrusted input today

| Input | Today |
|---|---|
| Okkama source | check and compile in your process (`okkama check`, `okkama build`); every compiler phase is bounded, see §1 |
| Bytecode `.spb` | verified before it runs, compiled under a memory bound (§2); a separate process with OS limits remains the safest way to run untrusted bytecode |
| A program | on the Sparrow core under budgets (`--max-steps`, `--max-memory`, `--max-output`, `--timeout`); in a sandbox when it must not reach files, network or processes (§3) |
| Embedding `sparrow-core` | `run_limited` with `Limits`: budgets and the native groups the program may use (§5) |

## 1. Source

**Guaranteed.**
- The lexer terminates on any text; the parser bounds its recursion and the
  tree (depth 128, 2²⁰ nodes); trees are freed without recursion.
- The import graph is walked with an explicit stack and bounded: 1024 nested
  imports, 16 384 modules, 256 MiB of module sources; a deeper chain is a
  diagnostic ([#20]).
- Generic specialization is bounded: a request chain deeper than 256 or more
  than 262 144 specializations is a diagnostic with the chain ([#32]).
- Name conflicts are diagnostics naming both sources, and `check` output does
  not depend on the order of files or of hash maps ([#33]).
- Register allocation of generated bytecode is checked by an independent
  analysis in debug builds and in the release gate ([#30]); IR passes can be
  switched off and are compared in the gate ([#29]).
- Coverage-guided fuzzing of the lexer, parser, analysis, OIR verifier, SPB
  decoder and execution runs nightly ([#34]).

**Not guaranteed.** Compile time of very large functions ([#50]); analysis
types have no depth limit yet ([#49]).

## 2. Bytecode `.spb` on the Sparrow core

The core picks every register's machine representation from the declared
types, so the verifier is a memory-safety boundary.

**Guaranteed.**
- Decoding is bounded: files up to 256 MiB, every count charged at its element
  size against 512 MiB before allocation, canonical LEB128; any truncation is
  an error with a byte position ([#24]).
- The verifier checks structure and types: operands and results of every
  instruction, calls, edges, handlers, role slots, caps, `destroy`, the entry,
  natives against the ABI ([#16]); its analysis is bounded per function
  (64 MiB, [#24]).
- Intrinsic contracts are checked at load (`sparrow check` runs them too).
- Machine frames are bounded (256 KiB) inside a stack headroom checked in
  every prologue; recursion through `destroy` and closures ends in a
  `Stack overflow` failure ([#25]).
- Runtime helpers called from machine code have signatures checked at compile
  time ([#23]); exceptional edges keep the values their handlers read, also
  under a stressed collector ([#22]).

- Compiling a function is bounded: the core estimates its cost (registers
  live at each instruction × the blocks it emits) while generating it and
  refuses a function above 256 MiB, or above the run's memory budget, before
  the expensive phases run ([#73]).

**Not guaranteed.**
- Generic intrinsic payloads are checked by representation, not by exact type
  ([#69]).

**Use today.** Verify with `sparrow check`; run untrusted bytecode in a
separate process with an OS memory limit.

## 3. Programs

**Guaranteed.**
- On every engine (the core, IR and the JVM), `--max-steps`, `--max-memory`,
  `--max-output` and `--timeout` stop a runaway program with its own report,
  which `catch` cannot intercept; without them nothing changes and nothing is
  spent ([#21], [#71], [#237]). Steps are counted alike on all three.
- Value graphs of the IR engine are freed without recursion ([#28]).
- A cancelled SQLite query never reaches a closed connection ([#18]); X.509
  path search is bounded ([#17]).
- Private RSA operations (key generation, PSS and PKCS#1 v1.5 signing, OAEP
  decryption) run in aws-lc, constant-time and blinded, on every Rust engine
  ([#70]).

**Not guaranteed.**
- On the JVM the memory budget is the Java heap and the thread stacks, not
  the whole process ([#237]).
- A single native operation (a long BigInt division, a sort) finishes before a
  budget stops the run; the memory budget measures the whole process ([#72]).
- From the CLI a program has the host access of the user running it: files,
  network, processes, environment.

**Use today.** Budgets on any engine; a container or OS sandbox for host
access.

## 4. Packages

`blade` checks package names as module paths, installs `pkg/` and
`blade.lock` as one transaction ([#39]); dependencies are audited against
RustSec in CI ([#19]); packages are published only after the release gate
passed on the same commit ([#26]).

## 5. Embedding `sparrow-core`

**Guaranteed.**
- `run_limited` takes `budget::Limits`: budgets, an interrupt flag the host
  may set from any thread, and `natives`, the native groups (`Fs`, `Net`,
  `Process`, `Env`, `Clock`, `Random`, `Terminal`) the program may use; a
  native outside them fails the program, process workers need `Process`
  ([#31]).
- A panic inside a native provider stops the run with an internal error, and
  that runtime refuses further runs; a fresh runtime works ([#31]).
- A memory budget needs a probe: `budget::set_memory_probe` (the CLIs read
  mimalloc; `budget::Counted` is a counting allocator for others).

**Not guaranteed.**
- A panic in another runtime helper aborts the process at the `extern "C"`
  boundary rather than unwinding through machine code ([#23]).
- Host state (environment defaults, working directory) is per thread, not per
  runtime ([#40]).
- `run_worker` is the CLIs' worker entry, not an embedding API.
