# Internal HPACK tables and header blocks

`http/internal/hpack_tables` holds octet-string HpackField(name,value[,sensitive]), the complete ordered RFC 61-entry static table, and immutable HpackDynamicTable(capacity). Dynamic capacity is locally bounded 0..1 MiB; size accounting is uncompressed name/value octets plus 32 per entry. New entries are newest-first, duplicates are valid, oldest entries are evicted on growth/shrink, and an oversized entry clears the table. Combined indices 1..61 address static fields, 62 onward dynamic; zero/missing indices are connection COMPRESSION_ERROR (9). Compression accepts opaque names/values, including pseudo-fields; HTTP validity belongs above it. Strings use one Latin-1 scalar per octet.

`http/internal/hpack::HpackDecoder([effective_limit])` returns immutable successor contexts through decoded(bytes,HpackBudget). Result fields preserve exact order/duplicates and never-indexed metadata; result.context() must be retained for the next block. It implements indexed fields, all literal representations, raw/Huffman strings and leading dynamic-size updates. Nonconformant/later/oversized size updates fail with compression error. At most two leading updates are accepted, following the conformant encoder profile in [RFC 7541 section 4.2](https://www.rfc-editor.org/rfc/rfc7541.html#section-4.2). A reduction through allowed(maximum) remembers the smallest effective limit across later increases, requiring an adequate leading eviction update. Apply allowed() only at the protocol's outgoing-SETTINGS acknowledgment point. Initial HTTP2 compression contexts start at 4096; a lower constructor limit represents an already effective lower advertisement, not permission to bypass ACK ordering.

HpackBudget(encoded,decoded,fields) defaults 65536/65536/128, with maxima 1 MiB/1 MiB/1024; zero permits empty blocks. Decoded accounting charges every emitted field, including indexed repeats, and includes per-field 32-byte overhead. Encoded bytes are checked before parse; decoded/count overflow aborts the connection with ENHANCE_YOUR_CALM (11). Strings have separate 1 MiB primitive bounds and are materialized before the completed field's cumulative budget charge; transient string memory is not claimed to equal the smaller field-list budget. A failed block yields no reusable context: caller must abort the connection, not continue with the old table and risk desynchronization.

HpackEncoded(Sequencing<HpackField>,budget) is a conservative stateless encoder: static exact/name references and raw literal strings; it adds no outgoing dynamic entries and does not attempt Huffman encoding. It forces Authorization, Proxy-Authorization, Cookie and Set-Cookie to never-indexed, and preserves explicit sensitivity of any field through re-encoding. Sensitive fields never use an indexed exact representation. Ordinary unknown fields use without-indexing literals. Sequence count is checked before item/cursor access; each used item is observed once and processing stops at first budget overflow. Output is a bounded in-memory block, so no transport prefix escapes an encoding failure. Live connection output must also signal any required table-size update; the HEADERS writer explicitly selects zero capacity.
