# Explicit localized collation

`locale/collation` represents an original string together with an explicit locale
and immutable policy. `CollatedString(text,locale,options)` computes its derived
key once; `string()` preserves the original text. `order(other)` implements
Comparing<CollatedString> by unsigned lexicographic key order. Builtin string
equality and ordering retain their original locale-independent semantics.

CollationOptions(strength,case_first,numeric,normalization) has these enums:

- CollationStrength: primary, secondary, tertiary, quaternary, identical.
- CollationCaseFirst: locale_default, lower, upper.

Strength controls the UCA comparison levels. Case-first affects applicable case
levels. Numeric mode orders decimal digit runs by numeric value; ICU's limit of
254 consecutive decimal digits is enforced instead of silently splitting a run.
Normalization enables ICU's canonical normalization handling. Disabling it uses
ICU's documented input assumptions; it does not promise canonical inequality.
Explicit options override the corresponding ICU settings; Unicode locale `co`
selects an available tailoring, such as de-u-co-phonebk. Other extension keywords
do not override these options. Unsupported or empty `co` fails explicitly.

The backend is **ICU 76.1 / Unicode and UCA 16.0.0 / CLDR 46.0**. This is the CLDR
collation snapshot shipped with that ICU release, distinct from the 46.1.0 data
used by other locale modules. All four runtime version coordinates are checked.
No process locale or environment language is read. ICU resolves the explicitly
supplied base locale through its pinned fallback data to root, never the host
default locale. Full normalized locale identity still participates in compatibility.

Run `sh tools/build-icu-collation.sh` to download the checksum-verified official
release and build under `.runtime/icu-76.1`. The generated directory is
ignored by Git. Darwin and Linux builds are supported; this delivery does not
claim a Windows build. FFI::Platypus is needed by this optional backend. A custom
installation can supply `OKKAMA_ICU_LIBDIR`; the version checks remain mandatory.
Function handles bind the selected backend on first successful use. Missing or
wrong versions throw UnavailableCollation; there is no host-version fallback.

Keys are opaque ephemeral bytes, including the ICU terminator. Do not persist
them or use them as string identities. Both operands must have exactly the same
locale, strength, case-first, numeric flag, normalization flag and data version.
Otherwise order() throws IncompatibleCollation. `key()` permits repeated sorting
inside that same domain; raw byte sequences cannot carry this compatibility check.

Text is limited to 8,192 Unicode scalars and keys to 262,144 bytes. Invalid text,
unsupported tailorings and exceeded input/key budgets throw InvalidCollation.
Each native call owns one collator and closes it on success and failure; pointers
never enter the language. Registry failures return the portable NativeFailure
wire value, which the represented value maps into the documented error types.

Focused tests: native/75-native-collation.t and 690_std_collated_strings.t.
The native oracle compares generated byte keys against ICU's separate direct
UTF-8 comparison API for 400 pairs across locales, strengths and numeric policies.
It also verifies cleanup, wrong UCA, missing backend, bounds and registry failures.
Language checks exercise original text, phonebook, incompatibility and ordinary
string ordering. [Runnable example](../../examples/std-v4/localized-collation.ok).

Upstream contracts: [ICU 76 release](https://unicode-org.github.io/icu/download/76.html),
[collation guide](https://unicode-org.github.io/icu/userguide/collation/),
[API and keys](https://unicode-org.github.io/icu/userguide/collation/api.html).
