# Owned HTTP2 session

`Http2Session(input,output,owner,local,peer,limits)` adopts one already selected H2 transport after successful client preface. It never guesses ALPN or upgrades HTTP1. local is the advertised Http2Settings, peer the applied initial Http2PeerSettings, limits HttpLimits. Construction performs no wire I/O. exchange(request) lazily starts one consuming reader and bounded connection writer, returns Http2Exchange with immutable request/response and up to sixteen informational Response values. Body openings remain explicit and one-shot; pseudo-fields/HPACK/frame types are absent from the result.

The session allocates monotone odd uint31 IDs, caps active stream/body owners at 100 and pending admission at 256, waits FIFO for current peer concurrent-stream credit (including zero), and wakes admission after SETTINGS/lease release. Outgoing headers and DATA use the verified connection writer/scheduler. Source length versus Content-Length is checked before head output when known; actual body bytes/EOF/maximum are checked while sending. Body readers are opened once and closed on completion/error/cancellation. Whole header blocks are indivisible; a physical-start hook distinguishes queued cancellation from reset of an actually opened stream.

Each stream's native incoming buffer is retained directly by a supervised holding task, while registries/ready observations only borrow it. This protects reverse-order and ready-but-unclaimed responses across async scopes. Final headers configure expected length before DATA can arrive. Informational responses, final response, optional terminating trailers, body length and both half-close directions remain separate. A malformed response resets only its stream after shared HPACK state advances. Stream cancellation closes its producer/body, drains its supervised work and queues RST without cancelling the connection writer or siblings.

GOAWAY stops admission, preserves eligible lower-ID streams and reports Http2Unprocessed(stream) for streams above the cutoff; queued requests have stream zero. No implicit retry is performed. RST after a complete response preserves its received body, including NO_ERROR early request abort. CONNECT success is rejected pending dedicated tunnel ownership. Push remains disabled. Header byte/count budgets apply to input HPACK, individual fields to line_bytes, and outbound field-list budget also respects an advertised peer maximum.

close() stops admission and requests I/O cancellation; disposal drains those tasks before closing the explicit transport owner. settled() on a running session waits for registered shutdown/disposal and transport/producer cleanup. Fully received buffered bodies remain available after physical close; their holding tasks retain at most the bounded receive storage until application EOF/close/drop. Clean EOF releases storage and slot once; repeated empty reads remain valid. Unfinished bodies retain the closing failure. External client/opening decorators supply connection/header/body-idle/SETTINGS deadlines; this session does not invent clocks or timeout policy.

`examples/std-v4/http2-session.ok` verifies two typed POST exchanges, reverse response order, body leases, PING and exact WINDOW_UPDATE over actual TCP using explicit cleartext prior knowledge. 497 six memory/lifecycle cases and 498 three actual CLI assertions PASS; final compatibility nine files / 79 assertions, full regression 699 files / 12455 assertions PASS with unchanged source inventory. Session construction initially needed an explicit native holding lifetime and original task-failure observation; no Atomic resource-ownership shortcut was used. Parser/runtime cancellation races discovered here have separate direct tests and require the full interpreter regression gate. The explicit H2 public-client profile, verified TLS opening and shared pool are described in [http2-client.md](http2-client.md); mixed negotiation is verified separately, while retry and remaining HTTP features stay open.
