# Internal HTTP2 flow accounting

`http/internal/http2_flow` implements immutable Http2FlowWindow(scope,stream,remaining), Http2SendCredit(connection,stream), Http2DataPayload(frame), Http2WindowIncrement(frame) and Http2WindowFrame(stream,amount). These are connection collaborators, not public flow/frame API or an async scheduler.

A window retains signed remaining credit within -2147483647..2147483647. Connection scope requires stream zero; stream scope a positive uint31 ID. available() saturates negative credit to zero. sent(length) returns a successor or Http2NoCredit, allowing the owner to wait rather than turn local lack of credit into a peer fault. received(length) debits valid bytes or raises FLOW_CONTROL_ERROR (3) with the window's scope. credited(increment) accepts positive uint31 increments and rejects overflow with the same scope. adjusted(delta) applies a SETTINGS_INITIAL_WINDOW_SIZE difference to stream windows only; negative credit is retained, while overflow is a connection FLOW_CONTROL_ERROR. The connection window cannot be changed by this setting. These rules follow [RFC 9113 section 6.9](https://www.rfc-editor.org/rfc/rfc9113.html#section-6.9).

Zero-byte accounting consumes no credit even with a negative window; it does not authorize arbitrary empty frames. The connection/message state machine decides whether an empty terminal DATA frame is allowed. DATA charges its complete payload length including pad-length byte and all padding, while application bytes omit them. WINDOW_UPDATE masks its reserved bit, rejects zero with correct connection/stream scope and emits exact four-byte uint31 increments.

Http2SendCredit.available() is the minimum of connection/stream capacity. spent(length) preflights both and publishes both immutable successors synchronously, without partial debit on refusal. Owner must install both states under its scheduler before any await/output. This value is not an inter-task atomic registry or permission for concurrent writes.

Receiving intentionally has no all-or-nothing pair. A valid connection charge must survive when the independent stream check fails; discarded stream bytes then release connection credit under the owning reader. Rolling back the connection debit on stream error would desynchronize sibling flow accounting. Settings deltas must be processed sequentially for every live stream; a later valid duplicate cannot mask an intermediate overflow.
