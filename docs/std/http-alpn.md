# Negotiated HTTP conversations

HttpClientProtocols(ClientPolicy,TlsClientPolicy) validates enabled H1.1/H2 and advertised ALPN without effects. selected(actualProtocol) obeys exact h2/http/1.1; absent ALPN selects H1 only when enabled. clear() selects ordinary H1 when enabled; H2-only means explicit prior knowledge. Unsupported H1.0/unknown protocol/advertisement disagreement rejects. No protocol is inferred from the advertised list or a failed handshake.

HttpSelectedConnecting(route,tls,policy,clock) opens exactly one checked TCP/TLS conversation. Actual TLS selection happens after URL DNS/IP certificate identity/SNI verification and before application bytes. H2 performs the supervised preface; H1 directly adopts its existing session. HttpConversationAcquisition supplies ExchangeDetails and the restricted HttpConversation capability. Common exchange/adapter helpers are internal transport composition, rather than an alternative user-facing message API.

Public HttpClient supports H1-only, H2-only and mixed H1.1/H2 policies. Default remains H1-only. The H2 and mixed profiles use one shared physical-pool implementation. Each transport owns a native connection permit in its supervised lifetime task. H2 admits independent streams; an actual H1 conversation admits one request/body lease until EOF. Constructor policy and actual response/details versions remain explicit. Existing redirects, cookies and scoped Basic/Bearer compose through Exchanging.

A queued request whose conversation retires before its slot is granted is re-admitted on a fresh conversation. No exchange or write was started: even an unsent POST is safe here. No emitted request is replayed by this mechanism. The per-attempt child group settles old admission, while a full-operation booking group lets client close cancel all queued/pending acquisitions before releasing references. Slot ownership is marked inside the granting action, covering cancellation/completion races. Early H1 body close discards physical conversation; H2 close resets only its stream.

Connection deadlines begin after physical admission. Waiting for the H1 slot is outside header timing; final headers/upload use the existing header deadline. Body-idle timeout stays per explicit read. Idle eviction never selects an active entry. Endpoint policy is rechecked before every shared/reused exchange, including its original absolute URL path. No cross-origin coalescing, idle TTL, automatic failed-request retry or implicit proxy is introduced.

Focused tests cover exact/absent ALPN, unsupported choices, actual DNS/IP TLS selection to H1/H2, no application bytes on certificate/selection rejection, H1 body serialization, H2 multiplexing over TLS, re-admission of a POST with zero bytes on the abandoned connection, and cancellation of queued admission on client close. Final compatibility is recorded after completion; no interpreter/provider change requires a new full gate.
