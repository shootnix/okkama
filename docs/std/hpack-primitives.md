# Internal bounded HPACK primitives

`http/internal/hpack_primitives` defines HpackInteger(value,prefix,pattern), ParsedHpackInteger(bytes,offset,prefix), HpackString(bytes), ParsedHpackString(bytes,offset,decoded_maximum), and HpackHuffman(bytes,decoded_maximum). These are internal collaborators, not stable public HPACK/frame API. Integer values are uint32; prefix widths 1..8; pattern cannot overlap prefix bits. Decode accepts at most five continuation octets and reports the following offset. Truncated/overflowing/excessively extended integers fail with connection COMPRESSION_ERROR (9). This is an explicit implementation bound allowed by [RFC 7541 section 5.1](https://www.rfc-editor.org/rfc/rfc7541.html#section-5.1).

Strings preserve opaque octets, including bytes unsuitable for HTTP fields; HTTP validation belongs above compression. Raw literals are length-prefixed without Huffman encoding. The decoder accepts both representations, consumes only the encoded string, and enforces decoded capacity before extra output. Encoded and decoded strings are capped at 1 MiB; zero decoded capacity permits empty strings. Huffman uses all 257 RFC codes, forbids the EOS symbol and requires final padding to be a prefix of EOS of at most seven bits. Fixed generated trie has 513 nodes. Integer/string policy remains std; only measured expensive Huffman bit processing crosses `runtime/hpack` to `core.hpack`. No external package is used.
