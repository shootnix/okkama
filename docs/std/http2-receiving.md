# Internal HTTP2 aggregate receive flow

`Http2ReceiveFlow(controls,maximum[,window])` implements Http2BodyEvents and tracks one connection receive window with 1..256 active slots. Default wire window is 65535; explicit Http2FlowWindow permits a pre-established remaining context. register(stream) admits strictly increasing odd IDs before requests are emitted. attach(stream,buffer) accepts final response bodies in any arrival order; open(stream,buffer) combines both for already configured fixtures. The registry borrows native body owners; a supervising session/caller must retain them directly. It does not acquire resource lifetime via Atomic storage.

`data(payload)` charges full connection DATA bytes before delivery. Stream-window/length faults return the current frame's connection charge before propagating; failed(fault) then fails the affected body, returns older unread charge and returns whether the connection reader should emit RST_STREAM. The ledger deliberately does not duplicate that protocol reset. An abandoned body queues CANCEL for its stream. Padding/consumed bytes emit connection WINDOW_UPDATE and, while remote-open, stream WINDOW_UPDATE. Connection overspend aborts before delivery. The owner still checks complete message/lifecycle/stream admission rules.

Late known-closed DATA receives minimal connection charge/credit and preserves final buffered payload. Idle/future stream DATA is a connection protocol fault; DATA on a registered request before final fields is a stream fault. Clean application EOF now closes native storage and calls discard(stream,0,false) once, retiring the slot. Repeated EOF remains empty; explicit close/drop does not duplicate release. Capacity therefore bounds current bodies rather than connection history. Highest ID is primitive and prevents reuse.

stop(error) disables admission/obsolete control emission and fails unfinished bodies. Completed wire bodies retain buffered data for application consumption after peer EOF; the caller retains those actual buffer owners. Their later reads restore ledger credit without writing to a closed connection. Session half-close, pending metadata and outgoing request cancellation remain separate collaborators.
