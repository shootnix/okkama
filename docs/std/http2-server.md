# Owned HTTP2 server session

`Http2ServerSession(input,output,owner,handling,details,policy,clock)` adopts one explicitly selected H2 transport. `details.version()` must be H2 and the policy must enable H2. Selection is explicit cleartext prior knowledge or externally negotiated ALPN; this session does not sniff HTTP1, implement h2c Upgrade or perform TLS handshakes. The constructor is lazy. One `serve()` lifetime performs the bounded server preface, runs the sole reader/writer and supervises independent request handlers. `close()` cancels work immediately; `settled()` waits for task cleanup and physical transport disposal.

The server advertises 100 concurrent streams and a 65535-byte initial per-stream receive window. The active and retired registries are bounded by this admission cap, output is bounded to 256 tickets / 1MiB, and HPACK/message/body budgets use the explicit policy. No push capability is provided. Each request body buffer is created in its owning stream task; the reader waits for acquisition before delivering following DATA, then continues independently of handler work. Incoming pseudo-fields, Content-Length and trailers are checked before/as they arrive. Decoded HPACK context survives stream semantic errors. Rejected streams retain only the increasing ID boundary; late DATA still charges and returns connection credit.

Handlers receive `Request` with H2 version and an absolute URL reconstructed from checked pseudo-fields, plus `HttpRequestContext` with supplied transport observations and restricted cancellation. RST_STREAM and transport EOF cancel pending handler work, execute defers and preserve sibling streams when the fault is stream-scoped. Handler timeout produces minimal503; request body read timeout produces one CANCEL reset. Uncaught handler failures and invalid response metadata become minimal500 before response output; failures after output reset the stream. Final ordinary responses must be >=200; successful CONNECT and WebSocket results require a separate negotiated tunnel profile and are rejected. HEAD/204/304 do not inspect or open suppressed bodies. Streaming body lengths are checked; response trailers use final HEADERS END_STREAM. No implicit Date/Server fields are added.

`stop_accepting()` queues GOAWAY with the observed request boundary and refuses later streams. `drained()` waits for active responses and actual GOAWAY output, then closes/settles the session. An external drain deadline may cancel this wait and must close/settle the session. This session's own drain has no implicit deadline. A later EOF can terminate a drain; transport closure is still joined.

[Example](../../examples/std-v4/http2-server.ok) announces an ephemeral loopback port, accepts one prior-knowledge connection, responds `hello` to independent H2 requests and settles on EOF. Evidence records focused tests and a peer that independently writes client magic, SETTINGS and HPACK and checks exact response frames.

The [HttpServer listener](http-server.md) now composes explicit H2-only prior knowledge and ServerDrain; its focused gate is separate from the session gate.

The header budget now covers preface and the whole incoming HEADERS/CONTINUATION section across physical reads using one monotonic deadline. A reader boundary hook resets it only after complete dispatch. Physical DATA payload reads use the separate body-idle budget; zero disables that budget independently. A stalled partial DATA frame cannot be resynchronized, so physical read timeout closes the connection; a pending application body read timeout remains stream-local CANCEL. An independent idle monitor closes only when no handler is active and no section is partially read; it starts even when the reader was already waiting before the last handler completed. Activity replaces the notification Event before waking observers.

Connection protocol/HPACK faults attempt GOAWAY with their actual error code and no debug payload, allowing at most one second to flush the control before deterministic close/settlement. This failure-cleanup bound is separate from zero-disabled normal deadlines. Unexpected writer/reader termination or a programming failure in a stream wakes supervision and disposes the peer; the original failure is observed rather than hanging with all timeouts disabled. Ordinary handler Error still produces500. Programming panic is not converted to500.

Final policy evidence: 11 files /47 checks PASS. Expect100 willingness is now a memoized informational HEADERS write triggered by application body consumption. Unsupported/duplicate expectations yield417 before handler effects; a complete body can skip100. Continue gate: 3 files /8 checks PASS.

Remaining server work: TLS key/identity transport, mixed-protocol selection and negotiated RFC8441. Do not infer full HTTP completion from this profile.
