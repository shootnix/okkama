# Internal HTTP2 field blocks and typed metadata

`http/internal/http2_headers::Http2HeaderBlockReading(first,AsyncReading,decoder,budget[,receive_maximum]).result()` consumes exactly one HEADERS/CONTINUATION block. First frame must be HEADERS; padding and deprecated priority fields are removed from HPACK input. Following frames must be CONTINUATION on the same stream without any interleaved control/other-stream frame. END_STREAM belongs only to the initial HEADERS; END_HEADERS terminates the field block. Result retains fields, successor compression context, stream and end_stream. The next frame stays unread. The operation is lazy/memoized and borrows physical transport; cancellation drains pending reads. Owner closes transport after connection fault/cancellation. Encoded block bytes are bounded and no more than 1024 frames are consumed, even for zero-byte fragments.

An interleaved malformed PRIORITY normally has a stream-level FRAME_SIZE_ERROR in isolation. Inside a continuation sequence it cannot downgrade the sequencing failure: the header reader promotes that stream-scoped failure to connection PROTOCOL_ERROR. Actual HTTP field validity remains stream-scoped after complete HPACK state is retained. Sequence rules follow [RFC 9113 section 6.10](https://www.rfc-editor.org/rfc/rfc9113.html#section-6.10).

Http2HeaderBlockWriting(output,stream,fields,budget,fragment_size,end_stream).result() preflights the complete bounded encoded block before any output. Conservative stateless HPACK explicitly selects zero dynamic capacity at every block start; this satisfies any peer table reduction. It splits at chosen positive fragment size, emits HEADERS then CONTINUATION, sets END_STREAM only on first frame and END_HEADERS only on last. No more than 1024 output frames; caller chooses a fragment size within the peer's actual receive maximum. Per-write cleanup drains cancellation. Caller must serialize the whole block with other connection output: per-frame AsyncWriting FIFO alone cannot prevent concurrent blocks interleaving. This helper is not the connection scheduler.

`http/internal/http2_fields` maps typed metadata without any body observations. Http2RequestFields(Request,stream[,route_url]) emits method/scheme/authority/path before lowercased ordinary fields; absolute URL derives coordinates, origin/star needs explicit route URL, classic CONNECT emits only method/authority. Host must be single and agree after canonical host/default-port normalization. Http2ResponseFields(Response,stream) emits status then ordinary fields; 101 is rejected. These pure mappings do not perform ALPN negotiation or select a connection.

ParsedHttp2Response(fields,stream,end_stream) and ParsedHttp2Request(fields,stream) validate pseudo-field context/order/uniqueness, required control data, lowercase ordinary names, generic octet grammar/edge whitespace and connection-specific/TE prohibitions. Errors are stream PROTOCOL_ERROR. Informational responses cannot end the stream, 101 is HTTP1-only, and status needs three valid digits/range. Incoming ordinary HTTP(S) requests reconstruct an AbsoluteTarget from authority/scheme/origin path, preserving query presence; OPTIONS star and CONNECT keep their special forms. Missing authority may use exactly one Host; neither absent routing authority nor non-HTTP gateway schemes are supported by this profile. CONNECT requires explicit authority port and forbids scheme/path; extended CONNECT is not supported. Host/:authority agreement applies on input and output. body supplied to request()/response() is retained without length/replayability/read/close calls. Pseudo-fields never become ordinary Headers.

The owning connection must install block.context() before validating HTTP fields: a malformed message can reset one stream while HPACK state stays synchronized for siblings. Content-Length versus DATA bytes, trailers, stream state, flow control, ALPN, physical ownership and public client integration remain separate work. The implementation does not advertise a complete HTTP2 engine.
