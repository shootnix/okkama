# Точная арифметика BigInt

Первый срез [плана завершения](stdlib-completion-todo-v4.md):
CONTRACT → тесты → реализация → проверка. Модуль `numbers/bigint`.

Шаги: (1) BigSum/BigProduct; (2) BigQuotient/BigRemainder;
(3) BigPower/BigGcd/BigLcm; (4) примеры, документация и общая регрессия.

Объекты выражений сохраняют неизменяемые операнды и вычисляют точный BigInt через
`#projected value()`. Повторный запрос не меняет аргументы. Результаты не сужаются
до builtin int/float. Для двухоперандных выражений используйте именованные
аргументы `left` и `right`, как у существующего BigDifference.

- BigSum — сумма; BigDifference — разность; BigProduct — произведение.
- BigQuotient — частное с усечением к нулю, независимо от знаков.
- BigRemainder — остаток: a = q*b+r; |r| < |b|; ненулевой r имеет знак a.
  Нулевой делитель допускается как операнд выражения, но `value()` бросает
  BigDivisionByZero. Ни NaN, ни Infinity, ни host exception не являются результатом.
- BigGcd — неотрицательный НОД; gcd(0,0)=0.
- BigLcm — неотрицательный НОК; если один операнд ноль, результат ноль.
- BigPower(base is BigInt, exponent is int) — степень, включая 0^0=1.
  Отрицательный показатель отвергается в конструкторе через InvalidBigExponent;
  `exponent()` ошибки сохраняет неверный показатель.

## Бюджет степени

BigPower по умолчанию ограничивает результат **1048576 битами**. Конструктор
`BigPower(base, exponent, maximum_bits)` позволяет явно выбрать положительный
бюджет. Неположительный бюджет отвергается в конструкторе через InvalidBigPowerLimit.
Запрос результата сверх бюджета бросает BigPowerLimitExceeded. Обе ошибки
предоставляют `maximum_bits()` и диагностический `text()`.

Ноль имеет размер 0 бит, ±1 — 1 бит. Эти случаи и степень 0 вычисляются без
построения огромных промежуточных чисел. Для |base| ≥ 2 нижняя граница
`(bits(base)-1)*exponent+1` вычисляется точно до возведения в степень. Если она
превышает бюджет, тяжёлое вычисление не начинается. Иначе промежуточный результат
содержит не более удвоенного бюджета бит; после вычисления проверяется точный
размер. Верхнюю оценку нельзя использовать для преждевременного отказа: 3^2
должно помещаться в 4 бита.

Это ограничение результата и его основного промежуточного целого, не обещание
фиксированного RSS или времени: стоимость backend, десятичной строки и уже
созданных входных BigInt сюда не входит. Увеличенный бюджет — явный выбор caller.

## Граница backend и тесты

Нативные операции принимают/возвращают canonical decimal strings. Signed division
не должна наследовать округление host: делятся положительные модули, затем
восстанавливаются знаки. Native zero division и power budget errors тоже имеют
коды существующего закрытого ABI: `invalid_input` для неверных операндов,
`resource_exhausted` для превышения бюджета. Public std предоставляет
конкретные ошибки, описанные выше; набор NativeFailure-кодов не расширяется.

Проверки: таблицы всех сочетаний знаков с независимой машинной арифметикой для
маленьких чисел; перенос на 100 цифрах; произведение (10^40-1)*(10^40+1);
частное и остаток для 10^80+1; тождества, нули, ±1, повторные вызовы и сохранение
операндов. Степень: точный 2^100, нечётные/чётные знаки, границы бюджета,
огромный показатель при маленьком бюджете, ошибочные аргументы. НОД/НОК: нули,
симметрия и большие общие множители. Fixtures не используют Math::BigInt как oracle.

## Пример и команды проверки

[Исполняемый пример](../../examples/std-v4/bigint.ok) делит большое число,
восстанавливает его из частного и остатка и вычисляет 2^100.

Из `okkama-pl/`, используя Perl 5.42:

```sh
prove -l t/interpreter/251-std-v4-bigint-arithmetic.t t/interpreter/250-std-v4-examples.t
OKKAMA_STDLIB_DIR=../std perl bin/okkama ../examples/std-v4/bigint.ok
perl ../docs/audits/evidence/stdlib-v4/check.pl full
```

Конфигурационные параметры степени доступны как primitive values и проверяются
в конструкторе без вычисления зависимости. Делитель — BigInt-операнд выражения; его
арифметическая проверка выполняется только при запросе value().
