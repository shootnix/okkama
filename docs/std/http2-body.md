# Internal HTTP2 incoming body buffer

`Http2BodyBuffer(stream,initial_window,body_limit,events,expected_lengths,empty)` owns native byte storage and one stream's BodyReading lifetime. initial_window is 0..1 MiB, total body_limit 0..9007199254740991 bytes, expected_lengths empty or one nonnegative BigInt. Normal declared lengths exceeding body policy are rejected before storage. empty describes HEAD/body-forbidden responses whose representation Content-Length does not require wire payload.

`data(Http2DataPayload)` validates stream/end state, stream flow, total byte policy and Content-Length before storing app bytes. Padding consumes full flow credit and is released immediately; app bytes are released when bytes(limit) consumes them. Http2BodyEvents.credit(stream,amount,stream_update) asks the owner to release connection credit and, while remote-open, stream credit. The owner must charge connection flow before delivery and return the whole current frame's charge after a pre-storage stream fault; this buffer does not account aggregate connection windows.

`ending(trailers)` validates exact length and remote end. Buffered final payload remains readable after END_STREAM; trailers() becomes available only after clean empty application EOF. Pending reads suspend on a generation event without blocking the sole wire reader. One read may be pending; overlaps are rejected. Cancelled reads or close discard unread bytes once and request stream cancellation when remote end has not arrived. fail(error) preserves failure and discards without requesting a second reset. Callbacks must remain safe after connection closing and suppress obsolete wire updates. Dropping the buffer closes storage/consumption lifetime.

Http2IncomingBody(buffer,known_lengths) is a one-shot non-replayable BodyOpening with explicit UnknownBodyLength. Dropping an unopened body closes its buffer. Http2BodyLength(headers,stream).known() validates decimal/comma lists, at most 1024 digits per lexeme, and equal repeated lexemes; errors carry the actual stream ID. Http2Trailers(fields,stream) rejects pseudo/connection fields and shares conservative forbidden-field/Connection-nomination policy with HTTP1 via internal HttpTrailerRules.

Existing runtime/buffer provider; no new provider/VM code. 494 eleven cases PASS; shared trailer refactor 422/484/494 76 assertions PASS with the original eight body cases. Incoming aggregate flow, header promise/message order, actual response leases and physical session follow. Internal helpers do not advertise a complete H2 client.

Receive integration now releases native storage/slot at clean EOF via one discard(stream,0,false); repeated EOF stays empty. Close/drop does not duplicate release. [Aggregate ledger](http2-receiving.md), 494/495/496 22 PASS, owns connection accounting while actual buffer owners remain in supervising caller/session.

Owned session can create storage before response metadata: require_fields() rejects premature DATA and configure(lengths,empty) publishes final semantics once before any bytes. Cumulative policy supports HttpLimits exact integer ceiling; receive storage still follows the bounded window. Native storage already released at EOF is not reclosed by scope destruction. [Session](http2-session.md) retains ready/unclaimed owners explicitly.
